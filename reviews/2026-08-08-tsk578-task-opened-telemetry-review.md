## Проверка по 12 измерениям

1. **Соответствие целям.** Все три пункта декомпозиции tsk-578 покрыты: кто/куда
   пишет событие (решено и задокументировано), обработка повторного открытия и
   ухода без ответа (решено), перевод признаков на реальное время с
   миграционным путём (реализовано). DRIFT не обнаружен.
2. **Корректность.** LATERAL-join берёт `LIMIT 1 ORDER BY created_at DESC` —
   ровно одно ближайшее ПЕРЕД сдачей событие на строку `real_subs`, двойного
   счёта нет (подтверждено тестом `test_real_pace_used_and_picks_nearest_opening_before_submission`,
   явно проверяющим, что берётся близкое, а не далёкое открытие). Повторный
   submit внутри одной попытки без нового открытия сознательно переиспользует
   тот же opened-якорь для разных сдач — задокументировано как ожидаемое
   поведение, а не дефект (тот же якорь = то же «начало отсчёта» для каждой
   попытки ответить).
3. **Безопасность данных и миграций.** Миграция — только индекс, `upgrade`/
   `downgrade` симметричны, откат не теряет данные. Применена на dev,
   `alembic upgrade head` прошла чисто.
4. **Безопасность и секреты.** Новых эндпоинтов нет — запись события целиком
   внутри уже защищённого `start-or-get-attempt` (существующий ACL:
   `current_user.id == student_id` или сервисный ключ). IDOR-периметр не
   расширен, `test_idor_sweep.py` зелёный без изменений.
5. **Покрытие тестами.** 5 новых тестов: запись при новой/переиспользуемой
   попытке (HTTP-уровень), форма payload (сервис-уровень), реальный источник +
   выбор ближайшего открытия, фолбэк на прокси при малой выборке, `pace_source`
   в разборе темы. Полный `pytest`: **1967 passed, 11 skipped, 0 failed**.
   Регрессионный набор (`test_tsk577_topic_mastery.py`,
   `test_hint_events_stage36.py`, `test_attempt_meta_task_ids.py`,
   `test_idor_sweep.py`, `test_learning_api_routes.py`) — зелёный отдельно.
6. **Docs/Config/Runtime Drift.** Docstring модуля `topic_mastery_service.py`
   обновлён под новую реальность (реальный источник + фолбэк). План описывает
   архитектурное решение полностью.
7. **Phase Integrity.** Staged-набор соответствует объёму плана, посторонних
   файлов/фаз не подмешано. TODO/заглушек нет.
8. **Goal-Level Data Completeness.** На момент деплоя реальных данных 0 у всех
   тем — это ожидаемо и обработано явным фолбэком, не заглушкой.
9. **Domain Model Completeness.** Новый `event_type='task_opened'` укладывается
   в существующую доменную модель `learning_events` без новых классификаторов.
10. **Date/Time Critical.** Все временные операции — на стороне PostgreSQL
    (`now()`, `EXTRACT(EPOCH FROM ...)`, `created_at <= received_at`), без
    сравнения `str`/`datetime` на стороне Python — класс ошибок из
    `docs/ai/ERRORS.md` (2026-03-03) не воспроизводится.
11. **Cross-project memory sync.** Изменение **не расширяет** контракт, который
    читают SPW/TG_LMS: HTTP-ответ `start-or-get-attempt` не меняется (событие —
