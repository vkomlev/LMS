## Контекст

Судья по критериям построен в tsk-658 и работал только для `TA`. У 244 заданий
`SA`/`SA_COM` критерии подтверждены методистом (`grading_criteria.status=approved`),
из них **179 без эталона и без обязательного файла** — те, которым судья нужен.
Три причины, по которым он до них не доходил (найдены чтением кода 15.09), закрыты
этой задачей. Ничего нового не строилось: тот же сервис, та же очередь, тот же
LLM-клиент.

## Границы (соблюдены)

- `is_correct`/`score` работы разбор не трогает — проверено тестом тика (`is_correct` остаётся `NULL`).
- Ученику разбор не показывается: `code_review` не входит в ответ на сдачу (проверено в тесте пометки), схемы ученических ответов не менялись.
- Детектор авторства для `SA_COM` не включён: ветка `criteria` его не зовёт (тест с `AssertionError` на вызов), у кодовой ветки — прежний детектор кода, как и до задачи.
- Бэкфилла по старым сдачам нет: пометка идёт только через приём ответа.
- Боевая БД — только чтение (калибровочный скрипт, SELECT через DSN из `.mcp.json`).
- Коммит выключенным: рубильник `criteria_review_enabled=false` по умолчанию, включение — правка настройки в кабинете, без выката.
