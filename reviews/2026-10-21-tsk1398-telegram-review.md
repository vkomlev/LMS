# Ревью: tsk-1398 — Telegram как канал уведомлений и ответов

**Решение: ПРИНЯТО.**

- LMS: ключ ученического бота `STUDENT_BOT_TOKEN` (копия из `/opt/tg_lms/.env`, проверен `getMe` → `cyberguru_p_bot`). Отписка — строка `messenger_link(tg, disabled_at)`: «стоп» в боте, 403 при отправке (бот остановлен), кнопка в кабинете; новая привязка по ссылке снимает её (`tg_deep_link_service.link_from_bot`). Отписанному не уходят ни уведомления, ни опрос, ни срочное.
- `POST /integrations/student-bot/inbound` — только сервисный ключ (тест 401/403). Ученик ищется по `users.tg_id` (активный, не слитый). Неизвестный tg_id — тишина.
- Маршрут вынесен в свой роутер: `bot_router` этапа А уже подключён в `main` раньше, добавленный позже маршрут FastAPI не скопировал бы.
- TG_LMS: `early_router` до диалогов — только кнопки опроса, стоп-слова и ответ свайпом на сообщение бота (ввод в меню не трогает); `late_router` после всех диалогов — прочий текст. Подписи кнопок сверяются с LMS тестом. Ограничение: свободный текст при открытом диалоге (не свайп-ответ) забирает диалог.
- SPW: `tg` в списке каналов — только «Отключить» для подключённого; отписавшемуся снова показывается «Подключить Telegram».
- Тесты: LMS 189 соседних прошли (3 новых Telegram); TG_LMS 552/552 (5 новых); SPW — см. прогон; tsc/eslint чисто.
- ERRORS.md: не требуется.
