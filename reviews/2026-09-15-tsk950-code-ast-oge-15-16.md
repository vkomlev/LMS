## 1. Итог одной строкой

`code_ast` в нынешнем виде засчитывает **18 %** верных решений ОГЭ-16 (11 из 61),
поэтому эталоны в `accepted_answers` **не записаны** — по решению оператора
путь для Python-заданий — прогон программы на тестах ([[tsk-953]]), а для
КуМир — ручная проверка с опорой на критерии. Для всех 55 заданий записаны
**черновики критериев** (`grading_criteria`, `status=draft`) с проверенным
эталоном/ориентиром и тестами; поведение для ученика не изменилось.

## 3. Эталоны для 30 заданий Python

Все 30 условий разобраны и разложены на четыре семейства (`scripts/tsk950_oge16_specs.py`):

- **A** (22 задания): читать N, затем N чисел; отобрать по «кратно k» / «оканчивается
  на d»; max / min / сумма / количество;
- **B** (6): ввод до 0; сумма чисел, кратных 6 и оканчивающихся на d;
- **C** (7242): сумма двух наибольших и двух наименьших, ввод до 0;
- **D** (7243–7245): камера — max / min / средняя скорость + YES/NO.

Эталоны собраны шаблонами: по 4 на семейство A (счётчик в `for`, `max()/min()`
в цикле, список + генератор, `while`), по 3 на B/C/D. Итого **106 программ**,
каждая исполнена на примере из условия, на дополнительных тестах из условия
(7244) и на 6 случайных тестах против образцовой функции — **106/106 верны**
(`scripts/tsk950_codeast_measure.py`, результат `reviews/tsk950/measure_result.json`).

## 4. Замер code_ast — честная цифра

Мерил функцией движка `CheckingService._canon_code` (то, что стоит на проде), а
не своей копией. Набор: 61 разное верное решение «как пишут девятиклассники»
для 5 заданий (`scripts/tsk950_oge16_variants.py`; каждое тоже прогнано на
примере и случайных тестах — неверных 0).

| Задание | Решений | code_ast (прод) | + обезличивание имён переменных |
|---|---|---|---|
| 7226 max, кратное 5 | 13 | 4 (31 %) | 7 (54 %) |
| 7228 count, кратное 4 | 12 | 1 (8 %) | 6 (50 %) |
| 7233 sum, оканч. на 4 | 12 | 1 (8 %) | 6 (50 %) |
| 7241 ввод до 0, два условия | 12 | 2 (17 %) | 3 (25 %) |
| 7244 камера min + YES/NO | 12 | 3 (25 %) | 3 (25 %) |
| **Итого** | **61** | **11 (18 %)** | **25 (41 %)** |

Порог задачи — «меньше половины ⇒ одного code_ast мало» — пройден с запасом,
причём даже с доработкой движка (не различать имена переменных). Причина
системная: `ast.unparse` — точное совпадение структуры, а верных структур у
задачи «прочитай N чисел и посчитай» десятки (`for`/`while`, `+=`/`= m + x`,
`if a and b`/вложенный `if`, `str(x)[-1]`/`% 10`, список/накопление).

## 5. Что ещё поменяла бы запись эталона (найдено до записи)

1. **Движок сверяет только `response.value`**; `response.comment` в оценке не
   участвует (`checking_service.py:643`). Форма SPW `TaskFormSA_COM` у заданий
   без эталона прячет поле «Ответ» и показывает редактор кода как «Ваш ответ» —
   текст уходит в **comment**. Появись эталон — форма покажет поле «Ответ» и
   редактор станет «Комментарием»: программа ученика уедет мимо сверки.
2. **Оптимистичный зачёт SA_COM** (`attempts.py`, `optimistic_manual`) работает
   только при отсутствии эталона: с эталоном ученик получал бы «0 баллов, на
   проверке» до прихода преподавателя.
3. Гибридный режим `partial_auto_check` не спасает: при несовпадении он выносит
   `is_correct=False` и не отправляет работу преподавателю — при 18 % это
   ложный незачёт для четырёх из пяти верных решений.

Отсюда рекомендация «эталоны в черновик, проверять исполнением», принятая
оператором.

## 7. Критерии для 25 заданий КуМир — как проверялись ориентиры

Чтобы ориентир в `notes` не был «по памяти», написан мини-симулятор Робота
(`scripts/tsk950_robot_sim.py`: подмножество КуМир — команды, проверки
«… свободно» со связками, `нц пока`, `если … то … иначе … все`; поле с
рёбрами-стенами). Семь семейств полей генерируются случайно (длины стен, место и
ширина проходов, положение Робота), родственные задания получаются симметриями
(отражения, транспонирование) канонического поля и алгоритма. Геометрия
лестницы 7217 снята с SVG условия на проде. **25/25 алгоритмов — 200 случайных
полей каждый, 5000 прогонов, ошибок 0.** Два первых черновика алгоритмов
симулятор забраковал (7208: подъём упирался в горизонтальную стену; 7225:
ошибка в цепочке симметрий) — то есть проверка была не формальной.

## 8. Как записывалось и сверка

Через боевой API под сервисным ключом, на сервере под `app`
(`scripts/tsk950_apply_criteria.py`, ключ читается из `/opt/lms/.env` внутри
скрипта): `GET /tasks/{id}` → пропуск, если критерии или эталон уже есть →
`PATCH /tasks/{id}` с полным `solution_rules` + блок `grading_criteria`.
Сначала режим плана (55 строк, `mrr=True auto=False`), затем запись: 55 OK,
0 пропусков, 0 ошибок. Записанный `criteria.json` побайтно совпадает с
пересобранным из репозитория.

SQL-сверка после (read-only MCP): у обоих курсов `gc_draft = n`,
`gc_manual = n`, `gc_reviewed = 0`; **не изменились** `manual_review_required`
(55 true), `auto_check` (0 true), `partial_auto_check` (0), `short_answer` (0
заданных), `max_score` (по 1), `is_active` (55). `content_provenance` теперь
`manual_web` у всех 55 — так устроен обработчик PATCH (tsk-433), и это
ожидаемо: правило выведено из-под переиздания источником.

## 9. Генераторы заданий (п. 6 декомпозиции)

- Импорт из Google Sheets (tsk-267): шаг `code_ast` ставится по колонке
  `normalization` (`code` → `[trim, strip_punctuation, collapse_spaces, code_ast]`),
  пустая колонка — `[trim, lower]`. Автоматически для 15/16 не выводится.
- Импортёр внешних заданий ContentBackbone (`external_tasks/adapter/builder.py`):
  флаг `answer_is_code` ставит методист явно; парсер sdamgia для ОГЭ-15/16 даёт
  `manual_review_required=true` без эталона — ровно то, что стояло у 55 заданий.
- `/methodist` (`references/assignment-rules.md` § 4b, `lms-wp-export.md`):
  правило «ответ-код Python ⇒ `code_ast` без `lower`» записано.

**Вывод после замера:** принуждать генераторы ставить `code_ast` для ОГЭ-16 не
нужно и вредно (18 % + побочные эффекты формы). Правильный контракт для
заданий «напишите программу» до появления прогона тестами: `accepted_answers`
пусто, `manual_review_required=true`, критерии — черновиком. После tsk-953 —
блок тестов ввода/вывода. Правило `code_ast` остаётся для заданий «допиши
строку / выражение», где ответ короткий и вариантов мало.
Попутно: авторское задание 6945 того же курса хранит фрагмент кода
`if a % 3 == 0: cnt += 1` с `lower` в нормализации — класс из памяти проекта
«генератор забыл флаг», здесь без последствий (фрагмент в нижнем регистре).

## 11. Вердикт `/review-gate`: ПРИНЯТО (данные, кода LMS нет)

Кода сервиса в этом заходе нет — только запись данных через существующий API и
вспомогательные скрипты вне рантайма. Проверено: чтение до записи и режим
плана; запись 55/55 без ошибок; SQL-сверка после — критерии `draft/manual`,
остальное правило не изменилось; черновик машинному судье не отдаётся;
ученику ничего не видно (форма и оптимистичный зачёт без эталона — как были).
Скрипты: `PYTHONIOENCODING`/UTF-8, секрет в argv не выносится, временные копии
с сервера удалены.

Спорное, названо честно: критерии 55 заданий записаны без построчной вычитки
оператором — потому и `draft`; подтверждение — в кабинете методиста или
следующим заходом (образец tsk-590: `reviewed_by=2` только после чата).
Ориентиры КуМир проверены симулятором на модели поля по тексту условия (и SVG
для 7217); точная форма поля остальных 24 картинок не сверялась — если рисунок
расходится с текстом (проход у самого угла и т.п.), ориентир может не подойти,
это пометка преподавателю, не автопроверка.
