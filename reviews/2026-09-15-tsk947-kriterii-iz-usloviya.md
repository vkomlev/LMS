## 5. Почему WP публиковали с сервера, а не с этой машины

Python (3.14, OpenSSL 3.0.18) с этой машины **не завершает TLS-рукопожатие** с `victor-komlev.ru`
(92.53.96.101): `connect` мгновенный, `do_handshake` висит до таймаута при любом контексте
(TLS 1.2/1.3, без проверки сертификата, другой набор шифров, без тикетов, с ALPN). `curl`
(Schannel) и `openssl s_client` с той же машины — 0,8–1,5 с. К `api.learn.victor-komlev.ru` тот же
Python ходит нормально. На машине работает FlClash в TUN-режиме (`198.18.0.1` — источник даже
у ssh) — вероятно, трафик `python.exe` к этому хосту уходит в туннель, где рукопожатие теряется.
Настройки VPN оператора не трогал.

С сервера LMS Python проходит, но `create_connection` висит ровно таймаут: у хоста есть
AAAA-запись, IPv6-маршрут с сервера — чёрная дыра, потом падает на IPv4 (память проекта «сайт не
отвечает — это IPv6»). Решение: копия CB на HEAD (`git archive`, без правок соседа) в
`/tmp/cb947` под `app`, зависимости `--target` мимо venv LMS, `sitecustomize.py` оставляет только
`AF_INET`, минимальный env из трёх переменных (передан через stdin ssh), запускатель
`wp_publish_runner.py` зовёт штатный `_cmd_wp_publish`, минуя `monolith.cli.__init__` (тот тянет
docx/telethon/playwright). 8 с на урок. После работы `/tmp/cb947` удалён.
