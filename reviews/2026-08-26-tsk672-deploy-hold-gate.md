# tsk-672 — выкат больше не увозит работу, которая ждёт решения оператора

**Дата:** 2026-08-26
**Проекты:** LMS (`main`), SPW (`master`)
**Скиллы:** `/executor-pro` (правка выкатных скриптов), `/claude-booster` (правило в глобальном контексте), `/review-gate` (это решение)
**Захваты:** `clm-337` — `C:\Users\user\.claude\CLAUDE.md`

## Что случилось и почему дисциплина не помогает

`deploy.sh` в LMS и SPW делает `git fetch` + `reset --hard origin/<ветка>`. На прод
уезжает **вся ветка**, а не работа выкатывающего. Чипы пишут в одну ветку, поэтому
«я свою правку не выкатывал» не значит «её нет на проде».

25.08 чип tsk-658 сознательно придержал разбор развёрнутого ответа по критериям
(включение = постоянный расход на модель, решение оператора) и вынес развилку.
Через час чип tsk-665 выкатил своё — и разбор уехал прицепом. Ущерба не было,
оператор решил оставить, но решение принял постфактум.

Просить выкатывающего «посмотреть, что рядом в ветке» бесполезно: у него нет этого
знания и нет повода его искать. Ровно так же не сработало предупреждение хука
openapi (tsk-495 → рецидив tsk-669) — правило держалось на внимании человека.

## Что выбрано из трёх кандидатов

| Кандидат | Решение | Почему |
|---|---|---|
| Рубильник, выключенный по умолчанию | **Взят как первое средство, но правилом, а не кодом** | Рубильник уже есть у части работ (`AI_TUTOR_ENABLED`, `code_review_cron_enabled`). Не хватало не средства, а правила «когда его заводить». Закрывает главный класс — «оператор решает, включать ли»: выкат становится безопасным по построению, включение идёт правкой `.env` без выката. Но рубильником не закрыть схему API, миграцию и поведение экрана. |
| Отдельная ветка | **Отклонён** | Дороже всего при сегодняшнем темпе: ночью в одном дереве работали до пяти чипов, ветка добавляет мержи, конфликты и память о ней каждому. Общее дерево уже дало инцидент ADR-0008 — вторая ось параллелизма только усложнит. |
| Предупреждение на выкате | **Взят как вторая сетка, в виде отказа, а не вопроса** | Дёшево: точка `.last-deploy-sha`/HEAD уже есть, диапазон считается одним `git rev-list`. Обычный выкат не получает ни одного лишнего шага — только печать списка. Останавливается только тот выкат, где реально есть помеченная работа. |

Вопрос-подтверждение вместо отказа отвергнут: деплой запускают и через `ssh -tt`,
и из фонового чипа без tty. Вопрос там либо повиснет, либо проскочит. Отказ до
`reset` безопасен — прод не тронут, откатывать нечего.

## Что теперь мешает неодобренному уехать

1. **Пометка ставит тот, кто придерживает работу.** Строка в теле своего коммита:
   `Hold-For-Operator: <что должен решить оператор>`. Внимание требуется от того, у
   кого знание есть, а не от соседа — в этом отличие от правила, которое не сработало.
2. **Гейт в `deploy.sh`** (между `fetch` и `reset`, оба проекта): печатает список
   коммитов, которые уедут сверх текущей версии; если среди них есть помеченный —
   выводит его и причину, выходит с кодом 2 и **ничего не трогает**.
3. **Осознанный обход остался:** `DEPLOY_HOLD_OK=1` (по образцу `DBCHECK_OK=1`,
   `CHIP_SOLO=1`), с машины оператора — `deploy-lms.ps1 -HoldOk` / `deploy-spw.ps1 -HoldOk`.
   Обход не молчит: печатает, какие именно пометки проигнорированы.
4. **Сверка по факту, а не по намерению** (урок tsk-676): после `reset` скрипт
   печатает, что реально приехало (`.last-deploy-sha..HEAD`), а не то, что
   выкатывающий собирался выкатить.

## Цена обряда

- Обычный выкат (пометок нет): **ноль лишних действий**, +2 строки заголовка и список
  едущих коммитов. Ничего не спрашивается, ничего не ждёт ввода.
- Выкат при наличии пометки: остановка, чтение причины, одно решение — ждать или
  повторить с `DEPLOY_HOLD_OK=1`.
- Постановка пометки: одна строка в сообщении коммита, только у того, кто и так
  сознательно придерживает работу.

Это осознанно **не** ещё один шумящий гейт, который начнут обходить не глядя, как
`ROOT_ALLOW_MULTI_TASK_COMMIT=1`: он молчит на всех выкатах, кроме тех, где есть
ровно та ситуация, ради которой заведён.

## Валидация

Тест вырезает блок гейта **из боевого `deploy.sh`** (а не копирует его) и прогоняет
по паре временных репозиториев — «сервер» и origin. Сервер для этого не нужен.

```
$ bash deploy/vps/test-hold-gate.sh          # LMS, ветка main
=== 1. Выкатывать нечего — гейт пропускает ===            OK (код 0)
=== 2. Обычные коммиты без пометок ===                    OK (код 0) + список напечатан
=== 3. В ветке есть помеченный коммит ===                 OK (код 2) + причина показана
=== 4. Осознанный обход DEPLOY_HOLD_OK=1 ===              OK (код 0)
=== 5. Помеченное уже на проде — гейт молчит ===          OK (код 0)
ИТОГ: успешно 8, провалов 0

$ bash deploy/vps/test-hold-gate.sh          # SPW, ветка master
ИТОГ: успешно 8, провалов 0
```

Дополнительно:
- `bash -n` на обоих `deploy.sh` — синтаксис чистый.
- Разбор обоих `.ps1` парсером PowerShell — ошибок нет; `param()` стоит первой
  инструкцией (иначе PowerShell не принял бы файл), BOM у обоих на месте (`ef bb bf`).
- Прогон `.ps1` с заглушкой вместо `ssh`: без флага собирается
  `sudo -u app bash …/deploy.sh`, с `-HoldOk` — `sudo -u app env DEPLOY_HOLD_OK=1 bash …/deploy.sh`,
  код 2 попадает в свою ветку вывода («прод не тронут»).

## Ограничения — что НЕ закрыто

- **Гейт начнёт действовать со следующего выката.** Сейчас на сервере лежит старая
  версия скрипта; она приедет вместе с ближайшим деплоем — и только выкат после него
  будет проверять пометки. Специально деплоить ради этого не стал: в ветках сейчас
  чужая незавершённая работа (tsk-679, tsk-655, tsk-661), и мой выкат увёз бы её —
  то есть ровно то, против чего заведена задача.
- **Полигонные скрипты** (`deploy/poligon/deploy-*-poligon.sh`) и деплой TG_LMS не
  тронуты: полигон — тестовый стенд, неодобренная работа там не стоит обряда; TG_LMS
  вне границ задачи.
- **Ключ ищется по всему сообщению коммита.** Коммит, который просто упоминает
  `Hold-For-Operator` (например, отменяющий пометку), остановит выкат. Оговорено в
  README обоих проектов; лечится обходом или переформулировкой сообщения.
- **Пометка не мешает мержу и не мешает коммиту** — только выкату. Это осознанно:
  коммитить и пушить работа должна, иначе она живёт в дереве и мешает соседям.

## Как откатить

Изменение — только в выкатных скриптах и документации, состояния нигде не завёл.

```bash
# LMS
git revert <sha коммита tsk-672>          # или точечно:
git checkout <sha до правки> -- deploy/vps/deploy.sh deploy/local/deploy-lms.ps1 deploy/local/deploy-lms.cmd
# SPW — то же самое своими путями
```

На сервере откат приедет обычным деплоем. Разовый обход, когда откатывать незачем, —
`DEPLOY_HOLD_OK=1`. Правило в `~/.claude/CLAUDE.md` — резервная копия
`~/.claude/skills/claude-booster/references/backups/CLAUDE.md-2026-08-26.md`.

## Решение review-gate

**ПРИНЯТО.**

Проверено по измерениям:
- **1. Соответствие целям** — все четыре обязательных пункта постановки закрыты:
  цена обряда оценена и сведена к нулю на обычном выкате; существующие рубильники
  учтены и стали первым средством, а не заменены новым; правило для постановок чипам
  записано в глобальный контекст и в README обоих проектов; сверка «что реально
  уехало» добавлена в скрипт.
- **2. Корректность** — пять сценариев в тесте, включая «пометка уже на проде»
  (гейт не всплывает повторно) и «выкатывать нечего». Отказ происходит **до**
  `reset`, состояние сервера не меняется. Ложное срабатывание безопасно (в сторону
  остановки), обход задокументирован.
- **5. Тесты** — есть, прогнаны в обоих репозиториях, проверяют боевой текст скрипта,
  а не копию. Живого прогона на сервере нет по причине из «Ограничений» — заявлено
  прямо, не выдано за успех.
- **6. Docs drift** — README деплоя обоих проектов и глобальный CLAUDE.md обновлены
  в тех же коммитах.
- **7. Phase integrity** — заглушек и TODO нет; коммит идёт только своими путями
  (в деревьях параллельно работают другие чипы), состав проверяется `git show --stat`
  до пуша.
- **11. Cross-project** — правило деплоя касается LMS и SPW, запись добавлена в
  `ContentBackbone/docs/cross-project/CHANGELOG.md`. Контракты API и схема БД не
  затронуты, `contracts/*.md` и `STATE.md` не менялись.
- **12. Public API** — не затронут (изменений в `app/api/**` нет).

Блокирующих находок нет.
