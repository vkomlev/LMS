# tsk-1131: дробные числа внутри многотокенных ответов — по значению

## Контекст
id-351: ответ `A: 2.33 / B: 1.33 / C: 1.00` против эталона `… C: 1.0` — незачёт:
`strip_punctuation` склеивал `1.00`→`100`, `1.0`→`10`; сравнение по значению из
tsk-1119 работало только для ответа из одного числа.

## Правка
`CheckingService._matches_numbers_in_text` — запасной путь ПОСЛЕ провала текстового
сравнения (только при `strip_punctuation`): числа вынимаются из обеих сторон, на их
место ставится буквенная метка, «скелеты» сравниваются прежней нормализацией, числа —
попарно, в том же порядке и количестве. Условия:
- включается, только если есть хоть одно дробное число;
- целые пары — как текст (`0101` ≠ `101`);
- у ученика дробных знаков не меньше, чем у эталона (`1.00` за `1.0` — да; `89.9` за
  `89.90` — нет, id-10378 задание на формат);
- цепочки `192.168.1.10`, `25.12.2024` — путь не включается.

## Боевой прогон (read-only, 6168 сдач SA/SA_COM со strip_punctuation)
- незачёт → зачёт: 4 (все id-351);
- зачёт → незачёт: 0 (путь только добавляет зачёты).

## Известное, не тронуто
«C: 10» против «C: 1.0» засчитывается и до правки (текстовый путь склеивает 1.0→10) —
ложный зачёт класса tsk-1119 в многотокенных ответах; исправление ужесточит проверку,
нужен отдельный прогон и решение.
