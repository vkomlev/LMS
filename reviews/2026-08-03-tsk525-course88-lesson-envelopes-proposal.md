## Контекст и масштаб

[[tsk-424]] (экспертное ревью) нашло: ни один из разделов курса 88 «Python для ЕГЭ»
не открывается явной формулировкой цели. Задача создавалась под «10 разделов», но
после [[tsk-524]] (добавлен подкурс «Рекурсия» между «Функциями» и «Множествами»)
в графе курса 88 сейчас **11** подкурсов — предложение покрывает все 11, включая
новый.

Формулировки составлены `/methodist` по реальному содержанию (материалы + banка
заданий) каждого раздела — не шаблонной заглушкой. Стиль и разметка —
`<p><b>После этой темы сможешь:</b> …</p>` — взяты из уже устоявшейся конвенции
«конверта урока» CreateCourses, встречающейся в новых курсах LMS (например,
материалы id=1341, 1319, 1345 и др.), для единообразия по всей платформе.

## Куда физически вставляется формулировка

Ни у одного из 11 разделов нет отдельного вводного материала (заглушки) — первый
материал раздела **сразу начинается с содержания** (см. пример: материал 204
«Числовые операции и операторы» открывается «Python предоставляет ряд операций…»).
Поэтому формулировка вставляется **первым абзацем в `content.text` первого по
`order_position` материала раздела** — без создания нового материала (решение по
аналогии с точечными правками содержания в [[tsk-523]], не плодить сущности).

## Разметка вставки (техническая)

Для каждого материала — вставить в начало существующего `content.text` (JSONB,
`format: "html"`) блок:
```html
<p><b>После этой темы сможешь:</b> {формулировка}.</p>
```
перед первым существующим абзацем/тегом материала. Остальной HTML не трогаем.

## Критерии готовности
- Все 11 формулировок утверждены оператором (этот отчёт).
- Запись через `/db-check`: read текущего `content.text` → `UPDATE materials SET
  content = jsonb_set(...)` в транзакции → верификация `SELECT` после коммита
  (независимо через MCP read-only).
- Живой прогон курса 88 в браузере — цель видна первым блоком в начале каждого
  из 11 разделов, навигация/порядок материалов не сломаны.
- `pytest -q` до/после без регрессий (правка контента, кода не касается).
