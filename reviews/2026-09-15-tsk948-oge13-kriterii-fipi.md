## 2. Источник критериев

- **13.1** — методические рекомендации ФИПИ ОГЭ-2026 по информатике (`doc.fipi.ru/.../mr_oge_informatika_2026.pdf`, раздел 2.1; текст извлечён OCR — кириллица из PDF не читается напрямую). Это редакция с макетами слайдов (2 текста + 2 картинки / 3 + 3), совпадающая с нашими условиями. Шкала: 2 — структура/шрифт/изображения по требованиям; 1 — не более одной ошибки суммарно (однотипные считаются за одну) либо два безошибочных слайда; 0 — остальное или чужой формат файла. Слайдов больше трёх — оцениваются первые три.
- **13.2** — демоверсия ФИПИ (зеркало критериев на `inf-oge.sdamgia.ru/problem?id=10585`, там же строки на 1 и 0 баллов, которых нет в МР): 2 — текст 14 пт, выделения, интервал, выравнивание по ширине, отступ 1 см без пробелов, без ручных разрывов, ≤5 ошибок; таблица по образцу, уже текста, по центру, шапка полужирная, выравнивание по столбцам, верхние индексы, ≤3 ошибок; 1 — не более трёх нарушений в каждой части либо одна часть целиком верна; 0 — остальное.

## 3. Решения оператора (AskUserQuestion, 2026-09-15)

1. **Порог зачёта:** задание в LMS на зачёт/незачёт (`max_score=1`) → зачёт = 2 балла по ФИПИ; 1 балл по ФИПИ — незачёт с комментарием, что снижено.
2. **Форматы:** `.pptx/.docx` принимаются наравне с `.odp/.odt` (экзаменационное требование формата в LMS не проверяется); скриншот/PDF — незачёт.
3. Текст критериев — как предложен, без правок.

## 4. Что записано

Один блок `solution_rules.grading_criteria` всем 25 заданиям: `must` 8 / `accept` 8 / `reject` 8 пунктов (каждый 10–500 символов), `notes` 1080 символов, `status=approved`, `origin=manual`, `reviewed_by=2`, `reviewed_at` = момент записи. Текст — в `scripts/tsk948_oge13_criteria.py` (константы `MUST/ACCEPT/REJECT/NOTES`).

Путь записи: `PATCH /tasks/{id}` сервисным ключом (как tsk-945): `GET` текущего задания → `solution_rules` целиком + блок критериев → `PATCH` только `solution_rules`. Скрипт перед каждым PATCH сверяет `external_uid` (префикс `sdamgia:oge:13:`) и `course_id=1178`, после — что ответ содержит `status=approved` и остальные поля правила не изменились; при повторном запуске уже подтверждённые пропускает. Цели берутся из `GET /tasks/by-course/1178` по префиксу uid, не списком id руками; число целей ≠ 25 без `--force` — стоп.

Не использован `POST /tasks/grading-criteria/bulk`: он требует человеческую сессию методиста (`_assert_human_reviewer`) и пишет `origin=import`; условие задачи — `origin=manual`, `reviewed_by=2`, сервисный ключ.
