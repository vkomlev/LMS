## 3. Более широкая проверка — нет ли похожих дефектов в других частях LMS

Раз оригинальный скоуп F10 ограничивался только 25 подкурсами ЕГЭ, проверил оба паттерна дефекта БЕЗ ограничения по курсам — по всей активной базе `tasks`.

```sql
SELECT type, manual_review_required, count(*) FROM tasks
WHERE is_active AND type IN ('SA','SA_COM','TBL_COM')
AND short_answer IS NOT NULL AND jsonb_array_length(short_answer->accepted_answers)=0
GROUP BY 1,2
```

| type | manual_review_required | count |
|---|---|---:|
| SA | true | 132 |
| SA_COM | true | 122 |

**254 задания** (исправлено 2026-07-24: было опечаткой указано 52/174 — не совпадало с
собственной детальной разбивкой §3.2, которая суммируется в 132 = 80+26+26; перепроверено
независимо), но **у всех `manual_review_required=true`** — то есть ни одно не воспроизводит баг «always-wrong» (для него обязательно `manual_review_required=false`, иначе `checking_service` не молча зачитывает `is_correct=False`, а роняет `is_correct=None` через ручную очередь учителя). Активных заданий с пустым `accepted_answers` И `manual_review_required=false` (реальный триггер бага) **в базе не найдено ни одного** — ни в скоупе ЕГЭ, ни за его пределами.

### 3.2 Разбор 174 «ручных с пустым `accepted_answers`» — легитимны ли

Проверил по выборке из каждой группы (типы заданий, `requires_attachment`, реальные стемы):

- **SA, `auto_check=false`, 80 шт.** — курсы ОГЭ `wp:oge-z13/15/16` (написать программу / алгоритм робота / выбрать 13.1 или 13.2). Система сама объявляет `auto_check=false` — ответ принципиально не автосверяем (код-решение), легитимная ручная проверка.
- **SA, `auto_check=true, requires_attachment=true`, 26 шт.** — курс `chat-boty-tg-vk-max` («пришли скриншот, где бот работает»). Легитимно: доказательство сдаётся файлом, сверять нечего.
- **SA, `auto_check=true`, без attachment-флага, 26 шт.** — тот же курс, задания вида «придумай своего бота / собери и покажи видео / выложи на GitHub» (id 6173, 6178, 6179, 6190, 6192, 6194, 6153 — проверено по стему). Открытый проект без единственно верного ответа; `requires_attachment` формально не выставлен (мелкая метаданная-неточность, не искомый дефект — вне объёма tsk-321).
- **SA_COM, `auto_check=true`, 122 шт.** — курс `qa-manual-*` («Опиши в 2-3 предложениях...», «Перечисли...», критерий приёмки текстом прямо в стеме). Рубрика для учителя — часть стема, `accepted_answers` пуст по конструкции задания (эссе-формат), а не потому что «не разобрали ответ».

Отдельно — 24 задания курса `wp:oge-z14` (обработка таблицы) — у них `accepted_answers` **заполнен** (два числа) + `manual_review_required=true` для отдельно прикладываемой диаграммы (`prompt`: «два числовых ответа введите через пробел; диаграмму загрузите файлом — проверит учитель»). Комбинированная авто+ручная проверка по дизайну (аналог `TBL_COM`, tsk-366).

**Ни один из 254 не является дефектом «эталон потерян/не разобран».** Все — легитимный ручной формат по типу задания (код, файл/видео-доказательство, эссе, комбо авто+файл).

## 5. Профилактика
