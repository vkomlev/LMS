## Главная находка: типографика контента материалов не стилизована (SPW)

Живой скриншот материала 241 показал, что `<h3>` внутри `material.content.text`
рендерится **визуально неотличимо** от абзаца — при том, что разметка в БД была
корректной. Причина найдена в коде: `@tailwindcss/typography` (`prose`) не подключён
как зависимость (уже был документированный прецедент для этого в tsk-220 — там же
самом файле, для `<a>`), Tailwind preflight сбрасывает font-size/font-weight у h1-h6
и margin/list-style у ul/ol/blockquote. Это объясняет **большинство** жалоб «выделить
заголовки» (238, 239, 241, 260, 261, 263) одним нажатием — заголовки УЖЕ были в HTML
у 241/260/261, просто без стилей.

**Фикс:** `SPW/app/globals.css` — добавлен блок `.spw-content h1-h6/p/ul/ol/li/
blockquote/hr/table` по образцу уже работающего `.spw-content a`. Затрагивает контент
ВСЕХ курсов платформы, не только курс 88. Проверено локально (скомпилированный CSS
+ реальный HTML материала 241 в изолированной тестовой странице) и живьём на проде
после деплоя (материал 241 — заголовки жирные и крупнее текста; материал 239 —
«Ввод»/«Вывод» отдельными заголовками).

## Побочная находка: production-билд master был сломан (не связано с этой задачей)

При первой попытке деплоя SPW `next build` упал на
`deploy/poligon/new-code/poligon-catalog/page.tsx` (импорт несуществующего
`@/components/poligon/PoligonTierBanner`) — это staging-код для отдельной ветки
`poligon` (tsk-182), который случайно попадал под `tsconfig.json` `include: **/*.tsx`
и типизировался как настоящий роут. Деплой не выполнился, прод не пострадал (старая
версия продолжала работать, `deploy.sh` падает до `systemctl restart`). Фикс —
`tsconfig.json`: `exclude` дополнен `"deploy/poligon/new-code"` (в `app/` таких роутов
нет, изоляция безопасна). Без этого фикса деплой tsk-414 (и любой последующий) был бы
невозможен.

## Не чинили — эскалация оператору

### F. Счётчик прогресса — НОВЫЙ корень, не рецидив tsk-214/261 A1

QA: «5/6, хотя решила все 6» (курс 90 «Как установить Python»), «31/43» — прочитан
раздел про A1/tsk-214 первым, диагноз доведён до конца.

**Диагноз (подтверждено на данных QA):** задача 110 в курсе 90 — `SA_COM`,
`solution_rules.auto_check=true`, `manual_review_required=false` (полностью
автопроверяемая), последняя попытка `is_correct=true`, `checked_at=NULL`.
`_compute_syllabus_task_status()` (`me_service.py`) требует `checked_at IS NOT NULL`
для **любого** `SA_COM`/`TBL_COM`/`TA` (whitelist `MANUAL_REVIEW_TASK_TYPES` по ТИПУ
задания), не глядя на флаг `manual_review_required` — хотя именно этот флаг
(`teacher_queue_service.py`, `tsk-247`) уже является единственным источником истины
«нужен ли вообще учитель» для очереди проверки. `checked_at` ставится ТОЛЬКО учителем
вручную; для авто-проверенных задач учителю нет причины открывать очередь (`review_kind
=optional`) — `checked_at` может не проставиться никогда. Итог: верно решённая
авто-проверяемая задача навсегда виснет `pending_review` в списке прогресса раздела и
не засчитывается в дробь `X/Y`, хотя `learning_engine_service.compute_course_state`
(используется для разблокировки курсов) её уже считает пройденной — те же «три
независимые реализации "пройдено"», что и в tsk-261, но здесь — расхождение НЕ с
`finished_at`, а с `manual_review_required`.

**Масштаб (прод, read-only):** активных `SA_COM`/`TBL_COM` с `manual_review_required=
false` — **2167**; пар (ученик, задание), где авто-верный ответ уже стоит `checked_at
IS NULL` и потому виснет `pending_review` в проценте — **156** прямо сейчас.

**Рекомендация:** `_compute_syllabus_task_status` должен проверять `manual_review_
required` (как `mandatory_review_sql`/`MANDATORY_REVIEW_TEMPLATE`), а не blanket
`task_type in MANUAL_REVIEW_TASK_TYPES` — для `SA_COM`/`TBL_COM` с `manual_review_
required=false` верный ответ должен засчитываться `passed` сразу, как `SC`/`MC`/`SA`.
Это код-изменение с широким охватом (все курсы, не только 88) — решение о фиксе и
объём регресс-тестов нужны от оператора/`/fastapi-api-developer`, не применялось.

### C (шире 3 фиксов). Класс `strip_punctuation` на числовых ответах

Помимо трёх явно подтверждённых QA задач (исправлены), тот же дефект (десятичная
точка/знак минус стираются `strip_punctuation` до сравнения) затрагивает ещё
**~15 задач** с чисто числовым ответом в дереве курса 88 (курсы 103/104/107/110:
id 47,48,52,54,62,65,67,71,116,226,234,358,359,361 и др.). Не расширялось за пределы
явно указанного в письме — риск ложного срабатывания на многострочных/текстовых
ответах (где `strip_punctuation` работает штатно) требует построчной сверки каждого,
не мехнического применения ко всем.

## tsk-313 (нормализация навигаторов) — статус

Канон (эталон CreateCourses, курс 823 «Python для подростков»): каждая смысловая
подтема — `<h3>` (вложенная детализация `<h4>`), перечисления — `<ul>`/`<ol>`, без
голого текста/`<strong>`/`<blockquote>` вместо заголовка. Курс 88 писался вручную на
WP и целиком не атомарен (один материал = несколько подтем) — полная переатомизация
вне охвата этого чипа.

**Сделано:** главный источник жалобы («заголовки не выделены») закрыт CSS-фиксом
платформенно (см. выше) — это касается ВСЕХ курсов, не только 88. Точечно
нормализованы 239 (blockquote→h3) и 263 (убран мусор). Материалы 241/260/261 уже
соответствовали канону в БД.

**Не сделано, зафиксирован остаток:** подкурс 107 «Работа со словарями» почти не
использует `<h3>` вовсе (материалы 247-256), плюс материалы 208/229/240/276/277 —
длинные тексты без внутренних заголовков. Это content-authoring задача (нужно
осмысленно разбить текст на подтемы), не механическая правка — специально не
трогалось, чтобы не исказить смысл автоматической вставкой заголовков произвольно.
Рекомендуется отдельный чип с `/methodist` для смысловой разметки курса 107 (и
опциональной ре-атомизации остальных длинных материалов), если оператор сочтёт нужным
идти дальше платформенного CSS-фикса.
