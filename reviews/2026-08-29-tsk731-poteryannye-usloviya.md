## 2. Корень — найден, а не предположен

### 3470 и 3472 — одна строка кода

`scripts/tsk558_yandex_wp_nav_19_21.py:147` собирал абзацы вопроса так:

```python
p19 = re.findall(r"<p>.*?</p>", q19_html)   # без re.S
```

Без флага `re.S` точка не совпадает с переводом строки, поэтому **любой абзац с
переводом строки внутри в выборку не попадал и молча исчезал**. Перевод строки внутри
абзаца бывает ровно у одного вида содержимого — маркированного списка: Яндекс отдаёт
пункты как `* …` через одиночный CRLF, а `_markdown_to_html` делил текст на абзацы
только по двойному переводу и оставлял оба пункта в одном `<p>`.

Отсюда обе формы дефекта:
- у **3470** хвост «Найденные значения запишите…» уцелел (это отдельный абзац), а
  список между ним и двоеточием исчез — обрыв в середине;
- у **3472** список был последним блоком — текст кончился на двоеточии вовсе.

**Радиус поражения — ровно два задания.** Этот скрипт трогал только 3470 и 3472;
других мест с этой идиомой в `scripts/` нет (проверено грепом).

### 3025 — другое происхождение

Класс A плейбука (`ege-import-playbook.md` §6.3): тело ТГ-поста @cyberguru_ege №956
**уже плоское**, восстановить ниже по потоку нечего. Но пост называет первоисточник:
Яндекс Учебник, задача `4b22ad8f-1eea-4f4f-9f2e-00d45f1a56d9`. Анонимный
`get_task_by_id` отдаёт условие целиком, с настоящей `<table>` из пяти столбцов.

Ключевая деталь: **в таблице источника есть пустые ячейки — это часть задачи, а не
пропуск.** Именно они схлопнулись, когда таблица стала плоской строкой: «1 0 0 0 /
1 0 0 0 / 1 0 0». Оператор увидел это как «потерян столбец и одно значение» — по
факту потеряны позиции пустот, и без них соответствие столбцов не определить.

Настоящий фрагмент:

|  |  |  |  | F |
|---|---|---|---|---|
| 1 |  | 0 | 0 | 0 |
| 1 |  | 0 | 0 | 0 |
|  | 1 | 0 |  | 0 |

## 3. Доказательства, что взят источник, а не шаблон

**3025.** Ответ источника `correct_answers: "zxwy"` совпадает с эталоном в базе.
Сверх того задача решена самостоятельно по восстановленному фрагменту: из F = 0 во
всех трёх строках следует w = 0 и z = 1; столбец с единицей не может быть w, столбец
с нулём не может быть z; перебор четырёх допустимых расстановок оставляет ровно одну,
при которой три строки остаются **различными** (остальные дают две одинаковые строки
или F = 1) — это `z x w y`.

**3470 и 3472.** Решатель `scripts/tsk689_games_solver.py` (калибровка: 20 боевых
эталонов курса 147, расхождений 0) считает ответ **по восстановленной формулировке**:

| id | Задание 19 | Задание 20 | Задание 21 | Эталон в базе |
|---|---|---|---|---|
| 3470 | 22 | 18, 21 | 17 | `22\n18\n21\n17` ✔ |
| 3472 | 17 | 9 | 8 | `17\n9\n8` ✔ |

Сильнее всего это подтверждает 3472: его задание 21 сформулировано **не типовым для
блока образом** — про выигрыш Пети вторым ходом (признак f = 2), а не про Ваню
(f = −2), как у большинства. Типовой шаблон дал бы другой ответ; совпадение с
эталоном возможно только если взят настоящий текст источника.

Дополнительная проверка: после починки кода (см. §5) исправленный скрипт собирает
условия сам — и выдаёт ровно тот текст, который был записан руками.

## 6. Масштаб: класс или три случая

Разобраны все **134** задания, где есть слово «условия:» и нет элемента списка в
разметке (из них активных 64). Проверялось каждое **вхождение** «условия:», а не только
последнее — иначе 3470 выпадал бы из выборки, ведь у него оборван первый из двух блоков.

**Действительно битых — ровно 3 места в 2 заданиях: 3470 (два) и 3472 (одно).**
В остальных 132 условия на месте: они оформлены тире прямо в тексте (`—`, `–`, `−`,
`&ndash;`, `&minus;`) — это не дефект, а другой способ вёрстки.

Расширенная проверка по всей базе — «текст задания кончается двоеточием» независимо от
слова «условия» — дала среди активных заданий **только 3472**. Остальные попадания
законны: вопросы викторин («Тест-кейс — это:»), задания с выбором вариантов
(«Выберите все верные утверждения:»), задание с формулой картинкой (3848) и уже
известный мусор скрейпа «Ответ:» в конце (класс F9, отдельная история).

Вывод: **класс не подтвердился как массовый.** Это одна конкретная ошибка в одном
разовом скрипте, поразившая ровно те задания, которых он касался. Отдельный
еженедельный инвариант на этот класс заводить не нужно — проверять было бы нечего.

## 11. Добор: курсив Markdown у 3470 и 3472

Оператор попросил закрыть и косметику. Условия этих двух заданий пришли из API
Яндекса Markdown-подобной строкой, а разбор знал только `**жирный**` — поэтому
одиночные звёздочки доехали до ученика как есть: «*S* камней; *1 ≤ S ≤ 33*»,
«игрок имеет *выигрышную стратегию*». Шесть мест: 1 у 3470, 5 у 3472.

**Чинилось поимённо, а не регуляркой по базе — и это принципиально.** Активных
заданий с одиночной `*` в стеме — **41**. Но почти везде звёздочка означает
**умножение** («12 = 3 * 4», «2 * 8 = 40», «символ «*»») либо это обломок табличной
вёрстки sdamgia (`*</td><td>*`). Слепая замена на курсив сломала бы там математику —
ровно тот класс ошибки, из-за которого в §6 пришлось разбирать каждое вхождение
руками. Курсив Markdown есть только у этих двух заданий: только их текст пришёл из
Markdown Яндекса.

- Скрипт: `scripts/tsk731_fix_yandex_italics.py`, замены заданы поимённо, порядок
  «сначала длинный фрагмент, потом короткий». Сторожа: текст без тегов до и после
  обязан совпасть (замена меняет оформление, а не содержание); одиночных звёздочек
  после правки не должно остаться ни одной. Повторный прогон даёт «курсив уже
  разобран» — идемпотентно.
- Корень закрыт там же: `_markdown_to_html` теперь разбирает `*курсив*` → `<em>`
  **после** жирного (иначе `**x**` съелось бы как две пары одиночных). В комментарии
  оговорено, что правило годится именно для Markdown Яндекса, а не для произвольного
  текста заданий — по причине выше.
- Живая проверка: обе страницы открыты заново, звёздочек в тексте страницы **0**,
  `S` идёт курсивом — как в нотации ЕГЭ.
