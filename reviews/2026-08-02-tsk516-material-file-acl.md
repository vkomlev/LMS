# tsk-516 — файл материала отдавался без авторизации

**Дата:** 2026-08-02
**Скилл:** `/fastapi-api-developer`
**Файлы:** `app/api/v1/materials_extra.py`, `app/services/materials_acl_service.py`,
`tests/test_material_file_acl_tsk516.py`
**Diff:** `reviews/2026-08-02-tsk516-material-file-acl.diff`

## Контекст

`GET /api/v1/materials/files/{file_id}` не имел ни `Depends(get_current_user)`,
ни ACL — в отличие от соседнего `GET /materials/{id}` (Y-5.1). Найдено попутно
при tsk-010, в охват той задачи не входило.

## Что подтверждено фактически (прод, только чтение)

| Проверка | Результат |
|---|---|
| `curl` без cookie на `/materials/files/<любой>` | **HTTP 404** (дошёл до диска — авторизации нет) |
| `curl` без cookie на `/materials/{id}` (образец) | HTTP 401 |
| `curl` без cookie на `/media/{sha_ext}` | HTTP 307 (публичен **намеренно**, ADR-0040/0047) |
| Файлов в `/opt/lms/uploads/materials/` на проде | **0** |
| Материалов со ссылкой `/api/v1/materials/files/` | **1** (id=187, курс 19, `is_active=true`) |
| Файл материала 187 | **HTTP 404** — ссылка уже битая |

Разница 404 против 401 — и есть доказательство: запрос анонима доходил до
проверки существования файла. Будь файл на месте, он был бы отдан.

## Чем file_id связан с материалом и курсом

**Прямой связи в БД нет.** `POST /materials/upload` кладёт файл на диск под
именем `{uuid4hex}_{оригинал}` и возвращает url; клиент отдельным PATCH сам
вписывает его в `content` материала. Ни колонки, ни таблицы вложений нет.

Связь устанавливается **обратным поиском** по `content` материалов
(`strpos(content::text, '/api/v1/materials/files/<file_id>') > 0`). Отдельная
таблица и миграция не заводились сознательно: файлов на проде ноль, ссылок
одна, а лишняя сущность потребовала бы backfill того, чего не существует.

`strpos`, а не `LIKE`: имя файла содержит `_`, который в `LIKE` значит «любой
символ» и расширил бы совпадение на соседние файлы.

## Пункт 4: ломает ли закрытие публичные страницы сайта

**Нет.** Проверено с трёх сторон:

- ContentBackbone таких ссылок не публикует: 0 совпадений в `monolith/` и 0 строк
  в прод-БД `content_hub` (`material`, `publication`, `link_map`, `asset`).
- Поиск по WP (`victor-komlev.ru`, REST search) — пусто.
- И решающее: на проде **0 файлов**, любая такая ссылка уже сейчас отдаёт 404.
  Ломать физически нечего.

Выносить решение оператору не потребовалось — публичной поверхности нет.

## Изменения

1. **`assert_material_file_access`** в `materials_acl_service.py` — правила
   тождественны `assert_material_access`: сервисный ключ и расширенная роль
   проходят, ученик обязан быть зачислен в дерево курса и не иметь просроченной
   оплаты (`payment_access_service`, tsk-010). Файл может быть вписан в
   несколько материалов (копирование) — достаточно доступа к любому.
   Файл-сирота (окно между upload и PATCH) закрыт для всех, кроме сервиса и
   расширенных ролей: привязать его к курсу не по чему.
2. **`download_material_file`** — `Depends(get_current_user)` + ACL **до**
   обращения к диску, иначе разница 404/200 сама выдавала бы анониму, какие
   файлы существуют. Плюс root-jail по образцу `/api/v1/media` и отсев `\`
   (на Windows-dev он работает разделителем пути, старая проверка его не ловила).
3. **`upload_material_file`** — `require_role("methodist", "admin")`.
   *Сверх запроса:* вторая половина той же дыры — аноним мог писать файлы на
   сервер. Оставлять её открытой после закрытия скачивания было бы странно;
   если оператор не согласен — правка изолирована и снимается одной строкой.

## Совместимость

`get_current_user` принимает legacy `?api_key=` (источник 5), а
`assert_material_file_access` и `require_role` пропускают `is_service` без
проверки роли. TG_LMS шлёт `api_key` в query на **каждом** запросе
(`api_client._request`, строка 317) и вызывает оба эндпоинта
(`get_material_file`, `upload_material_file`) — поведение не меняется.
Покрыто тестом `test_service_key_bypass_keeps_tg_lms_working`.

## Риски и хвосты

- Материал 187 (курс 19, активен) ссылается на **отсутствующий** файл — битая
  картинка на экране ученика. Дефект данных, к этой правке отношения не имеет;
  вынесен отдельно, а не залечен молча.
- Обратный поиск по `content` идёт без индекса. При нынешнем объёме материалов
  это незаметно; если файлов станут тысячи — понадобится GIN-индекс или
  явная таблица вложений.
- Миграций нет, схема не менялась.
