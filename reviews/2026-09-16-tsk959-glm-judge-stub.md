## Измерения
1. Цели — решение оператора «поднять потолок» выполнено; сверх него — отсев заглушки
   в клиенте, потому что именно этот дефект был предметом задачи, а поднятый потолок
   его не закрывает. Отклонение названо в отчёте оператору явно (не DRIFT молча).
2. Корректность — сниффер потока держит только куски, начинающиеся с `[req_`, до 160
   символов; реплика с другим началом проходит без задержки; короткая заглушка ловится
   на `finish()`. Исключение из `feed` идёт тем же путём, что `_check_payload_error`
   (внутри `async with http.stream` → `except LLMError` → следующая модель).
3–4. БД/секреты — не затронуты.
5. Тесты — 13 новых (потолок, три судьи на одной константе, зеркало стенда, причины
   пустого ответа, батч-заглушка → следующая модель, поток-заглушка кусками не доходит
   до ученика, реплика со скобкой не задерживается, короткая заглушка на `finish`,
   стенд называет заглушку). Смежные: 445 passed (`-k llm|tutor|judge|review|…`).
6. Docs — потолок нигде в docs не задокументирован числом; `.env.example` не меняется.
7. Фазы — TODO нет; staged-набор = файлы задачи.
11. Cross-project — контракты LMS↔SPW/TG не менялись.
12. Публичный API — не затронут.
