## Как доказано, что файл тот же

Имя файла в CAS — это sha256 его содержимого, поэтому принадлежность проверяется
пересчётом, а не совпадением имени (урок tsk-390: у заданий 4780-4789 имя файла совпадало,
а содержимое было чужим — другие листы внутри `.ods`).

`scripts/tsk761_verify_links.py` (read-only) для каждого задания скачивает файл по битой
ссылке и сверяет sha256 с sha привязанного CAS-файла. Базы источников: kpolyakov —
`cms/files/` (НЕ `/school/ege/` и НЕ `cms/images/` — там картинки); sdamgia — домен по
относительной ссылке неизвестен, перебираются `ege` / `inf-ege` / `inf-oge`, верным
считается тот, чей sha совпал.

## Изменения в коде

| файл | что |
|---|---|
| `scripts/tsk761_verify_links.py` | новый, read-only: сбор кандидатов из прод-БД + сверка sha256 с источником |
| `scripts/tsk761_rewrite_links.py` | новый: перезапись `href` на `/api/v1/media/<sha>.<ext>`; бэкап, транзакция, проверка внутри и после коммита, dry-run по умолчанию |
| `scripts/check_missing_attachments.py` | второй раздел отчёта: «ссылка на файл мимо нашего хранилища». Прежняя проверка этот класс не видела вовсе — она признаёт задание благополучным по одному наличию ссылки на CAS, а она тут есть, рабочая |

отказ плавающий, а не «файла нет»). Отсюда ретраи в скрипте.
