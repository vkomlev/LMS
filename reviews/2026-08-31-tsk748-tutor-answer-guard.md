# tsk-748 — наставник больше не может выдать готовое решение

**Дата:** 2026-08-31 · **Задача:** Root `tsk-748` (P0) · **Скиллы:** `/fastapi-api-developer`, `/db-check` (read-only), `/review-gate`, `/claude-booster` (правило гейта)

## Что случилось

31.08 на вводной встрече **при ученике** ИИ-наставник спросил, на каком языке
программирования тот работает, сам предложил «скопируй текст задания, и я напишу
решение», и написал программу целиком с разбором (сессия 57, ученик 142,
задание 118, режим `concept`).

| Сколько сессий пострадало | **Одна из 56** — сессия 57 (реплики 157, 159, 163). Реплика 44 сессии 5 — законный микро-пример по методике |

Две поправки к исходной постановке задачи:

1. **«Модель нигде не записывается» — неточно.** По каждой реплике модель пишется
   в `ai_tutor_message.model` с самого начала контура; пуст только `meta` сессии
   (сводка). Версия «ответила запасная мини-модель» проверена и **отпала**.
2. **Журналы прода не понадобились** — ответ лежал в базе.

## Причина

Защита была **только текстовой**. Инструкция запрещала готовое решение — модель
не стала её соблюдать. Усугубляющий фактор: промпт сам себе противоречил —
«ЖЁСТКИЕ ЗАПРЕТЫ: не давать готовый код даже фрагментом» против «Шаг 3. Покажи
микро-пример 3-5 строк», и модель разрешила противоречие в пользу разрешающей ветки.

### Что считается решением (не «любой код»)

Методика разрешает микро-пример на посторонней задаче, и запрет всего подряд
сломал бы объяснение. Режется то, что переносится в поле ответа без понимания:

- законченная программа — есть и ввод, и вывод;
- второй блок кода в одном ответе (реплики 157/159 — справочник по четырём языкам);
- листинг длиннее 5 строк;
- пример на числах из условия задания;
- любой собранный код в режиме `thin`.

## Находки ревью (исправлены до коммита)

1. **Стриминг ломался.** Первая версия придерживала незавершённую строку всегда —
   короткая реплика без переводов строк («Ошибки — это нормально…», 87 символов)
   доехала бы одним куском в конце. Хвост придерживается только когда в строке
   виден зачаток кода.
2. **Голый код проезжал мимо детектора всегда.** Решение принималось по остатку
   строки, а поток приходит кусками по несколько символов — целой строки в руках
   не оказывается никогда. Перестроено: решение по всей строке, выдача только
   неотданного. Регресс закрыт параметризацией по размеру куска (1, 3, 7, 40, 500).
3. **Текст мог переставиться.** Придержанная строка уезжала бы ученику после
   блока кода — добавлен сброс придержанного перед входом в блок.

- Прод-цепочка задаётся `.env` и переопределяет код — правку `.env` нужно
  выкатывать отдельно от кода.
