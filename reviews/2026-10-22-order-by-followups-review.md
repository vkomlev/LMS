## Что сделано

### 1. Лента преподавателя `GET /teacher/activity-feed`: составной курсор

- Порядок ленты теперь полный: `(время, ранг источника, ключ строки)` по убыванию.
  - Ранг источника: `task_solved` 4, `help_requested` 3, `material_studied` 2, `student_idle` 1. При равном времени лента и раньше шла в этом порядке, так что видимый порядок не изменился.
  - Ключ строки: `task_results.id`, `help_requests.id`, `(student_id, material_id)` у `student_material_progress` (это её PK), `lesson_idle_episode.id`.
- Новый query-параметр `cursor` и новое поле ответа `next_cursor`. Курсор — непрозрачная строка (base64url от JSON), клиент передаёт её обратно как есть.
- Как выбирается следующая страница, для каждого источника:
  - ранг ниже, чем у курсора: `время <= курсор`;
  - ранг выше: `время < курсор`;
  - тот же источник: `(время, ключ) < (время курсора, ключ курсора)`.
  
  Рядом стоит отдельное `время <= курсор`, чтобы план мог пойти по индексу времени.
- Обратная совместимость. `before` и `next_before` остаются и работают как раньше: строго по времени. В описании они помечены как устаревшие. `cursor` и `before` вместе — 422.
- Валидация курсора. Ответ 422, а не 500, если:
  - курсор не разбирается;
  - время без часового пояса;
  - год вне 1970–9000;
  - источник неизвестен или не строка;
  - ключ не той длины или вне `1..2^31-1`.
- `get_activity_feed` возвращает 4 значения: добавился `next_cursor`. Вызовы в тестах обновлены.
- SPW (`lib/teacher/use-activity-feed.ts`, `components/teacher/ActivityFeed.tsx`): «Показать ещё» передаёт `next_cursor` в `cursor`. `lib/api-types.ts` перегенерирован из `docs/openapi.json`. Кроме курсора туда попали эндпоинты, уже выкаченные в LMS, которых не было в типах SPW. Изменения в типах только добавляют, ничего не удалено.

### 2. Тариф без оси: один действующий на группу

- Миграция `tsk996_tariff_single_active` (down: `tsk1398_messenger_link_tg`) добавляет частичный уникальный индекс `uq_pricing_tariff_single_active ON pricing_tariff (group_id) WHERE is_active AND match_kind IS NULL`. Это аналог `uq_pricing_tariff_axis_point` для NULL-оси. Схема API и так требует, чтобы `match_value` был NULL, когда NULL `match_kind`.
- `upgrade` сначала ищет дубли. Если они есть, миграция падает с `RuntimeError` и списком «группа N: варианты [id…]». Данные она не трогает.
- Кабинет маркетолога: на `POST /marketer/pricing/tariffs` и `PATCH /marketer/pricing/tariffs/{id}` ответ 409 с понятным текстом: «В группе уже есть действующий вариант без оси…». Раньше дубль создавался молча (201).

### 3. `GET /courses/{id}/tree`: порядок детей

- В `courses_repo.get_course_tree` добавлено `ORDER BY parent_course_id, order_number NULLS LAST, course_id`. Дети узла идут как в `/children`, а `parent_course_ids` у узла — по id.
- Кто потребляет дерево:
  - **SPW — нет**: ни одного обращения к `/tree`. Эндпоинт закрыт гейтом teacher/methodist/admin или сервисным ключом, а ученический SPW берёт разделы курса из `/me/...` (`sections`, см. `me_service`).
  - **Бот TG_LMS** — доступа из облака нет. Если бот рисует дерево, он теперь получит порядок `/children`. Нужно проверить, не сортирует ли он сам.

### 4. Курсы ученика: ответы bulk и reorder

- В `user_courses_repo` порядок вынесен в `_COURSE_ORDER = (order_number NULLS LAST, added_at, course_id)`, тот же, что у `GET /users/{id}/courses`.
- Bulk: новые и уже привязанные курсы отдаются одним списком в этом порядке. Раньше шли сначала новые, потом существующие по `course_id`.
- Reorder отдаёт курсы в новом порядке. `populate_existing=True` нужен, чтобы `order_number` в ответе был из базы, а не из закешированных сессией объектов.
- Попутно, по находке ревью: повтор курса в одной пачке (`[c, c]`) раньше давал 500 (две вставки одного PK). Теперь создаётся одна привязка.

## Независимое ревью (отдельный агент): ПРИНЯТО с правками

Блокирующих находок нет. Логика курсора проверена во всех трёх случаях ранга: ORDER BY каждого источника согласован со слиянием в Python, а PK `student_material_progress` уникален.

| Находка | Решение |
|---|---|
| Важная: курсор с нестроковым источником → `TypeError` → 500 | исправлено (`isinstance(source, str)`), тест |
| Важная: ключ курсора вне int4 → `DataError` → 500 | исправлено (`0 < k <= 2^31-1`), тест сервиса и API |
| Мелкая: крайние даты в курсоре → 500 | исправлено (год 1970–9000), тест |
| Мелкая: нет ничьи с `student_idle`, `has_more` не проверялся | добавлено в тест |
| Мелкая: `[c, c]` в bulk → 500 (было до правки) | исправлено, тест |
| Мелкая: порядок выката | LMS раньше SPW, записано ниже и в коммите SPW |
| Мелкая: лишнее в `api-types.ts` | оставлено: это честная регенерация, изменения только добавляют. Отмечено в коммите |
