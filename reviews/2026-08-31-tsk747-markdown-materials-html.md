# tsk-747 — материалы в markdown показывались ученику сырьём

**Дата:** 2026-08-31
**Задача:** [tsk-747](D:/Work/Root/tasks/tsk-747-materialy-v-markdown-pokazyvayutsya-ucheniku-syryom-pereizdat-6-materialov-v-html.md)
**Скилл:** `/fastapi-api-developer`; фаза записи в боевую базу — по протоколу `/db-check`

## Что было

SPW отдаёт `material.content.text` в `SanitizedHTML`
([MaterialViewer.tsx:43-49](D:/Work/SPW/components/material/MaterialViewer.tsx)), то есть
трактует тело материала как HTML. Поле `content.format` объявлено в типе `TextContent`,
но **не проверяется нигде** — значение `"markdown"` ни на что не влияет.

Материал, записанный в markdown, ученик видел сырьём: решётки заголовков, звёздочки
жирного, тройные кавычки код-блоков как обычный текст, переводы строк схлопнуты
в одну простыню. Подтверждено живьём 31.08.2026 на `/courses/id-1455/material/3863`.

Проверено отдельно и **не** входит в правку:
* 53 материала с `format = html`, где `#` стоит внутри `<pre><code>` — это комментарии
  в примерах на Python, не заголовки;
* 3 материала с `**` вне кода (id 241, 379, 3597) — оператор возведения в степень
  (`2 ** 3`, `4**512`) и маска номера карты, не жирный;
* 98 материалов `format = plain` — все однострочные, схлопывать нечего.

## Что сделано

1. **`app/utils/md_to_html.py`** — конвертер учебного markdown в HTML строго под белый
   список [sanitize.ts](D:/Work/SPW/lib/material/sanitize.ts). Заголовки, абзацы, списки,
   таблицы, `<hr>`, `<pre><code class="language-…">`, `<strong>`, `<code>`.
   Сознательные ограничения:
   * `*курсив*` не поддерживается вовсе — одиночная звёздочка в текстах про Python это
     оператор степени (грабли tsk-215);
   * предикат жирного — строгий, с границей слова (зеркало `fix_stem_markdown_bold_tsk212.py`):
     `4**512 + 8**512` не схлопывается в «512 + 8» жирным;
   * верхний уровень заголовков нормализуется к `<h2>` — под срез дубля `title` в SPW (tsk-217);
   * весь текст вне кода экранируется: голая `<` («< ромб >» в материале про ветвление)
     иначе съедает кусок урока.
2. **`tests/test_md_to_html_tsk747.py`** — 22 теста, включая перечисленные грабли и
   проверку «на выходе только теги из белого списка».
3. **`scripts/tsk747_materials_md_to_html.py`** — переиздание через
   `POST /materials/bulk-upsert` по паре (course_id, external_uid): те же строки, без дублей.
   `is_active`, `order_position`, `requirement_level` не передаются — при обновлении сервис
   их не трогает (tsk-377/tsk-378), поэтому переиздание не включит выключенное и не утащит
   материал в конец курса. `description`/`caption` передаются текущими значениями.
4. **Источник закрыт:** `scripts/import_authored_course.py` и
   `scripts/tsk653_import_mini_course.py` (те два скрипта, что писали `format: "markdown"`)
   теперь конвертируют тело автора в HTML до записи. Иначе markdown вернулся бы
   следующим импортом.

## Что поймал предпросмотр

Первая версия отбора искала markdown-разметку в теле любого материала — и дала
**68 кандидатов вместо 6**: решётки и звёздочки жили внутри `<pre><code>` HTML-материалов
курсов Python. Прогон конвертера по такому материалу превратил бы весь его HTML в
литеральный текст, то есть сломал бы урок целиком. Отбор сужен до `format = 'markdown'`,
плюс в скрипте стоит отдельная сетка: материал с HTML-тегами в теле пропускается всегда,
даже если назван явным `--ids`. Режим `--scan` только перечисляет подозрительные строки,
ничего не конвертируя.

## Риски и хвосты

* `content.format` в SPW по-прежнему декоративен. Материал, записанный в markdown в
  обход этих двух скриптов, снова покажется сырьём. Радикальное закрытие — валидация на
  входе API (`format = "markdown"` отвергать или конвертировать на сервере); вынесено
  отдельным пунктом в задачу, в эту правку не входит.
* ТГ-бот (`TG_LMS`) читает те же тела материалов и имеет свою историю с разметкой
  (tsk-257, tsk-722). Материалы теперь в HTML, то есть в том же виде, что и остальные
  3121 — для бота это не новый класс.
