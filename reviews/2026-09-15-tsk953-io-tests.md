## Цель

55 заданий ОГЭ 15/16 оставались без проверки: `code_ast` (точное совпадение
канона AST) засчитывал 18 % верных решений (замер tsk-950, 61 решение). Решение
оператора — исполнять программу ученика на тестовых входах и сравнивать вывод.
КуМир (курс 1180) в охват не входит.

Решения оператора (AskUserQuestion, 2026-09-15): ученику показывать номер теста,
ввод и ожидаемый вывод (без вывода его программы); 6 тестов на задание;
снять `manual_review_required` — вердикт тестов окончателен; 7245 — числовое
сравнение с допуском 0,05.

## Решение review-gate: ПРИНЯТО

Проверка по 12 измерениям (независимый проход по diff, а не по памяти автора):

1. Соответствие целям — семь шагов задачи: 1–3, 5, 6 в коде; 4 и 7 — исполнение
   после ревью (заполнение через API по `/db-check`, деплой + живая проверка).
   DRIFT нет; развилки учебного смысла вынесены оператору и решены.
2. Корректность — **найдено и исправлено в ходе ревью:** на проде бесконечный
   цикл снимает `RLIMIT_CPU` (SIGXCPU, код −24) раньше wall-clock таймаута, и
   первая редакция классифицировала это как `sandbox_killed` → «сбой песочницы»
   → ответ без вердикта уходил бы преподавателю вместо честного незачёта.
   Добавлено сопоставление `−SIGXCPU/−SIGKILL → timeout` + тест.
   Проверено: `input()` на исчерпанном вводе → своя категория; `print` с
   `sep/end/file`; программа-однострочник не теряется при выборе; `answer_json`
   не подменяется.
3. Данные/миграции — jsonb, миграций нет; запись на прод — только через API по
   протоколу `/db-check`, откат описан.
4. Безопасность — новых эндпоинтов нет (IDOR не применимо); профиль `stdio`
   открывает только `input`/`print`/генераторы; вывод программы ученику не
   показывается (песочница — не канал вывода с сервера); `open/exec/getattr`,
   dunder, `sys`/`os` закрыты; вложение читается тем же `read_code_attachment`
   со сверкой попытки и задания. Hardcoded URL в `app/` — 0 (прод-адрес только
   в `scripts/`, как у tsk-947).
5. Тесты — 29 новых + 400 смежных; корпус 61/61 и 0/165. Живой прогон на проде —
   после деплоя, в этой же сессии (ниже).
6. Docs — контракт и CHANGELOG в CB, openapi пересобран, типы SPW пересобраны.
7. Phase integrity — staged-набор = список файлов выше; TODO/заглушек нет.
8–9. Данные для работы — 30 заданий получают тесты скриптом из спецификаций
   tsk-950 (эталоны проверены исполнением).
10. Дата/время — не затронуто.
11. Cross-project — контракт + CHANGELOG обновлены (STATE без изменений: фаза та же).
12. Public API — новое поле ответа `has_io_tests` (расширение, обратно совместимо),
   openapi в том же коммите; старых путей нет.

Улучшения без блокировки: `sandbox_busy` тратит попытку (паритет с turtle_sim);
при жалобах — отдельная задача.
