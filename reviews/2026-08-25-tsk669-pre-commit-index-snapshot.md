# tsk-669 — pre-commit собирает openapi.json из снимка индекса, а не из рабочего дерева

Дата: 2026-08-25
Задача: `D:\Work\Root\tasks\tsk-669-...md` (рецидив [[tsk-495]] / [[tsk-461]])
Скилл: `/executor-pro`, решение `/review-gate` — см. раздел «Решение ревью».

## Что было не так

`.git/hooks/pre-commit` перегенерировал `docs/openapi.json` из **всего рабочего дерева**
(`scripts/export_openapi.py` импортирует `app.api.main` целиком) и сам делал
`git add docs/openapi.json` — уже после того, как автор указал свои пути через pathspec.
При параллельной работе нескольких сессий в одном дереве (ADR-0008) коммит одной уносил
в схему незакоммиченный код другой. В ночь на 25.08 класс выстрелил трижды за час,
в том числе в обратную сторону: откат присвоенного файла (`git checkout HEAD -- docs/openapi.json`)
стёр регенерацию у пострадавшего.

Правка tsk-495 (не блокирующее предупреждение) работала и не помогала: текст проматывался,
коммит проходил. Плюс хук жил только в `.git/hooks/` одной рабочей копии — его не было
видно в ревью и он не приезжал в свежий клон.

## Что поменялось в поведении хука

| | Было | Стало |
|---|---|---|
| Когда работает | всегда, при любом коммите | только если в коммите есть изменения под `app/*.py` |
| Источник схемы | рабочее дерево | снимок **индекса** (`git checkout-index`) во временном каталоге |
| Куда пишет результат | файл в рабочем дереве + `git add` | blob в **индекс** (`hash-object` + `update-index`); рабочая копия переписывается только если она совпадает с индексом (то есть чужой версии там нет) |
| Если собрать не удалось | (такой ветки не было) | есть незастейдженные правки под `app/` → **коммит блокируется** (exit 1) с двумя выходами: `--no-verify` либо дождаться соседа. Незастейдженных нет → сборка из дерева, как раньше |
| Где живёт | `.git/hooks/pre-commit` одной копии | `.githooks/pre-commit` в репозитории, ставится `scripts/install_git_hooks.sh` (`core.hooksPath`) |

Снимок берётся без `skills/`, `docs/`, `reviews/` — это ускоряет его до ~0.8 с
(полный снимок 2060 файлов занимал ~10 с). `.env` не трекается, поэтому копируется
в снимок отдельно — без него экспортёр не поднимет настройки.

`git stash` / `reset --hard` / `clean` в хуке не используются: дерево общее (ADR-0008).
`scripts/export_openapi.py` по существу не менялся — он пишет в `docs/openapi.json`
относительно родителя своего каталога, поэтому в снимке сам собой пишет в снимок.

## Изменённые файлы

- `.githooks/pre-commit` — новый хук (версионируется).
- `scripts/install_git_hooks.sh` — установка: `core.hooksPath=.githooks` + отключение
  старого `.git/hooks/pre-commit` (переименован в `pre-commit.disabled-tsk669`).
- `.gitattributes` — новый: `.githooks/**` и `*.sh` выкладываются с LF. Без этого при
  `core.autocrlf=true` (текущая настройка машины) в свежем клоне shebang получил бы `\r`
  и хук просто не запустился бы.
- `CONTRIBUTING.md` — раздел «Git-хуки репозитория»: как поставить и что делает.
- `docs/ai/ERRORS.md` — запись о классе (рецидив tsk-495/tsk-461) с профилактикой.

Отдельно про `git hash-object -w --path docs/openapi.json`: флаг `--path` обязателен,
потому что файл схемы лежит вне репозитория (в снимке) и git иначе не знает, какие
фильтры окончаний строк применять. Проверено, что blob из хука совпадает с тем, что
дал бы обычный `git add`:

```
--- blob схемы в индексе после хука ---
8d618da474214e5e9ed38f26760f50a940db79be
--- blob того же содержимого через git add ---
8d618da474214e5e9ed38f26760f50a940db79be
```

## Опыты (на реальном смешанном дереве, не на чистом)

Дерево `D:\Work\LMS` в момент проверки было общим: параллельная сессия держала
застейдженные `app/services/llm/*` и незастейдженный `app/services/task_results_service.py`
(в середине опытов она закоммитила своё — `7ecf7ef`, мои файлы не задев).
Подопытным был **свой** временный файл, чужие не трогались.

### Опыт 1 — источник схемы (главный)

Подготовка: создан `app/api/routes/_tsk669_probe.py` с эндпоинтом `/tsk669-probe-A-index`,
подключён в `app/api/main.py`, оба застейджены. Затем в **рабочем дереве** (без стейджа)
эндпоинт переименован в `/tsk669-probe-B-worktree`. То есть индекс и дерево расходятся.

```

[pre-commit] Сборка docs/openapi.json из снимка индекса...
[pre-commit] docs/openapi.json обновлён в индексе (источник — снимок индекса).
[pre-commit] В рабочем дереве лежит своя версия docs/openapi.json —
[pre-commit] она НЕ перезаписана. В коммит уходит версия, собранная из индекса.
EXIT=0

$ git cat-file -p :docs/openapi.json | grep -o "tsk669-probe-[A-Za-z-]*" | sort -u
tsk669-probe-A-index                 <- версия из ИНДЕКСА

$ grep -o "tsk669-probe-[A-Za-z-]*" docs/openapi.json | sort -u
```

Версия `B-worktree`, лежавшая в дереве, в схему не попала. Старый хук на этом же
состоянии положил бы в коммит именно её.

### Опыт 3 — коммит без `app/`

Коммит этой самой задачи (`.githooks/`, `scripts/`, `.gitattributes`, `CONTRIBUTING.md`,

```
[pre-commit] В коммите нет изменений под app/*.py — docs/openapi.json не трогаем.
```

`docs/openapi.json` не менялся ни в индексе, ни в дереве.

### Возврат состояния после опытов

`git restore --staged` по своим путям, обратный Edit в `app/api/main.py`, удаление
пробного каталога. Проверено: `app/api/main.py` без изменений, индексная версия
`docs/openapi.json` вернулась к `b11e51e` (= HEAD), рабочая копия соседа осталась
нетронутой. `git reset --hard`, `git clean`, `git stash` не применялись.

## Остаточные ограничения (честно)

1. **Индекс — тоже общий ресурс.** Если сосед застейджил своё под `app/`, схема соберётся
   с его кодом. Это заметно слабее прежнего дефекта (незастейдженные правки редактор
   пишет постоянно, стейджат осознанно и ненадолго), но не ноль. От bare-коммита чужого
   индекса защищает отдельный гейт `index_scope_gate.py`.
2. **`git commit -a`** стейджит всё изменённое до запуска хука — в общем дереве он уносит
   чужое сам по себе, независимо от схемы.
3. **`--no-verify`** остаётся осознанным обходом: схема тогда не пересобирается вовсе.
4. Похожего хука в `SPW`, `TG_LMS`, `ContentBackbone` нет — там `.git/hooks/pre-commit`
   отсутствует, чинить нечего.

## Как откатить

```bash
cd D:/Work/LMS
git config --unset core.hooksPath
mv .git/hooks/pre-commit.disabled-tsk669 .git/hooks/pre-commit
```

Это возвращает старое поведение на одной рабочей копии. Полный откат правки —
`git revert <коммит tsk-669>` плюс те же две команды (файлы в репозитории и локальная
настройка `core.hooksPath` живут отдельно).
