# tsk-987 — вводные курсы ЕГЭ/ОГЭ: исправление устаревшей статистики

## Контекст

Исходная постановка (`D:\Work\Root\tasks\tsk-987-...md`) требовала достроить
5 из 6 разделов в каждом из курсов 1474 (ЕГЭ) и 1481 (ОГЭ) — по диагнозу
предыдущей сессии «0 материалов, 0 заданий» под этими курсами.

Диагноз оказался неверным: запрос `materials WHERE course_id=1474/1481` не
заглянул в `course_parents` — у обоих курсов есть по 6 подкурсов-детей
(1475-1480 у ЕГЭ, 1482-1487 у ОГЭ), в каждом свой материал и 5 заданий,
39-41/6-7 учеников уже прошли каждый раздел.

Все 12 материалов построчно сверены с официальными источниками:
- `inf_11_2027.zip`, `inf_9_2027.zip` (спецификации ФИПИ ЕГЭ/ОГЭ-2027,
  `doc.fipi.ru`) — таблицы «Обобщённый план варианта КИМ» (уровень
  сложности, требуется ли спецПО, макс. балл, время) по всем заданиям.
- `inf_mr_2026.pdf` (методичка ФИПИ по итогам ЕГЭ-2026, прислана оператором
  в постановке задачи) — итоговая статистика экзамена 2026 года.

Извлечение текста через `pdftotext` даёт mojibake на этих PDF (шрифты CID
Identity-H). Таблицы спецификаций прочитаны визуально по PNG-рендеру
(`pdftoppm`), методичка (25 страниц связного текста) распознана через
`tesseract -l rus` (модель докачана в scratchpad, `TESSDATA_PREFIX` указан
туда).

11 из 12 материалов точны без изменений. Единственная неточность — средний
балл ЕГЭ по информатике указан как «55,9 за 2025 год» вместо официального
итога уже прошедшего экзамена 2026 года (58,39).

## Правка

Точечная замена в `materials.content->>'text'` (jsonb, HTML):

- Средний балл 2025/55,9 → 2026/58,39, участников 128 тыс. → 131 тыс.,
  порог 80% → 82%, «около 800 человек / 100 баллов» → «0,5% / ≈650 человек»
  (material 3888, раздел «Как сдают по стране»).
- «в среднем на 56» → «в среднем на 58» (material 3888, итоговый абзац).
- «средний балл по стране 55,9» → «58,39» (material 3888, список «Итог»).
- «В прошлом разделе — средний балл 55,9» → «58,39» (material 3890,
  первое предложение, для согласованности с разделом 2).

Источник цифр: `inf_mr_2026.pdf`, стр. 3 — «средний тестовый балл — 58,39»,
«более 131 тыс. человек», «более 82% преодолели минимальный балл», «доля
100-балльников составила 0,5%».

Сравнение с другими предметами (математика 62, физика 61,7, русский 60,7)
оставлено без изменений — это данные 2025 года, свежих аналогичных данных
по другим предметам за 2026 год не было в источнике, подменять их не стал.

## Протокол `/db-check`

Прод — локальный `.env` в `/opt/lms` смотрит в dev-БД, поэтому правка
выполнена скриптом на `lms-spw-vds` под пользователем `app` (правило
`docs/ai/operator-runbook.md`, «прод-скрипты запускать под app»).

1. Снимок «до»: `len`/счётчики вхождений `55,9` и `58,39` в обоих материалах.
2. Dry-run с `assert n==1` на каждую заменяемую подстроку внутри транзакции,
   затем `raise SystemExit` → гарантированный откат.
3. Подтверждение отката повторным снимком (счётчики не изменились).
4. Два прогона реальной записи упали на SQL-синтаксисе:
   - `to_jsonb(:new_text::text)` — `::` рядом с bind-параметром ломает
     парсер SQLAlchemy (`syntax error at or near ":"`);
   - `to_jsonb(:new_text)` без явного каста — asyncpg не может определить
     полиморфный тип (`DatatypeMismatchError`).
   Оба раза транзакция скрипта откатилась сама (exception до `COMMIT`),
   откат подтверждён повторным снимком перед следующей попыткой.
5. Рабочий вариант: `to_jsonb(CAST(:new_text AS text))`. Dry-run прошёл,
   реальный прогон закоммитил, `updated_at` сдвинулся.
6. Верификация после коммита — новый снимок совпал с ожидаемым (счётчики
   `55,9`/`58,39`), затем то же самое перечитано read-only через MCP
   `learn_prod_db` для контроля независимым путём.

Временные скрипты (`tsk987_check.py`, `tsk987_fix.py`, `tsk987_magic.py`)
удалены с сервера сразу после использования.
