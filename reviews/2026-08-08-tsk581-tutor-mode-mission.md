# tsk-581: режим `mission` в CHECK сессий наставника + сторож синхронности

**Дата:** 2026-08-08 · **Задача:** tsk-581 (P1, живой прод-дефект) ·
**Скиллы:** `/fastapi-api-developer`, `/db-check` (до и после), `/review-gate`

## Контекст

`app/services/ai_tutor/prompt.py::pick_mode` с коммита `2f289b2` возвращает режим
`mission` для заданий, которые сдаются артефактом. CHECK-ограничение
`ck_ai_tutor_session_mode` (миграция `tsk572_ai_tutor`) знало только
`concept | debug | deepen | thin`, поэтому вставка сессии падала
`CheckViolationError` → **500 ученику** при открытии наставника на миссии.

Воспроизведено на проде 2026-08-08: `GET /api/v1/ai-tutor/tasks/6341` (курс 1095,
задание «МИССИЯ 1 «Рабочая среда»») → 500. Дефект жил с выката `2f289b2`, то есть
до деплоя tsk-301; не всплывал потому, что миссии есть в одном курсе, где мало учеников.

## DB Findings (`/db-check` до правки)

Прод (`learn`, head `tsk301_subscription`):

```
ck_ai_tutor_session_mode = CHECK (mode = ANY (ARRAY['concept','debug','deepen','thin']))
ai_tutor_session: 7 строк — concept 5 (4 open, 1 closed), thin 2 (open). Строк mission нет.
```

Dev (`Learn`) — тот же head, то же ограничение. Значит рассинхрон был одинаков в обеих БД,
и дефект не «прод-специфика», а пропущенная миграция.

## Про `deepen` (пункт 3 задачи)

`pick_mode` его **не возвращает никогда** — точки входа нет: наставник открывается
только по заданию, а режим целиком выводится из формулировки и присланного ответа.
Инструкция режима в `_MODES` есть, значение в CHECK разрешено, живых строк с ним нет
(0 из 7). Это мёртвая метка, но не дефект: она ничего не ломает.

Решение — оставить и **сделать мёртвость видимой**: третий тест требует, чтобы каждый
недостижимый режим был перечислен в `RESERVED_MODES` с объяснением. Подключение режима
(например, «ученик пришёл с уже принятым ответом») меняет поведение для учеников —
это продуктовое решение оператора, не часть исправления 500.

## Risks / Follow-ups

- Откат миграции переводит строки `mission` → `concept` (иначе старое ограничение
  уронит `downgrade`). Осознанная потеря точности на исторических строках.
- Тот же класс рассинхрона возможен для `ck_ai_tutor_session_status` и
  `ck_ai_tutor_message_role` — там значения в коде живут строками, а не `Literal`,
  и сторож их не покрывает. Не блокирует: сейчас наборы совпадают.
- `deepen` остаётся зарезервированным — решение о точке входа за оператором.
