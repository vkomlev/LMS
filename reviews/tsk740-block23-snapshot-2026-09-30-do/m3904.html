После этого урока ты сможешь: написать программу, которая считает количество различных путей между двумя вершинами ациклического графа, и объяснить, почему прямой перебор путей для этой задачи не годится.

Вспомни: рекурсию и мемоизацию (запоминание уже посчитанных значений) ты разбирал в теме «Рекурсия в Python». Здесь они пригодятся напрямую.

Почему нельзя просто перебрать пути

Первая идея — обойти все пути и посчитать их. На маленьком примере это сработает, но в реальном файле задания путей бывают миллионы: каждая развилка умножает их количество. Перебирать их по одному — значит ждать ответ часами.

Выход в том, что нам не нужны сами пути — нужно только их число. А число путей до вершины складывается из чисел путей до её предшественников. Считать надо не пути, а количества.

Ключевое соображение

Количество путей из вершины X в финиш = сумма количеств путей из всех вершин, куда можно шагнуть из X. Для самого финиша количество равно единице: путь «стоять на месте».

Посмотрим на файле-примере, сколько путей ведёт из вершины 1 в вершину 100. Разметим вершины, начиная с конца:

вершина 100 : 1 путь (сам финиш)
вершина 7   : из 7 ведёт только ребро в 100        -> 1
вершина 4   : из 4 ведёт только ребро в 100        -> 1
вершина 1   : рёбра в 7, в 100 и в 4
              путей = 1 (через 7) + 1 (прямо) + 1 (через 4) = 3

Три пути — ровно те, что мы перечисляли в первом уроке. Обрати внимание: считали мы их, ни разу не выписав сам путь целиком, и веса рёбер здесь не участвовали вовсе.

Программа: рекурсия с запоминанием

def количество_путей(граф, старт, финиш):
    память = {}

    def посчитать(вершина):
        if вершина == финиш:
            return 1
        if вершина in память:
            return память[вершина]
        итог = 0
        for сосед, вес in граф[вершина]:
            итог += посчитать(сосед)
        память[вершина] = итог
        return итог

    return посчитать(старт)

Словарь память здесь и есть мемоизация: каждая вершина считается ровно один раз, а дальше её значение берётся готовым. Без этой строки программа считала бы одну и ту же вершину заново на каждом пути через неё — то есть вернулась бы к перебору со всеми его миллионами.

Почему рекурсия здесь безопасна: граф в задании ациклический, циклов в нём нет по условию. Значит спуск по рёбрам обязательно закончится, и функция не зациклится.

Второй способ: без рекурсии, повторными проходами

Ту же величину можно посчитать без рекурсии. Заведём словарь «сколько путей ведёт отсюда в финиш»: у самого финиша единица, у остальных пока ноль. Дальше повторяем проход по всем рёбрам и пересчитываем словарь целиком, пока числа не перестанут меняться — тем же приёмом, что и Беллман-Форд в прошлой теме.

def путей_без_рекурсии(рёбра, вершины, старт, финиш):
    путей = {в: (1 if в == финиш else 0) for в in вершины}
    for _ in range(len(вершины)):
        новые = {в: (1 if в == финиш else 0) for в in вершины}
        for откуда, куда, вес in рёбра:
            новые[откуда] += путей[куда]
        if новые == путей:
            break
        путей = новые
    return путей[старт]

Здесь пригодился плоский список рёбер из темы про словарь смежности. Пересчёт идёт в новый словарь, а не поверх старого — иначе результат зависел бы от порядка строк в файле, а он произвольный.

Этот способ — независимая проверка: как и в прошлой теме, два разных алгоритма на одном файле обязаны дать одно число.

Про глубину рекурсии. Номера вершин в задании доходят до 1000, и если вершин в файле много, цепочка вложенных вызовов может упереться в ограничение Python (по умолчанию около 1000 вложений) и дать ошибку RecursionError. Лечится либо строкой import sys и sys.setrecursionlimit(10000) в начале программы, либо способом без рекурсии, приведённым выше.

Чем этот вопрос отличается от кратчайшего пути

                 кратчайший путь        количество путей
веса рёбер       нужны                  не нужны
что копим        минимум                сумму
ответ            дробное -> int(...)     целое сразу
инструмент       Дейкстра               рекурсия с памятью

Файл при этом один и тот же, и чтение файла из второго урока переиспользуется без изменений — меняется только то, что делаем с построенным словарём.

Итог:

  • перебор путей не годится: их бывают миллионы;
  • количество путей из вершины = сумма количеств у соседей, у финиша = 1;
  • мемоизация обязательна — без неё это тот же перебор;
  • рекурсия безопасна, потому что граф ациклический, но при большом числе вершин нужен либо поднятый предел вложенности, либо способ без рекурсии;
  • второй способ (повторные проходы по списку рёбер) служит независимой проверкой;
  • веса рёбер в этом вопросе не используются.
