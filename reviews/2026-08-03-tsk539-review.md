прогоном против реальных данных.

## Проверка по измерениям

1. **Соответствие целям** — все три пункта запроса оператора закрыты: фильтр
   по ученику, фильтр по датам, пагинация («список обрывается»). DRIFT нет.
2. **Корректность** — ключевой риск был в верхней границе диапазона дат:
   наивное `submitted_at <= submitted_to` обрезало бы день по полуночи и
   теряло всё, сданное после 00:00. Сделан перевод в exclusive `+1 день` в
   Python (не через SQL INTERVAL — иначе результат зависел бы от таймзоны
   сессии БД), на это есть отдельный тест с временем 15:30, и живой прогон
   подтвердил на реальных данных (76 работ за 21.07, все карточки 21.07.26,
   включая сданные в 10:34).
3. **БД/миграции** — не применимо (read-only query-параметры).
4. **Безопасность** — ACL/identity-гейт не тронуты; фильтры сужают уже
   ACL-scoped выборку. `student_name` идёт через bind-параметр (`:student_name_pattern`),
   не черезف-строку — SQL-инъекции нет.
5. **Тесты** — LMS +7 (`test_pending_filters_tsk539.py`), SPW +7 (стало 25).
   Полный прогон: LMS 1534/11 (было 1527/11), SPW 916 (было 909).
   **Живой прогон против прод-данных, все три функции:**
   - фильтр по ученику: `student_name=Серебрякова` → 930 → 375, в выдаче
     ровно 1 уникальный ученик;
   - фильтр по датам: 21.07–21.07 → 76 работ, все карточки 21.07.26
     (верхняя граница включительна на реальных данных);
   - пагинация: первый запрос `limit=50&offset=0` («показано 50» из 930),
     клик «Показать ещё» → `offset=50`, список вырос до 100 карточек.
   Скриншоты смотрел глазами — строка фильтров рендерится корректно,
   «Сбросить» появляется при заданных фильтрах.
6. **Docs drift** — `docs/openapi.json` обновлён хуком, `lib/api-types.ts`
   перегенерирован. Cross-project контракт — см. follow-up ниже.
7. **Phase integrity** — без TODO/заглушек; pathspec-коммиты, проверено
   `git diff --stat -- app/` (чужого WIP в `.py` нет).
