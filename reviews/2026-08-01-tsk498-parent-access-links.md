# Review-gate: tsk-498 — родительская ссылка на дашборд без регистрации

**Решение: ПРИНЯТО**

## Контекст

Прямое требование оператора поверх только что закрытой [[tsk-478]]: вход по
почте слишком сложен для родителей («могут не разобраться с классической
регистрацией»). Оператор сам раздаёт ссылки лично. Это ВТОРОЙ путь к тому же
экрану — вход по magic-link с ролью `parent` остаётся.

Решения оператора (`AskUserQuestion`): бессрочно + ручной отзыв; несколько
активных ссылок на ученика; голая ссылка без доп. проверок при открытии.

## Изменения

**LMS:** миграция `parent_access_links` (хеш токена, `student_id`, `label`,
`revoked_at`, `last_used_at`); сервис выдачи/резолва/отзыва; три эндпоинта
управления под `require_role("methodist","admin")`; публичный
`GET /public/parent-dashboard/{token}` БЕЗ auth. Расширен фильтр access-лога
(tsk-496) на токен в пути. 13 новых тестов.

**SPW:** публичная страница `/p/{token}` в группе `(public)`; дашборд извлечён
в общий `StudentDashboardView` (один компонент на оба входа); блок выдачи/
копирования/отзыва в карточке ученика. 5 новых тестов.

## Проверка по 12 измерениям

1. **Соответствие целям** — все три решения оператора реализованы буквально;
   путь оператора = 2 действия (создать → скопировать), путь родителя = 1
   (открыть). DRIFT нет.
2. **Корректность** — «голая» ссылка работает без параметров периода (сервер
   сам берёт 30 дней) — иначе ссылка из мессенджера ломалась бы; кривой hex
   не роняет 500 (`bytes.fromhex` в try); отзыв идемпотентен, время первого
   сохраняется.
3. **Безопасность данных/миграций** — round-trip `upgrade→downgrade→upgrade`
   на dev чист. FK CASCADE на `users`: удаление ученика уносит его ссылки.
4. **Безопасность / trust boundary** — главное измерение этой задачи:
   - Токен 32 байта `os.urandom` (256 бит) — перебор невозможен.
   - В БД только sha256; сырой токен виден один раз в ответе на создание и
     не восстановим. Утечка списка ссылок ≠ утечка доступа (тест).
   - Токен НЕ сессия: открывает ровно один read-only эндпоинт ровно одного
     ученика. Войти по нему в LMS под учёткой нельзя — принципиальное
     отличие от `auth/test/issue-session` (тот закрыт от прода не зря).
   - Отозванный / несуществующий / мусорный токен → 404 с ОДИНАКОВЫМ текстом
     (тест сравнивает `detail` всех трёх) — ответ не подтверждает, что токен
     когда-либо существовал.
   - Ссылка параметризована `student_id` — токен ученика А не показывает Б
     (тест).
   - Дорогая агрегация дашборда защищена дешёвым индексным резолвом токена:
     невалидный токен отсекается до всякой работы, поэтому неаутентифицированный
     эндпоинт не даёт DoS-рычага без знания валидной ссылки.
   - **Принятый риск (решение оператора, задокументировано):** кто открыл
     ссылку — тот видит дашборд. Смягчено тем, что дашборд read-only и по
     контракту tsk-494 не содержит ни `solution_rules`, ни текста переписки.
5. **Тесты** — 13 backend (реальная БД) + 5 frontend. LMS полный прогон:
   1332 passed / 11 skipped / 0 failed. SPW: 807 passed (1 unhandled error в
   `methodist-schedule.test.tsx` — ПРЕДСУЩЕСТВУЮЩИЙ, файл не трогали).
   `type-check` чист, `lint` 0 errors (16 warnings — все предсуществующие).
6. **Docs/Config drift** — задача в трекере заполнена контекстом и решениями;
   `openapi.json` регенерирован (223 эндпоинта); `.skill-engaged-note.md`
   обоих репозиториев обновлены.
7. **Phase integrity** — staged-набор сверен построчно, только tsk-498.
   `tsconfig.json` в SPW (переписан Next при сборке) исключён из коммита.
8-9. Не применимо.
10. **Date/Time** — период на публичном эндпоинте timezone-aware, инверсия →
    422; дефолт считается от `datetime.now(timezone.utc)`.
11. **Cross-project memory** — обновляется сразу после этого PASS (тот же
    порядок, что tsk-494/tsk-478).
12. **Public API Contract Sync** — три новых эндпоинта + один публичный;
    OpenAPI в том же коммите; hardcoded URL нет (адрес ссылки строится из
    `settings.public_base_url`).

## Блокирующие проблемы (найдена и исправлена в ходе ревью)

- **[Исправлено]** Токен утекал в access-лог открытым текстом. Фильтр
  `AccessLogRedactingFilter` (tsk-496) маскирует только `api_key=` в QUERY, а
  здесь токен едет в ПУТИ (`/public/parent-dashboard/{token}`) — под паттерн
  не попадал. Для magic-link такой лог почти безобиден (токен одноразовый,
  TTL 15 минут), здесь наоборот: ссылка **бессрочная и многоразовая**, то
  есть строка в `/var/log/lms/app.log` — рабочий пропуск к данным ученика
  навсегда для каждого, у кого есть доступ к логам. Добавлен
  `_PATH_TOKEN_RE`; маршрут в логе остаётся читаемым, подставляется только
  маска. Тест `test_access_log_redacts_token_in_url_path`, регресс tsk-496
  зелёный.

## Улучшения без блокировки

- `DELETE /parent-access-links/{link_id}` не сверяет, к какому ученику
  относится ссылка — но гейт `methodist/admin` и так глобальный (эти роли
  управляют всеми учениками), сужение ничего бы не дало.
- Страница `/p/{token}` помечена `robots: noindex, nofollow` — ссылка не
  должна попасть в поисковую выдачу, если её где-то опубликуют.
