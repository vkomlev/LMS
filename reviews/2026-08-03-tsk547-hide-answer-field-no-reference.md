# tsk-547 — поле «Ответ» скрыто у заданий *COM без эталона

Дата: 2026-08-03
Skill: `/fastapi-api-developer` (парная правка LMS + SPW)
Задача: `D:\Work\Root\tasks\tsk-547-...md` · хвост [tsk-546](2026-08-03-tsk546-sa-to-sa-com-migration.md)
Коммиты: LMS `5859584`, SPW `3a7f96f`

## Задача

После tsk-546 у 271 активного задания `SA_COM` эталона для сверки
`response.value` нет вовсе: ОГЭ-13 сдаётся файлом `.odp`/`.odt`, ОГЭ-15/16 —
программой для исполнителя, авторские бот-проекты — скриншотом или объяснением.
Поле «Ответ» для них бессмысленно, но форма требовала его заполнить — ученик
писал туда что-нибудь формальное, лишь бы кнопка разблокировалась.

## Почему это не чисто фронтовая правка

SPW под учеником **не получает `solution_rules`** — видимость полей это
отдельный слой (tsk-460, эталон только привилегированному). Определить «эталон
пустой» на клиенте невозможно, нужен производный флаг с сервера.

Прецедент ровно этой формы уже был — `requires_attachment` (tsk-227): считается
в `learning.py`, отдаётся булевым полем схемы состояния задачи, клиент
интерпретирует как UX-сигнал. Сделано по нему.

## LMS (`5859584`)

- **`SolutionRules.has_reference_answer()`** — предикат «эталон есть» вынесен из
  `checking_service._check_table_answer:705` (чистое извлечение, поведение то же).
  Единая точка нужна, чтобы «сверять нечем» на проверке и «поле ответа
  бессмысленно» в форме не разъехались. Пустое правило живёт в трёх формах
  (SQL NULL / JSON-null / объект-но-пустой), и наивная проверка ловит только
  первую — плейбук ЕГЭ §6.1, эта ошибка дважды давала ложное «всё чисто».
- **`TaskStateResponse.has_reference_answer`** (`learning_api.py`), default
  `true` — если поле не пришло, клиент ведёт себя как раньше.
- **Типо-зависимость** (`learning.py`): у `SC`/`MC`/`TA`/квизов блок
  `short_answer` не заполняется в принципе, и голое «эталона нет» клиент принял
  бы за «поле ответа не нужно». Для них флаг всегда `true`.

## SPW (`3a7f96f`)

- **`TaskFormSA_COM`**: поле «Ответ» скрыто при `hasReferenceAnswer=false`,
  `answerMissing` снят из гейта отправки (иначе кнопка была бы заблокирована
  навсегда — заполнить нечего). Заголовок комментария меняется на «Ваш ответ»,
  подсказка — на «Впишите решение… либо приложите файл»: он теперь и есть ответ,
  а «можно добавить» вводило бы в заблуждение.
- **`TaskFormTBL_COM` намеренно НЕ тронут**: на проде 0 табличных заданий без
  эталона, гасить сетку не на чем. Флаг на бэкенде есть, если случай появится.

### Три места, где пустой `value` молча ронял поток (найдены по пути)

Ни одно не всплыло бы из постановки задачи — все три нашлись чтением кода вокруг:

1. **`page.tsx` `onChange`** — `ans.value.trim() ? {...} : null` обнуляло
   `currentAnswer`, и отправка по Enter молча не срабатывала. Условие сделано
   зависимым от флага: для заданий С эталоном прежнее (иначе Enter отправил бы
   пустой ответ).
2. **`page.tsx` восстановление черновика** — требовало непустой `value`, то есть
   ученик терял набранное решение при возврате на страницу.
3. **`saved-answer.ts` + `TaskHistoryCard`** — «нет `value` → ответа нет»
   скрывало у таких работ **весь** блок «Мой ответ» и комментарий ученика в
   истории. То есть ученик не видел собственное решение, а преподаватель — в
   карточке проверки (заодно молча ломалась фича tsk-543).
   `MyAnswerReadonly` больше не рисует пустую серую плашку вместо ответа.

**Фронтенд — развёрнут (`3a7f96f`), но живьём НЕ проверен.** Сессия оператора в

нельзя — юнит-тесты и типизация это не доказывают (`feedback_live_check_means_look`).

> уже не принимается. Доказательство — только результат самой страницы.
