# review-gate — tsk-932: устаревший дедлайн в напоминании о расписании

## Решение: ПРИНЯТО

## Находка
Живой UX/UI-аудит бота TG_LMS (tsk-306, 13.09) увидел один и тот же текст
«Расскажите, когда вам удобно заниматься осенью» с фразой «Ответить нужно до
30 августа», отправленный 29.08, 3.09, 6.09 и 12.09 — без пометки «повтор» и
без пересчёта даты.

## Диагностика
- Механизм найден: `LMS/app/services/schedule_preference_reminder_service.py`
  — суточный крон (`reminder_tick`), кладёт строку в `notifications`
  каждому молчащему ученику не чаще раза в 48 часов (cooldown по последнему
  напоминанию этого вида). Ретрай **осознан** — прямая постановка оператора в
  tsk-674: «Пока расписание не заполнено — напоминать постоянно».
- Бот TG_LMS (`schedule_preference_poller.py`) не сочиняет текст сам — берёт
  готовым из LMS (`title`/`content`/`payload.url`). Значит источник бага —
  LMS, а не бот.
- Баг — не в частоте повтора, а в тексте: `_TITLE`/`_BODY` и
  `payload["deadline"]` были захардкожены на момент запуска кампании (25.08) и
  никогда не пересчитывались.
- `/db-check` (read-only, прод `learn_prod_db`) подтвердил на живых данных:
  - 83 строки напоминаний, 38 уникальных получателей;
  - 16 получателей с >1 отправкой, из них 4 — реальные (не `test`) активные
    ученики: id 4509/4514 (`alumni`, 3 отправки, дальше исключены фильтром
    аудитории после смены тарифа), id 4518/4568 (`base_legacy`, 4 отправки:
    29.08 → 3.09 → 6.09 → **11.09**, дедлайн к последней отправке просрочен
    почти на две недели);
  - расписание к 11.09 уже свёрстано методистом и действует с 1 сентября
    (tsk-674 фаза 2) — то есть текст утверждал не просто «дедлайн прошёл», а
    «дедлайн, по которому решение уже принято без вас»;
  - id 4518/4568 сейчас исключены из молчащих через `student_schedule_preference_ack`
    (tsk-923, отметка «получено вручную» методистом 12.09) — это ручной
    workaround конкретного случая, не фикс самого текста; следующий ученик,
    который замолчит на пару недель, попал бы в ту же ловушку.
  - `payload["deadline"]` не читается нигде — ни ботом TG_LMS
    (`format_schedule_preference_message` берёт только `payload.get("url")`),
    ни кабинетом SPW (grep по `deadline` в SPW не нашёл использования этого
    поля от этого напоминания).

## Фикс
- `_BODY`: фраза с конкретной датой убрана, заменена вечнозелёной
  формулировкой без числа — не устаревает и не требует новой правки к
  следующей похожей кампании. Глаголы переведены в прошедшее/настоящее
  завершённое время («переехали», «уже собрано») — раньше текст на 13-й день
  после дедлайна всё ещё говорил «переезжают»/«собирается», как будто это
  ещё впереди.
- Формулировка второй ревизии (после первого прохода ревью): «и запишитесь
  на подходящее время занятий» вместо «и мы запишем вас» — по факту студент
  выбирает слот сам на той же странице (`/me/schedule`, фаза 3 tsk-674,
  подтверждено историей задачи: «новый ученик после пожеланий остаётся на
  странице и выбирает занятие»), автоматической записи нет.
- `payload["deadline"]` удалён — хранить неиспользуемое поле с застывшей
  датой в БД незачем.
- Сам механизм ретрая (cooldown 48ч, аудитория молчащих, дедупликация) не
  тронут — это подтверждённое решение оператора, не баг.

## Проверка 12 измерений
1. Соответствие целям — да, находка закрыта полностью (и текст, и мёртвый payload).
2. Корректность — да; edge case «студент выбирает слот сам, а не система»
   найден и исправлен в этом же проходе (см. выше).
3. БД/миграции — нет миграции, только литералы в сервисе; безопасно.
4. Секреты/инъекции — не затронуто.
5. Тесты — `LMS/tests/test_schedule_preference_tsk674.py` (27, зелёные),
   `TG_LMS/tests/unit/test_schedule_preference_poller_tsk674.py` (8, зелёные,
   не привязаны к конкретному тексту LMS — бот получает контент от LMS как
   есть). Ни один тест не проверял дословный текст с датой или
   `payload["deadline"]`, так что фикс их не ломает.
6. Docs/config drift — нет: правка не меняет API/схему, только константы
   внутри сервиса; обновление контрактов не требуется (см. п.11).
7. Phase integrity — фикс завершён целиком за один проход, TODO не осталось.
8-10. Не применимо (нет справочников/классификаторов/дат для сравнения типов).
11. Cross-project memory — `ContentBackbone/docs/cross-project/*` не
    документируют дословный текст напоминания или форму `payload`, только имя
    модуля/факт существования канала — обновление не требуется.
12. Public API contract — не затронуто, эндпоинты и форма ответа не менялись.

## MANDATORY-триггеры
Ни один не сработал (не auth, не публичный API, не cross-project контракт, не
миграция, не Next.js граница, не `as Type`).

## Operator handoff
Категория А (routine): коммит → пуш → деплой на прод → живая проверка —
делает агент сам, по стоячей авторизации оператора (`CLAUDE.md`, «Коммит /
пуш / деплой»). Деплой обязателен вместе с живой проверкой в этой же сессии.
