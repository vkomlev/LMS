## 2. Находка, которой не было в постановке

**Снятие с расписания стирает долг.**

Цепочка: у ученика без активных слотов резолвер цены не может выбрать вариант
(частотная ось) → `charge_service.recalculate_student_group` получает
`base is None` → **удаляет открытую строку месяца**, если по ней нет платежа
(`app/services/charge_service.py:326`). Ежедневный тик
`charge_cron_service.charge_cron_tick` делает это сам, даже если пересчёт не
звать руками: `recalculate_month` добирает строки по признаку «есть открытая
строка за период».

Доказательство на живых данных — три выпускника без слотов (4499, 4521, 4523):
начислений не осталось **ни за один месяц**. У 4497 и 4500 строки уцелели только
потому, что по ним есть подтверждённые платежи (DELETE защищён проверкой
`NOT EXISTS (student_payment …)`).

Отсюда порядок действий в механизме: **свод → заморозка долга → снятие с
расписания**. Обратный порядок стирает то, ради чего задача и написана.

## 3. Решения оператора (2026-08-25, через AskUserQuestion)

| Развилка | Решение | Что это значит в коде |
|---|---|---|
| Что считается долгом | Остаток по **всем открытым месяцам**, приложенный чек долг гасит | `graduation_service.settlement` берёт `status='open'`, покрытие считает `payment_service.payment_state` (`is_unpaid`) |
| Будущие занятия | Снять и «назначено», и «на перерыве» | `DETACHABLE_STATUSES`; без второго `break_service` вернул бы выпускника в расписание сам |
| Что закрывается | Только сдача заданий, материалы на чтение | `subscription_plan.course_work`, гейт в трёх точках приёма работы |

Факт, снявший часть вопроса про «историю до августа»: в `student_monthly_charge`
существует **только период 2026-08** — истории до августа нет вовсе.

## 4. Что сделано

### Схема

`app/db/migrations/versions/20260825_020000_tsk673_alumni_course_work.py`
— колонка `subscription_plan.course_work` (bool, по умолчанию `true`),
`false` только у `alumni`.
Revision `tsk673_alumni_course_work`, down_revision `tsk674_schedule_preference`.
**Rollback:** `alembic downgrade tsk674_schedule_preference` — вместе с откатом кода
(гейт читает колонку напрямую, без неё запрос упадёт).

Признак в данных, а не набором кодов в сервисе — тот же довод, что у
`billing_exempt` (tsk-610): следующий тариф-архив не должен требовать релиза.
Значение по умолчанию `true`, потому что обратное закрыло бы задания всем, у
кого тариф ещё не размечен.

### Сервис

`app/services/graduation_service.py` (новый):

* `settlement` — начислено / оплачено / ждёт разбора / остаток по открытым
  месяцам. Своих формул нет: итог месяца считает `charge_service.charge_total_minor`,
  покрытие — `payment_service.payment_state`;
* `schedule_plan` — активные слоты и будущие занятия; считает **ровно то**, что
  снимет `apply`, чтобы предпросмотр не расходился с действием;
* `apply` — свод → заморозка при остатке → снятие с расписания → эскалация.
  Не коммитит: перевод, снятие и эскалация обязаны быть одним целым;
* `assert_course_work_allowed` — гейт сдачи, `DomainError 403` с машинным
  признаком `course_work_closed` (по образцу `payment_overdue`, tsk-617).

**Пересчёт денег при снятии здесь НЕ зовётся** — в отличие от обычного
открепления (`lesson_calendar_service._recalculate_money_for`). Это осознанное
отличие, объяснённое в docstring: пересчёт удалил бы строку вместе с долгом.

**Заморозка** — перевод открытых месяцев ученика в `status='closed'`. Закрытый
месяц пересчёт не трогает вовсе (durable-инвариант денежного контура). Суммы при
этом **не меняются**: переставляется только статус.

### Правка соседнего модуля

`payment_service.ChargePaymentState` получил поле `is_unpaid` — величина уже
считалась внутри `payment_state` под именем `unpaid`, просто не выставлялась
наружу. Сделано, чтобы не заводить четвёртую копию правила «чек гасит долг,
только если покрывает остаток». Расчёт денег не затронут.

### API

* `GET /subscriptions/students/{id}/graduation-preview` — свод и след в
  расписании до нажатия, без единой записи;
* `POST /subscriptions/students/{id}` при `plan_code = alumni` выполняет
  побочные действия и возвращает их в поле `graduation`.

Хук висит в роутере, а не внутри `change_plan`, потому что это **единственный
путь** на «Выпускника»: продать его нельзя (нет тарифной группы), автоматика
переводит только на `base`. Один путь — один хук, тихого обхода нет.

### Гейт сдачи — три точки

| Файл | Что закрывает |
|---|---|
| `app/api/v1/attempts.py` (создание попытки) | обходной путь мимо учебного движка |
| `app/api/v1/attempts.py` (приём ответов) | сама сдача |
| `app/api/v1/learning.py` (start-or-get-attempt) | штатный путь клиента |

Проверка идёт **по ученику, а не по вызывающему** — иначе блокировка снималась
бы сменой клиента (класс tsk-433/tsk-617). Материалы, чтение задания и
`material_complete` не тронуты: закрыта сдача, а не курс.

### Экран маркетолога (SPW)

`components/marketer/StudentSubscriptionPanel.tsx`:
блок последствий появляется только при выборе «Выпускника» — что снимется
(слоты поимённо, число занятий), свод оплаты с суммой-эталоном рядом с остатком,
и итог сразу после нажатия. В списке тарифов «Выпускник» помечен «задания не
сдать».

Итог показывается на экране, а не только уходит в уведомления, — прямой ответ на
урок tsk-591/652 («механизм работал, а сигнал висел непрочитанным»): маркетолог
нажимает кнопку сам, и этот момент — единственное место, где сигнал точно будет
увиден. Запись в кабинет маркетологам и админам остаётся как страховка.

## 8. Риски и хвосты

**Р-1. Закрытие месяца одному ученику откатывается только оптом.**
`POST /charges/reopen` открывает месяц всей школе. Если маркетолог откроет
август обратно, строка выпускника тоже станет открытой — и следующий пересчёт
её удалит. Вероятность низкая (открытие месяца задним числом — редкая операция),
цена — потеря одной строки долга. Отдельная кнопка «открыть месяц одному
ученику» в охват задачи не входила.

**Р-2. Пропуск задания (`task_skip`) выпускнику по-прежнему доступен.**
Оператор закрыл «сдачу заданий»; пропуск — не сдача, и расширять охват молча я
не стал. Практического вреда нет: попытку выпускник всё равно не начнёт.

**Х-1. Выпускники до этой правки.** 4499, 4521, 4523 остались без начислений —
их строки удалены пересчётом ещё до задачи. Восстанавливать их эта задача не
должна (прямой запрет «не делать массовый пересчёт по прошлым выпускникам без
решения оператора»). Если суммы за них нужны — это отдельная задача с решением
оператора.

**Х-3. Кнопка «Запросить помощь преподавателя» у выпускника осталась видимой.**
Нажатие упрётся в гейт прав (`teacher_escalation = false` у «Выпускника», режим
гейта на проде `on`), то есть отказ будет — но кнопку человеку показывают зря.
Это поверхность tsk-301, а не эта задача; в охват не входило.

**Х-2. Соседний чип tsk-674.** Цепочка миграций согласована через SendMessage:
их ревизия закоммичена первой, моя цепляется за неё. `alembic heads` — одна
голова. В процессе работы их откат цепочки на dev снял мою колонку и дал 36
ложных падений; восстановлено точечно (`stamp` → `upgrade` только моей ревизии →
`stamp`), их таблицы не тронуты.
