## Проверка по измерениям (12)

**1. Соответствие целям.** Декомпозиция из файла задачи выполнена по всем 5 пунктам:
пост→ID→задание (через `external_uid`, не через тело поста — точнее), ID→видео
(через заголовок VK-видео), bulk-запись через `/db-check`-протокол (read→dry-run→
apply→верификация), живая проверка в SPW, отчёт с числами по обеим сторонам
(привязано/не найдено). DRIFT: нет.

**2. Корректность.** Ключевая находка в процессе: первая версия join через
`content_hub.asset.source_item_id` подвержена коллизии — один `content_hash`
технически прикреплён к двум разным ТГ-постам (пост 14856 "17_37359" технически
нёс тот же файл, что видео задания 70532). Обнаружено сверкой заголовка VK-видео
с текстом поста (см. `tsk324_build_video_hint_mapping.py` докстринг). Финальная
версия строит маппинг **только** из заголовка самого видео (`(N_ID)` в
`raw->>'title'`) — независимо от того, к какому посту технически привязан файл.
Проверено: 0 случаев, когда один `video_url` встречается под двумя разными
`ext_id` (скрипт-проверка на JSON-артефакте, 374 уникальных URL, 0 коллизий) —
значит внутри-одного-ext_id дубли (пере-заливка того же ролика) не искажают
привязку к чужому заданию.

**3. Безопасность данных/миграций.** `tsk324_apply_video_hints.py`: полная
транзакция (`async with conn.transaction()`), snapshot ДО (md5 stem/solution_rules),
UPDATE с WHERE-гвардом (`is_active AND hints_video пуст` — перепроверяется в самом
UPDATE, не только в SELECT, что защищает от гонки с параллельной записью), assert
`updated == len(plan)`, верификация ПОСЛЕ (hints_video == план, has_hints=true,
md5 stem/solution_rules не изменились). Dry-run по умолчанию (raise → implicit
rollback), `--apply` явный флаг. Независимая верификация ПОСЛЕ commit — отдельным
read-only MCP-каналом (`learn_prod_db`), не только встроенной проверкой скрипта
(см. [[feedback_local_env_prod_dsn_gotcha]] урок): `sdamgia with_hint` 8→157
(+149, совпало), kompege/polyakov не изменились (ожидаемо).

**4. Безопасность/секреты.** DSN читается из `.mcp.json` (не хардкожен, не в git),
паттерн идентичен принятому прецеденту `backfill_python_hints_video_tsk316.py`.
Запись прошла под `DBCHECK_OK=1` (гейт `db_write_gate` пройден осознанно).

**5. Покрытие тестами / живая проверка.** User-facing изменение развёрнуто на
прод и проверено в той же сессии (ветвь А, обязательное правило) — 3 разных
задания (2235/15949, 2374/9699, 2263/18621) открыты под живым студенческим
аккаунтом 142 (вход через реальный magic-link consume, `/me` подтверждён:
«Привет, Комлев Виктор!»). Блок «Подсказки» показывает верное число
видео-подсказок для каждого. Для 2235 открыт VK-плеер: заголовок и описание
видео дословно совпадают с текстом задачи в LMS (IP 98.162.77.94 → 98.162.64.0).
**Ограничение:** ни `claude-in-chrome`, ни in-app Browser не смогли отрендерить
движущиеся кадры VK-плеера — проверено, что это ограничение окружения (тот же
результат на постороннем ролике с 9,3 тыс. просмотров с другого канала), а не
признак битой ссылки. Доказательная база (точное совпадение метаданных видео +
рабочий плеер без ошибки «видео недоступно») достаточна для ПРИНЯТО, но
отмечается как единственный некритичный пробел — см. «Улучшения без блокировки».

## Улучшения без блокировки
- Оператору стоит один раз лично открыть VK-ссылку в обычном браузере и
  убедиться, что видео действительно проигрывается — автоматизированные
  инструменты сессии не смогли подтвердить это визуально (ограничение
  окружения, не находка о содержимом).
- 18 заданий без видео (kompege id=10028/ext=27425; 17 sdamgia id перечислены
  в выводе dry-run) можно разобрать вручную отдельным заходом — не блокирует
  текущий проход, зафиксировано в отчёте оператору.
- Krylov (v{variant}t{task}-схема, ~388 потенциальных кандидатов) — отдельная,
  более сложная схема join (пара вариант+номер, не единый числовой ID), не
  входила явно в scope этой сессии; можно вынести отдельной задачей при
  интересе оператора.
