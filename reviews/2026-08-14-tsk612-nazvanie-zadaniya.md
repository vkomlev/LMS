# tsk-612 — короткое название задания (находка F5 аудита навигации методиста)

**Дата:** 2026-08-14
**Задача:** `tsk-612` (закрывает F5 из `tsk-600`; волна `tsk-607` закрыта 2026-08-13)
**Проекты:** LMS (API + данные), SPW (кабинет методиста). ContentBackbone — к сведению.

## Контекст

Заголовок карточки задания в кабинете методиста показывал «Задание #5385» и
технический слаг, а в разборе темы задания подписаны первыми словами условия —
три подряд начинались с «Исходный код для этого задания:» и не различались.

**Разведка опровергла исходную постановку.** Предполагалось, что поля с названием
нет и нужна миграция. По источнику:

| Слой | Факт |
|---|---|
| БД | `tasks.task_content->>'title'` существует; 7554 задания, непустое название у **105** (все `sdamgia:oge`, шаблон «ОГЭ. Задание 13 (презентация) — вариант 10593»), 7376 — JSON-null |
| API | `TaskRead.task_content` отдаётся целиком → `title` уже доезжал до клиента. **Миграция не нужна** |
| Бэкенд | `app/utils/task_title.py::humanize_task_title` (curated title → очищенный stem → external_uid → «Задание #id») уже подключён в поиске, разборе темы, очереди преподавателя, заявках помощи |
| Поиск | `task_search_service` уже ищет ILIKE и по `title`, и по `stem` |
| Конвейер CB | явно шлёт заглушку `"title": ""` (`lms_import_file.py:234,409`, `wp_nav_import.py:546,613,655`) — заголовка у источника нет |
| SPW | `TaskDetail.tsx` и `CourseDetail.tsx` игнорировали `title`, подпись собиралась только из `stem` |

Вывод: не хватало **самих названий** и двух мест во фронте, а не поля и не миграции.

## Решение оператора (2026-08-14)

Названия генерирует модель по условию, вычитка методистом идёт после (названия
работают сразу). Охват — активные задания (**6422** без названия из 6527 активных).
Отвергнут детерминированный шаблон «курс + номер варианта»: различает задания,
но не говорит, о чём они.

## Почему защита названия точечная, а не через `content_provenance`

Существующая пометка `manual_web` (tsk-433) защищает `task_content` и
`solution_rules` **парой и целиком** — импорт перестал бы обновлять условие
задачи ради одного названия. Название — редакторское свойство: молчание
источника означает «нечего сказать», а не «стереть».

Без этой защиты ближайшее переиздание курса обнулило бы весь бэкфилл: UPDATE в
`bulk_upsert` перезаписывает `task_content` целиком, а конвейер шлёт `title=""`.

## Проверка качества генерации

Пробный прогон на курсе 863 «Занятие 2. Ввод и вычисления» — те самые 14 заданий
с одинаковым началом условия:

| Задание | Было в списке | Стало |
|---|---|---|
| #5550 | Исходный код для этого задания: print(17 // 5)… | Целая часть деления 17 на 5 |
| #5551 | Исходный код для этого задания: print(17 % 5)… | Остаток от деления 17 на 5 |
| #5552 | Исходный код для этого задания: print(10 / 4)… | Деление 10 на 4 |
| #5556 | Исходный код для этого задания: a = input(…)… | Сложение строк вместо чисел |

Два дефекта найдены и закрыты прямо в прогоне:

1. **Одинаковые названия у разных заданий** (#5548 и #5554 → «Преобразование
   текста в число»). Модель видит только свой пакет из 8, совпадения возникают
   на границе пакетов. Добавлен второй проход: совпавшие задания уходят в модель
   одним пакетом с требованием их развести; неразведённое попадает в отчёт на
   вычитку, а не подменяется наугад.
2. **Перекос в сторону чисел** («Округление 10 делить 3» вместо «Округление
   числа до двух знаков») — требование «различай числами» пересилило смысл.
   Формулировка поправлена: сперва смысл, различающая деталь — только когда
   иначе не отличить.

## Риски и follow-ups

- **Вычитка названий** — методистом, по JSONL `reviews/evidence/2026-08-14-tsk612-task-titles.jsonl`
  и по совпадениям, которые печатает скрипт. До вычитки названия уже работают.
- **1027 неактивных заданий** остаются без названия сознательно (решение по охвату).
  При включении такого задания название придётся завести отдельно.
- **Курс 561 «Архив: контент Виктора Комлева (legacy)»** активен и держит 193
  задания без названия — попадает в бэкфилл. Стоит проверить, должен ли архив
  быть активным (вне охвата tsk-612).
- **Мягкие переносы ЕГЭ** (`­`) снимает только `_stem_preview`;
  `humanize_task_title` их не знает, поэтому в очереди преподавателя и в поиске
  подпись из стема может рваться посреди слова. Существующее поведение, не
  регрессия — отдельная задача.
