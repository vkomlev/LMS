# tsk-699 — список заданий курса отдавал ученику все выключенные задания

**Дата:** 2026-08-26
**Скилл:** `/fastapi-api-developer`
**Файлы:** `app/api/v1/tasks_extra.py`, `tests/test_tasks_acl_post_s5.py`

## Что было

`GET /api/v1/tasks/by-course/{course_id}` принимает `is_active` со смыслом
«по умолчанию (`null`) — все задания, и активные, и выключенные». Параметр
заводился под кабинет методиста (tsk-559), а ограничения для непривилегированного
вызывающего не появилось: ученик, имеющий доступ к курсу, одним запросом получал
стемы и варианты **всех** заданий курса, включая снятые с публикации.

Тот же класс, что закрытые сегодня tsk-695 (материал по прямой ссылке) и tsk-697
(задание по `GET /tasks/{id}` и `/tasks/by-external/{uid}`), только оптом: там
утекало одно задание, здесь — курс целиком. Хвост был прямо записан в tsk-697.

Прод, 26.08.2026 (MCP read-only): выключено **1220 заданий из 7629**; в курсе 138,
на котором ловили tsk-697, — **28 выключенных из 61**.

## Что сделано

Помощник `_active_filter_for` рядом с `_deny_if_inactive_for_student`
(`app/api/v1/tasks_extra.py`): непривилегированному вызывающему фильтр
принудительно `True`, привилегированному — как просил.

```python
if privileged:
    return requested
if requested is not True:
    logger.info("tsk-699: force is_active=true for student user_id=%s course_id=%s (requested=%s)", ...)
return True
```

`assert_course_access` уже возвращал признак `privileged` (используется рядом для
скрытия `solution_rules`, tsk-460) — новых обращений к базе правка не добавляет.

Явный `?is_active=false` от ученика тоже подменяется на `true`: иначе параметр
остался бы прямой дверью к выключенным. Ответ при этом честный (200 со списком
активных), а не 403 — по тому же соображению, что и 404 в tsk-697: разница в
поведении сама по себе рассказывала бы о наличии скрытого среза.

Фильтр применяется **в SQL** (`tasks_service.get_by_course`, `filters` до
`limit/offset`), а не постфильтром поверх страницы — пагинация не теряет строки.

Заодно уточнено описание параметра в OpenAPI.

## Проверка потребителей (до правки)

Оператор отдельно предупредил: экран программы курса в SPW может строить что-то
на выключенных элементах, и тогда фильтр изменил бы вид экрана, а не только закрыл
утечку. Инвентарь снят механически, из источника:

| Потребитель | Как ходит | Влияние правки |
|---|---|---|
| SPW, программа курса ученика (`lib/learning/use-course-syllabus.ts:124`, экран + лента) | cookie ученика | **нет** — см. разбор ниже |
| SPW, кабинет методиста (`lib/methodist/use-methodist-content.ts:95`) | cookie с ролью `methodist` | нет — `privileged=True` |
| ContentBackbone (`monolith/lms_client/client.py:180`, `get_tasks_by_course_paged`; переиздание, prune, content-lint, backfill'ы) | сервисный `X-API-Key` | нет — `is_service=True` |
| ТГ-боты TG_LMS (`list_by_course` в диалогах курса, статистики, заданий методиста) | единый сервисный `X-API-Key` на все 4 бота | нет — `is_service=True` |

**Почему экран программы курса не меняется.** Список item'ов ученику строит не
`by-course`, а `GET /me/courses/{id}/syllabus-states`, и он фильтрует выключенное
сам: `_SYLLABUS_TASKS_SQL` — `WHERE t.course_id = ANY(:tree_ids) AND t.is_active = true`
(`app/services/me_service.py:906-907`), материалы — так же (`:931-932`). `by-course`
служит там **справочником обогащения**: ответ раскладывается в `Map<task_id, TaskRead>`
и из него берутся `title`, `type`, `external_uid` для строк, уже отобранных
syllabus-states. У выключенных заданий совпадений в этой карте и так нет — они
просто занимали место в ответе (и в лимите `?limit=500`, из-за чего у больших
курсов активные задания за пределом страницы могли терять название; после правки
это чуть менее вероятно). Ни нумерация, ни прогресс на них не завязаны: прогресс
секции считается по `items` из syllabus-states (`aggregateProgress`).

Материалы того же экрана уже ходят с `?is_active=true` явно
(`use-course-syllabus.ts:141`) — то есть клиент этого поведения и ожидает.

## Тесты

`tests/test_tasks_acl_post_s5.py` — блок tsk-699, 6 сценариев:

- ученик, параметр не передан → выключенное задание не в списке, активное на месте;
- ученик, явный `?is_active=false` → выключенного нет, отдаются активные;
- ученик → `external_uid` выключенного задания не встречается в теле ответа вовсе;
- методист → без параметра оба задания, `is_active=false` — срез выключенных (tsk-559);
- сервисный ключ → оба задания (переиздание CB, ТГ-боты);
- преподаватель → оба задания (разбор сдачи по снятому заданию).
