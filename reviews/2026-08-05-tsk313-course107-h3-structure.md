# tsk-313: смысловая разметка подкурса 107 «Словари» — честный остаток

Дата: 2026-08-05. Продолжение tsk-414/tsk-313 (см.
[reviews/2026-07-26-tsk414-tsk313-course88-qa-fixes.md](2026-07-26-tsk414-tsk313-course88-qa-fixes.md)).
Платформенный CSS-фикс (`SPW/app/globals.css`, коммит `5b48ebb`) уже делает `h1-h6`/`ul`/`ol`
визуально выделенными во всех курсах. Эта сессия закрывает зафиксированный тогда честный
остаток: материалы, где смысловая подтема была подписана НЕ заголовком (`<strong>label:</strong>`
перед блоком, либо голый текст) или перечисление шло текстом без списка.

## Инвентарь (прочитан вручную, не regex)

Изначально в задаче перечислено 15 материалов: подкурс 107 «Словари» (247-256) + 208/229/240/276/277.
Каждый прочитан целиком через MCP `learn_prod_db` (read-only) и сверен с каноном
(`ContentBackbone/docs/wp-content-contract.md` + живой эталон курс 823 «Python для подростков»:
каждая смысловая подтема — `<h3>`, вложенная детализация — `<h4>`, перечисления — `<ul>`/`<ol>`).

**9 из 15 уже соответствуют канону, правка не нужна:**
- 276 «Функции для работы со списками» — уже 4 корректных `<h3>` в БД, полностью канон.
- 247/248/250/251/252/253/255 (курс 107) — материал = единственная подтема, совпадающая с
  заголовком материала, содержимое — уже `<ol>`/`<ul>` с примерами; доп. заголовок ничего не
  добавил бы, кроме дублирования заголовка страницы.
- 229 «Методы множеств» — плоский `<ol>` список методов без текстовых меток подтем (та же
  природа, что уже готовый 253 «Методы словарей»); группировка по смыслу (mutating/set-algebra/
  query) была бы **придуманной** структурой, не запросом самого текста — не тронуто.

## Протокол `/db-check`

`scripts/tsk313_course107_h3_structure.py` — по образцу `tsk414_material_content_fixes.py`.

1. **Read** — MCP `learn_prod_db` (read-only), полный текст всех 15 материалов прочитан и
   разобран вручную построчно.
2. **Dry-run** — `DBCHECK_OK=1 python scripts/tsk313_course107_h3_structure.py` (без `--apply`):
   все 6 fixer-функций прошли ассерты на уникальность старых подстрок и сохранность контента,
   транзакция откатилась намеренно (`RuntimeError("DRY-RUN")`).
3. **Apply** — `DBCHECK_OK=1 python scripts/tsk313_course107_h3_structure.py --apply`: транзакция
   закоммичена, для каждого материала верифицирована длина текста после `UPDATE` (совпала с
   ожидаемой).
4. **Независимая верификация** — отдельный read-only запрос MCP `learn_prod_db` после коммита
   подтвердил итоговый текст всех 6 материалов побайтово (заголовки на месте, весь код/примеры
   целы, дубль в 208 убран).

Каждый fixer защищён ассертами на точное количество вхождений старой подстроки (`count()==1`)
до замены — при расхождении (например, если параллельная правка контента изменит текст) скрипт
падает `AssertionError`, а не молча портит данные.
