# tsk-509 — экран управления тарифными группами и вариантами тарифа

Дата: 2026-08-01 · Проекты: SPW (только фронт) · Задача: tsk-509

## Контекст

Выделенный остаток tsk-505: девять адресов управления составом тарифов существовали
и были покрыты тестами, но вызвать их можно было только из API — завести группу или
вариант маркетолог не мог. Доработка сервера не потребовалась ни в чём.

## Два решения оператора

| Развилка | Решение | Почему так |
|---|---|---|
| Что делает «убрать вариант» | Гашение — основное действие, удаление насовсем — отдельное с подтверждением | По варианту считаются деньги 33 учеников; ошибка должна быть обратимой, но накопленный мусор всё же убираем |
| Правится ли ось варианта (частота / сегмент) | Нет, только пересоздать | Смена «2 занятия» на «1 занятие» тихо перенесла бы учеников между ценами. Правятся имя, цена, порядок |

## Что сделано

Отдельный экран `/marketer/pricing/groups`, а не блок на «Ценах»: там ежедневная работа
— поправить сумму, здесь редкая и опасная — поменять устройство расчёта. Кнопке «удалить
вариант» не место рядом с полем, которое правят каждую неделю.

- Заведение группы, переименование, правка пояснения (пустое поле стирает его, а не
  молча сохраняет старое), удаление.
- Добавление варианта: имя, цена в рублях, ось (ничем / частота / сегмент). Нечисловая
  частота не даёт нажать кнопку — такой вариант выпал бы из подбора, и группа перестала
  бы считаться.
- Гашение и возврат варианта в расчёт одним нажатием; удаление насовсем — с
  подтверждением и пояснением, что вернуть будет неоткуда.
- Каждая группа показывает, каким курсам назначена. Удаление используемой группы не
  предлагается вовсе: сервер его отклонит (409), и знать это нужно до нажатия.
- Группа без действующих вариантов прямо говорит, что цена по ней не посчитается.

## Дефекты, найденные и исправленные по ходу

1. **Группа объявлялась свободной до загрузки курсов.** Пустой список — это «ещё не
   знаем», а не «никому не назначена»; по нему открывалось удаление используемой
   группы. Теперь до загрузки показывается «Смотрим, кому назначена…», удаление закрыто.
   Закрыто тестом с задержанным запросом.
2. **«Добавить вариант» — подстрока кнопки «Добавить вариант в группу «X»».** Живой
   прогон открыл форму чужой группы. Тот же класс, что уже чинили для «Сохранить»:
   имя кнопки обязано называть объект и не быть подстрокой соседнего. Подписи полей
   повторялись во всех группах — доступное имя теперь называет группу.
3. **«2 раз(а) в неделю»** — скобочная заглушка вместо русского языка на экране, который
   читает человек. Склонение занятий вынесено в функцию и покрыто тестами.

## Живая проверка на проде

SPW `f300774`. Полный цикл под реальной сессией оператора, экран смотрел глазами:

| Шаг | Результат в БД |
|---|---|
| Завести группу «Проверка tsk-509» | `pricing_group` id=3 с пояснением |
| Добавить вариант «3 занятия», 7500 ₽, частота 3 | `price_minor=750000`, `match_kind=attendance_frequency`, `match_value=3` |
| Погасить вариант | `is_active=false` — строка на месте, не удалена |
| Вернуть в расчёт | `is_active=true` |
| Удалить вариант и группу | обе строки сняты |

**Тестовые данные сняты полностью:** 2 группы, 4 варианта, все действующие — исходное
состояние. Существующие группы на экране читаются верно: «2 занятия в неделю»,
«1 занятие в неделю», «сегмент: insider», у обеих — «Удалить нельзя: группа назначена
курсам».

## Решение

**ПРИНЯТО.** Развёрнуто и проверено на проде. Сервер не менялся — только фронт.
