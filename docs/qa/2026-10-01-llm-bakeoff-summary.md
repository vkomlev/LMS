## Почему прогон не «по умолчанию»

`llm_model_bakeoff.py` без `--models` гоняет `DEFAULT_CANDIDATES` — августовский список
(`grok-4.1-fast`, `deepseek-v3.2`, …), которого нет ни в одной боевой цепочке. Такой прогон
остановлен; вместо него — боевые цепочки + новинки через `--models` (отсюда `-partial` в
именах файлов).

## Предложения оператору (ничего не применено)

1. **Наставник:** убрать из головы `gemini-3-flash` и `glm-5.3` — прод-данные за две
   недели, не один прогон. Цепочка `openai/gpt-5.5 → anthropic/claude-sonnet-4.6` (или

   решение оператора, как и 16.09). Канон — `providers._DEFAULT_TUTOR_MODELS` (правка
   кода + выкат).
2. **Судья:** `google/gemini-3.7-flash` головой (на проде таймаутов вдвое меньше, чем у
   `luna`), `glm-5.3` вывести (44 % таймаутов):
   `LLM_JUDGE_MODELS=google/gemini-3.7-flash,google/gemini-3.6-flash,openai/gpt-5.6-luna,openai/gpt-5.6-sol`.
3. **Новинки в цепочки сразу не ставлю.** По `model-routing.md` («Проверка модели перед
   вводом в боевую цепочку») нужны: формат на двух непохожих образцах, проходы в разные
   часы, удержание роли и поддакивание на исторических диалогах
   (`scripts/tutor_replay_bakeoff.py`). Кандидаты на такую проверку: судья —
   `gemini-3.8-flash`, `deepseek-v4.1-flash`; наставник — `gpt-6.1-sol`.
4. **Баланс $1,40** — пополнить; при исчерпании начнутся отбои по резервации $0,05.

## Дефекты стенда, найденные прогоном

1. `DEFAULT_CANDIDATES` — августовский список; прогон «по умолчанию» меряет не боевые
   цепочки. Брать по умолчанию цепочки из кода/`.env` + флаг новинок.
2. Наставницкая ось даёт модели `max_tokens=700`, бой — 900 (`ai_tutor.py`). Думающие
   модели (`glm-5.3`, `glm-5.3-flash`, `deepseek-v4.1-flash`) тратят лимит на
   `reasoning_content` и отдают пустой `content` — стенд пишет «пустой ответ», хотя на
   коротком запросе они отвечают за 5–17 c. Вердикт этих трёх по наставнику —
   недостоверен. (На бою у `glm-5.3` при этом таймауты, а не пустые ответы.)
