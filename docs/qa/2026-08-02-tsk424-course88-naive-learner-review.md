## Портрет ЦА

Источник портрета: заявленная цель курса, переданная оператором в задаче + структура курса (10 тем: установка → первая программа → числа → строки → условия → циклы → списки → функции → множества → словари — классический курс подготовки к разделу программирования ЕГЭ по информатике).

- Возраст/класс: 10–11 класс, готовятся к сдаче ЕГЭ по информатике.
- Учебный контекст: выбрали Python как язык для задач ЕГЭ на программирование; курс — самостоятельная подготовка (`self_guided`), без обязательной привязки к очным занятиям.
- Успеваемость (пессимистичная калибровка): троечник-хорошист, который может путаться в синтаксисе, не удерживает длинную цепочку рассуждений без примера, забывает пройденное через 1-2 темы, если оно не напоминается.
- Мотивация: сдать экзамен, конкретная практическая цель — набрать баллы за задания на программирование, не «полюбить Python ради Python».

### Что уже умеет
- Базовую логику из курса информатики 8-9 класса (переменные, простая арифметика).
- Читать пошаговую инструкцию с примером кода и повторять её почти дословно.

### Что скорее всего не умеет
- Уверенно писать код с нуля без готового примера перед глазами.
- Держать в голове больше 2-3 новых понятий одновременно.
- Самостоятельно разбираться в синтаксисе, который просто назван, но не показан примером (критично для находки W1 ниже).

### Что мог забыть
- Точную разницу целочисленного/дробного деления между темами (Числа → далее).
- Синтаксис цикла `for`, если встретит отсылку к нему в теме «Списки» до собственно темы «Циклы» (в курсе порядок верный: Циклы идут раньше Списков, поэтому это не сработавший риск — см. ниже).

### Словарь и абстракции
- Простые слова: переменная, число, строка, список — уже понятны из школьной информатики.
- Термины на грани: «итерируемый объект», «хешируемый», «распаковка последовательностей», «стек вызовов» — требуют примера рядом (курс это в основном делает).

### Порог внимания и формат
- Выдерживает абзац-два текста + один пример кода подряд; длинные простыни без кода утомляют.
- Опоры, которые помогают: короткий пример кода сразу после определения, конкретные числа вместо абстрактных `x`/`y` (курс это делает почти везде).

## Корневые причины

### RC1. Термин назван, но не показан примером синтаксиса
Проявления: f-строки (материал 264) названы без единого примера кода.
5 Why:
1. Почему ученик спросил «а как писать f-строку»? — Материал упомянул термин в одном предложении и сразу перешёл к другому способу форматирования (`%`, `.format()`), не дав примера f-строки.
2. Почему материал так устроен? — Автор, судя по стилю, писал материал линейно как справочную статью и, видимо, планировал добавить пример f-строк, но не добавил.
3. Почему это не поймали раньше? — QA-письмо (tsk-414, класс E) это уже подметило 22 июля; фикс-сессия tsk-414 явно выбрала чинить только 2 других пункта класса E и оставила f-строки как честный незакрытый остаток (это видно в истории движения tsk-414 — статус не «all fixed», а частичный).
4. Почему остаток не подхватили сразу? — Не было отдельного тикета/чипа именно под этот пункт, а класс E не критичен по приоритету рядом с классом F/G/H.
5. Первопричина: точечный контент-пробел в одном материале, не системный процесс. Ответственный контур: `/digital-copywriter` (дописать 3-4 строки с примером `f"{name}"` в материал 264) или `/methodist` (если решат вообще убрать упоминание f-строк, раз задание уже принимает `.format()`).
Ответственный контур: `/digital-copywriter`.
Профилактика: при упоминании альтернативного синтаксиса в тексте — обязательный минимальный пример (правило уже есть в rubric.md К7, просто не применено здесь).

### RC2. WP-хвосты «Вопросы»/шоткоды не долистали до конца при переносе с сайта на LMS
Проявления: `[spoiler]`-тег (материал 236), «Вопросы»-блоки без автопроверки (материалы 290/294/295).
5 Why:
1. Почему ученик видит квадратные скобки / бесполезный вопрос без поля ответа? — Материал скопирован из WP-статьи почти дословно, включая служебную разметку сайта (шоткоды, риторические вопросы «для самопроверки»), которая на WP имела смысл (JS-плагин спойлера, читатель отвечает сам себе), а в LMS это либо не работает, либо не нужно.
2. Почему осталось именно здесь? — tsk-411 (2026-07-25) целенаправленно вычищал похожий класс артефактов («Задания для закрепления» + `blockquote class="check"` + `[spoiler]`-блок с решениями), но искал по конкретному маркеру этого блока — инлайновый одиночный `[spoiler]` вокруг вступительного абзаца (материал 236) и одиночные «Вопросы»-концовки (290/294/295) не совпадают с этим маркером и не были найдены тем прогоном.

4. Почему это не всплыло в tsk-313 (нормализация структуры)? — tsk-313 целилась в заголовки/списки/`<blockquote>`, а не в шоткоды/риторические вопросы — другой класс дефекта того же источника (ручной перенос с WP).

### RC3. Понятие подробно объяснено, но ни разу не отработано руками
Проявления: рекурсия (материал 222, курс 104) — единственный материал с иллюстрацией стека вызовов, но ни одно из 43 заданий темы «Функции» не требует написать рекурсивную функцию.
5 Why:
1. Почему ученик может спросить «зачем я это читал»? — Материал даёт полноценную теорию (базовый/рекурсивный случай, стек вызовов, факториал, Фибоначчи) с расчётом на то, что дальше это применится, но применения в заданиях нет.
2. Почему заданий на рекурсию нет? — Банк заданий темы «Функции» ориентирован на практические задачи ЕГЭ-стиля (параметры, `*args`/`**kwargs`, поиск делителей, шифр Цезаря), а рекурсия для типовых заданий ЕГЭ на Python не является обязательным приёмом (в самом экзамене рекурсивные задачи редки).
3. Почему тогда материал такой подробный? — Видимо, авторский выбор дать тему полнее, чем строго требует экзамен (общий кругозор), не подкрепив её практикой.
4. Почему это не поймали раньше? — Дефект не про корректность (ошибок в материале нет), а про полноту банка практики — не тот класс, что ловят QA-письма про баги; такие пробелы ловит именно методический аудит.
5. Первопричина: расширение теории без параллельного расширения банка заданий (нарушение гейта «глубина практики» из `assignment-rules.md` §3.4 — «приём изложен в материале, но нигде не применён»).
Ответственный контур: `/methodist` (добавить 2-3 задания на написание рекурсивной функции — например, рекурсивный факториал/сумма цифр числа — либо явно сократить материал до уровня «нужно только для общего кругозора»).
Профилактика: при добавлении нового материала-теории — сразу проверять гейт «каждый приём ⇒ ≥1 задание, где ученик его применяет руками» (уже прописан в `assignment-rules.md`, просто не был применён к этому материалу).

## Навигация и плавность

Курс — 10 плоских тем без вложенных подкурсов, без записей в `course_dependencies` (0 строк). Это значит:
- Порядок отображения задают `order_number` в `course_parents` (Установка → Первая программа → Числа → Строки → Условия → Циклы → Списки → Функции → Множества → Словари) — сама последовательность выстроена методически разумно (например, «Циклы» идут раньше «Списков», поэтому пример `for` в материале «Создание списков» не является форвард-референсом).
- Но отсутствие `course_dependencies` означает, что ничего технически не мешает ученику открыть, скажем, «Списки» до «Циклов» напрямую по ссылке/поиску — реального гейта прохождения нет, есть только порядковый номер в списке. Для дисциплинированного ученика, идущего по порядку, это не проблема; для того, кто скачет по темам, есть риск наткнуться на `for` до объяснения синтаксиса цикла. Этот пункт пересекается с экспертным ревью (критерий К9) — там расписан подробнее.
