# tsk-740: методы Полякова для задания 23 против нашего блока — разбор и предложения (30.09.2026)

Источник: kpolyakov.spb.ru/school/ege.htm, раздел «23: алгоритмы на графах» (22.09.2026):
`ege23.doc` (методичка, обновлена 28.09), `23data.zip` (1 файл), `23solve.zip`
(9 решений на Python). Скачано по разрешению оператора, лежит в скратчпаде сессии,
в LMS ничего не переносилось.

## Что у Полякова

**Банк** — 8 задач, все на **одном файле** — файле демоверсии ФИПИ (sha256 `b2075dc7…`,
тот же, что у нашего задания 10258). Меняется только вопрос:

| № | Вопрос | Ответ |
|---|---|---|
| 1 | кратчайший путь 1 → 100 (демо) | 10971 |
| 2 | … через вершину 4 | 16058 |
| 3 | … не через 633 | 11782 |
| 4 | … не через 173 и 633 | 16869 |
| 5 | сумма номеров промежуточных вершин кратчайшего пути | 4673 |
| 6 | … только по рёбрам длиной ≥ 1000 | 23814 |
| 7 | … не более чем из 6 рёбер | 20198 |
| 8 | сумма промежуточных вершин пути из п. 7 | 1368 |

**Все 8 ответов перепроверены независимо** (Дейкстра с кучей + отдельная динамика по
числу рёбер, скрипт `scratchpad/pol/verify.py`) — совпали 8 из 8.

**Методы:**
1. **Основной — рекурсия с запоминанием (`@cache`)**: «лучший путь из вершины = минимум
   по рёбрам (вес + лучший путь из соседа)». Функция — 7 строк, вся программа — 17.
   Все вариации делаются маленькой правкой той же функции: запрет вершины — одно
   условие; «через N» — два вызова и сумма; «не более N рёбер» — третий параметр;
   сам путь — функция возвращает ещё и список вершин.
2. **Второй — Беллман-Форд в упрощённом виде**: массив `dist` на 1001 элемент (номера
   вершин ≤ 1000, никакого пересчёта номеров), 1000 проходов по списку рёбер.

**Чего у Полякова нет:** **подсчёта путей** (второй вид вопроса по кодификатору) —
ни в методичке, ни в задачах. Дейкстры тоже нет.

**Дефекты у Полякова (для справки, не наши):** в методичке фрагмент
`if v1 not [155, 633] and …` не запускается (пропущено `in`; в файлах решений верно);
в шапке «время — 7 мин», у ФИПИ — 12.

## Что у нас (блок 1490–1494)

- Кратчайший путь — **Дейкстра с `heapq`** как основной метод (урок 3902, программа
  целиком в 3906, ~22 строки), Беллман-Форд и Флойд — как проверка (3903).
- Количество путей — **та же рекурсия с запоминанием**, что у Полякова, только со
  словарём `память` вместо `@cache`, + повторные проходы как проверка (3904),
  топологическая сортировка (3905).
- Банк: 39 заданий на **разных файлах**, но **только два голых вида вопроса** —
  «кратчайший путь A → B» и «сколько путей A → B». Вариаций (через/не через вершину,
  фильтр по весу, ограничение числа рёбер, вершины самого пути) **нет ни одной**.

## Проще ли его способ для ученика — да, по трём причинам

1. **Один шаблон на оба вида вопроса.** «Функция от вершины → ответ до финиша» с `min`
   даёт кратчайший путь, с `sum` — количество путей. У нас сейчас ученик учит два
   разных инструмента (Дейкстру и рекурсию), хотя второй покрывает оба вопроса.
2. **Инструмент уже знаком.** Запоминание через `functools` ученики курса 112 проходят
   раньше — в задании 16 (курс 144, позиция 17) и снова в 19–21 (курс 1464); там оно
   записано как `@lru_cache`, `@cache` — его короткая форма (уточнено при реализации). `heapq`, порядок в кортеже
   `(расстояние, вершина)` и отбрасывание устаревших записей появляются в блоке 23
   впервые — это три новых понятия ради одного вопроса.
3. **Вариации дёшевы.** В рекурсии ограничение пишется одной строкой прямо в том
   месте, где выбирается следующее ребро. В Дейкстре «не более N рёбер» и «вернуть
   сам путь» заметно сложнее.

Плюс: ловушка `KeyError` для финиша без исходящих рёбер (ошибка №2 в нашем уроке 3906)
в его шаблоне закрыта строкой `if start not in data`.

## Где его способ хуже — граница применимости

Рекурсия с запоминанием **верна только на ациклическом графе**. В демоверсии оба
вопроса про ациклический граф, но кодификатор для кратчайшего пути говорит просто «между
вершинами графа». Если в экзамене встретится граф с циклом, рекурсия зациклится, а
Дейкстра и Беллман-Форд — нет. Поэтому Дейкстру не выбрасываем: она становится
**вторым способом** с явным правилом «нет слова „ациклический“ в условии — Дейкстра».

Попутно: наше предупреждение про `RecursionError` (урок 3904) избыточно. В файле не
больше 200 строк, значит в пути не больше 200 рёбер и глубина рекурсии ≤ 201 при
пределе 1000. Строку `sys.setrecursionlimit` можно оставить как страховку, но пугать
не нужно.
