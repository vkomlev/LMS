## Вердикт

**ПОНЯТНО С ОГОВОРКАМИ для сегмента ЦА, который уже пишет на Python;
ФАКТИЧЕСКИ НЕ ПОНЯТНО начиная с задания 16 (order_number=17) для сегмента
ЦА, который Python не выбрал как основной трек.**

Коротко: темы №1-15 (пакеты 1-3, 18 из 28 листьев, теоретико-расчётная часть
курса) методически крепкие — пошаговые разборы, альтернативные инструменты
(Excel и Python бок о бок), реальные варианты КИМ. Но начиная с темы №16
(«Рекурсивные функции», это ПЕРВОЕ место во всей 26-шаговой прогрессии
курса, где решение требует читать/писать Python-код) и до конца курса
(№16-27, 10 из 28 листьев — больше трети курса) единственный активный
теоретический материал каждой темы даёт готовый Python-код без единого
объяснения синтаксиса, и ни разу до этого места (темы 1-15) синтаксис
Python не преподаётся вообще. Ни один из 5 независимых пакетных проходов
не нашёл явного P0 внутри своих тем (после обязательной верификации), но
этот межпакетный факт виден только на уровне всего дерева и по сути
эквивалентен блокеру для трети ЦА курса.

## Ключевая находка всего дерева (видна только при сведении 5 пакетов)

**Тема №16 (courses.id=144, order_number=17) — первая точка всей
26-шаговой прогрессии курса 112, где ученику НУЖНО читать/писать Python,
и до неё этому нигде не учат.**

Доказано структурно, а не предположено:
- `course_dependencies` внутри всего куста курса 112 пуст (0 строк) — порядок
  тем держится ТОЛЬКО на `order_number`/`order_position`, без принудительного
  гейта знаний.
- Темы order_number=2..16 (задания 1-15, пакеты 1-3) используют Python
  максимум как ОДИН ИЗ путей решения наравне с Excel/устным способом
  (пакеты 1, 2, 3 явно отмечают это как сильную сторону — UDL, несколько
  каналов). Ни один из этих 15 материалов не объясняет базовый синтаксис
  Python (функции, циклы, списки) как учебную цель.
- Тема order_number=17 (задание 16, «Рекурсивные функции», courses.id=144) —
  первый материал куста, где Python — ЕДИНСТВЕННЫЙ путь, и он сразу
  требует понятия «рекурсия», без объяснения даже того, что такое функция
  и как её вызвать. То же самое повторяется в order_number=18-20 (задания
  17, 18, 19-21 — файлы+генераторы списков, 2D-массивы, декоратор
  `@lru_cache`).
- Пакет 5 (задания 22-27, order_number=21-26) не переоткрывает эту находку
  как новую — потому что ученик, дошедший до этих тем, уже «пробил стену»
  в пакете 4; но пакет 5 подтверждает, что программирование остаётся
  безальтернативным каналом и там.

Портрет ЦА этого курса прямо называет часть аудитории «не выбравшей Python
как основной трек» — то есть создатели курса ЗНАЛИ про этот сегмент, но
не дали ему точки входа именно там, где она нужна впервые. Это не
локальный дефект одной темы, а разрыв между заявленной целью курса (весь
ЕГЭ, включая не-Python-учеников) и структурой прогрессии — виден только
при сравнении order_number=2..16 с order_number=17 одновременно, ни один
из пакетов 1-4 в одиночку не мог его сформулировать так (пакет 4 диагностировал
проблему внутри своих 4 тем, но подтверждение «а до этого нигде не учили»
требует видеть весь куст).

## Корневые причины (сквозные по всему дереву)

### RC1. Прогрессия курса собрана «по номеру задания КИМ», а не «по требуемому навыку»
Приоритет: эквивалент P0 (см. «Ключевая находка»).
5 Why:
1. Почему ученик без Python-опыта не может решить задание 16? — Материал
   темы даёт только готовый Python-код, без объяснения синтаксиса.
2. Почему до этой темы синтаксис не давали? — 15 предыдущих тем (задания
   1-15) построены вокруг расчётных/теоретических приёмов КИМ, где Python
   — опциональный альтернативный путь (наравне с Excel/устным способом), а
   не учебная цель.
3. Почему нет отдельного модуля «Python с нуля» между темой 15 и темой 16? —
   `order_number` в дереве курса 1:1 повторяет номер задания КИМ (2↔1,
   3↔2, ..., 17↔16), это структурное решение авторинга, а не педагогическая
   прогрессия навыков.
4. Почему конвейер импорта не закладывает эту связку? — Материалы кодоёмких
   тем 16-27, судя по `external_uid` (`wp:mat:komlev:...`) и стилю подачи,
   перенесены 1:1 из внешнего видео-курса/вебинара, рассчитанного на
   аудиторию, уже способную читать код по ходу разбора — тексту не
   пересобирали заново под ученика без такой базы.
5. **Первопричина.** Курс 112 — это библиотека-справочник «одна подтема на
   один номер задания КИМ» (не жёсткий линейный курс: `access_level=self_guided`,
   `course_dependencies` пуст), что нормально для темы 1-15, но ломается
   ровно там, где приёмы решения задания физически требуют нового навыка
   (программирование), а заявленная ЦА явно включает учеников без этого
   навыка.
Ответственный контур: `/methodist` (спроектировать явную точку входа —
отдельный модуль или встроенные вводные блоки) + `/digital-copywriter`
(написать сами объяснения синтаксиса).
Профилактика: чек-лист методиста для кодоёмких тем КИМ — «какой новый
навык программирования эта тема требует ВПЕРВЫЕ во всей прогрессии курса,
объяснён ли он до первого использования, есть ли путь без него».

### RC2. Подсказки и объяснения ответов не заполнялись при импорте банка заданий
Приоритет: P1 (системный, 5/5 пакетов).
Проявления: `hints_text` пуст на 100% проверенной выборки в каждом из 5
независимых пакетов (сотни заданий, разные темы, разные источники импорта —
kompege/sdamgia/kpolyakov/Крылов и т.п.), `explanation` вариантов SC — пустая
строка везде, где проверено.
5 Why: 1) Ученик, ответив неверно, не получает объяснения. 2) Потому что
поле физически пустое у всех проверенных заданий, без единого исключения.
3) Совпадение по всем 5 независимым пакетам, разным источникам импорта и
разным номерам КИМ говорит о том, что заполнение этого поля никогда не было
частью пайплайна генерации/импорта, а не о случайном пропуске. 4) Фокус
кампании 2026-07 (tsk-350..399) был на корректности САМОГО ответа, не на
наличии подсказки — поэтому класс не пойман раньше. 5) Первопричина: поле
`hints_text`/`explanation` существует в схеме, но не было частью
обязательных требований к импортируемому банку заданий.
Ответственный контур: `/methodist` (правило приёмки банка заданий).
Профилактика: чек-лист приёмки — «заполнен ли hints_text хотя бы для части
банка (не обязательно всех), не сливает ли он готовый ответ».

### RC3. «Кухонная раковина» — материал-донор не почищен после разрезания урока на LMS-узлы
Приоритет: P1 (повторяется как минимум в 3 из 5 пакетов).
Проявления: тема 156/материал 420 дублирует материалы 421-424 дословно
(пакет 1); тема 157/материал 427 частично дублирует теорию дочерней темы
165 (пакет 2); тема 163/материалы 374-375 дублируют код класса
`TuringMachine` (пакет 3).
Правило уже предвидено самим справочником skill'а (`rubric-and-report.md`):
«аудит считал урок целиком, а LMS показывает ученику отдельные
материалы... нужна проверка будущего разрезания перед публикацией» — но
чек-лист авторинга ещё не закрывает этот шаг практически, что подтверждено
находкой в 3 разных темах независимо.
Ответственный контур: `/methodist` (структура графа материалов) +
`/digital-copywriter` (сокращение текста-донора).
Профилактика: перед публикацией темы — текстовый diff между «родительским»
материалом и материалами, на которые его дробят.

### RC4. Деактивация материалов не различает ценность содержания
Приоритет: P1 (подтверждено в 3 из 5 пакетов, максимальный ущерб в пакете 5).
Проявления: пакет 3 — концептуальные материалы самопроверки деактивированы
одинаковым паттерном во всех 5 своих темах; пакет 4 — `required`, но
недостижимые (`is_active=false`) материалы-списки ссылок в 3 темах; пакет 5
— два ПОДЛИННО ЦЕННЫХ обучающих материала (408, 410) скрыты тем же
паттерном, что и малоценные списки ссылок в соседних темах.
5 Why: похоже на массовую операцию по формальному признаку («второй
текстовый материал темы» = устаревший), без построчного просмотра
содержимого каждого конкретного материала — из-за чего вместе с
малоценными списками ссылок под нож попал и подлинно ценный контент.
Ответственный контур: `/methodist` — перед любой массовой деактивацией
материалов сверять содержимое, не только позицию/заголовок.
Профилактика: чек-лист — «дублирует ли деактивируемый материал активную
"Теорию" дословно, или несёт уникальный контент» перед `is_active=false`.

## Визуалы (сквозной вывод)

- Рендер визуалов НЕ проверялся ни в одном из 5 пакетов — это read-only
  DB-ревью без браузерного доступа. Везде, где упомянуты визуалы, статус —
  «изображение/видео объявлено по ссылке, рендер не подтверждён», не
  дефект W6 сам по себе.
- Сильная сторона (пакеты 1, 2, 4, 5): скриншоты и ASCII-схемы стоят рядом
  с объясняемым шагом, а не только обложкой — там, где они есть.
- Системный пробел (пакет 3): 4 из 5 тем (системы счисления, логика, сети,
  объём информации) не имеют НИ ОДНОГО визуала в текстовом слое для
  абстрактных, пространственных по природе понятий (разряды числа, отрезки
