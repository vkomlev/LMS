# Еженедельный разбор трудных заданий

Процедура (tsk-773). Правило-триггер живёт в `~/.claude/CLAUDE.md` и ссылается сюда.

## Зачем

Дефект задания снаружи не виден: текст на месте, правило проверки есть, ответ формально
принимается — а решить нельзя. Такие задания всплывали, только когда ученик не выдерживал
и писал обращение:

* **tsk-770** — эталон равнялся длине *второго* по краткости пути. Ученик дважды ответил
  верно, дважды получил незачёт и написал: «там возможно ошибка».
* **tsk-772** — из условия пропал список птиц, без которого задача не решается вовсе.
  У другого задания за кавычку выпала точка предложения: ученик посчитал 41 символ вместо
  42, получил незачёт, исчерпал попытки и потратил заявку помощи.

Оба раза сигнал был в данных задолго до обращения: ученики не сдавали задание с первой
попытки. Смысл процедуры — читать этот сигнал раньше, чем о нём напишут.

## Когда

Еженедельно, по понедельникам. В начале любой сессии от понедельника агент смотрит дату
последнего разбора в реестре; если прошло ≥7 дней — одной строкой предлагает запустить.
Молча не запускает: разбор ручной и небыстрый.

## Отбор

```bash
python scripts/weekly_hard_tasks.py            # окно 7 дней
python scripts/weekly_hard_tasks.py --report   # + сохранить отчёт в docs/qa
```

Задание попадает в разбор, если за неделю **минимум два ученика не сдали его с первой
попытки** либо **по нему была заявка помощи** (решение оператора, tsk-773). Ручные отметки
преподавателя попыткой ученика не считаются.

Скрипт только читает боевую базу и делит находки на три потока.

## Поток 1. Впервые — проверяем корректность

Задания, которых ещё не было в реестре. Проверяем ровно четыре вещи:

1. **Полнота** — все ли данные на месте. Пропавший список, потерянная строка, отсутствующий
   файл-приложение. Приём: сверка с первоисточником, если он есть (у партий `oge:reshu`
   с 5-значным id в ключе это `inf-oge.sdamgia.ru/problem?id=<id>`).
2. **Корректность ответа** — пересчёт решателем, а не доверие эталону.
   `scripts/tsk772_solve_oge_batches.py` покрывает партии ОГЭ t1, t3, t5, t6, t8, t10.
3. **Однозначность** — нет ли второго верного ответа. Ученик, ответивший иначе и тоже
   верно, получит незачёт (так было с `СР` при эталоне `СЕД`).
4. **Полнота эталона** — принимает ли правило все написания, которые считает верными
   источник. Нормализация — только `trim` и `lower`: она **не приравнивает «ё» к «е»**,
   поэтому «Долгопёр» при эталоне «Долгопер» не засчитается.

Очевидные дефекты правятся сразу по протоколу `/db-check` (снимок до правки, транзакция,
поштучная верификация чтением из базы, живая проверка на проде).

## Поток 2. Повторно — вопрос к самому заданию

Задание уже разбирали, корректность подтверждена, а ученики снова спотыкаются. Значит
дело не в дефекте, а в задании: сложность не соответствует месту в курсе либо формулировка
понятна автору, но не ученику.

Это методическая работа: разбор через **`/methodist`**. Переписывание условия и смена
сложности — **решение оператора**, агент готовит предложение, а не правит молча. Цена
ошибки здесь выше, чем при исправлении эталона: испорченный текст увидят все ученики.

## Поток 3. Вводный курс — сигнал о ясности материала

Вопросы курса-онбординга (`lms:onboarding:*`) — это проверка понимания прочитанного.
Ошибка с первой попытки здесь **нормальна и дефектом не является**: ученик читает,
отвечает, ошибается, перечитывает. Но если неверно отвечает большинство (12 из 17), скорее
непонятен разъясняющий материал перед вопросом. Работа `/methodist` по тексту раздела,
а не проверка эталона.

## После разбора

Отметить рассмотренные, иначе в следующий понедельник они снова придут как «впервые»:

```bash
python scripts/weekly_hard_tasks.py --record 6551 6553 --verdict fixed --note "что решили"
```

Вердикты: `fixed` — нашли и починили дефект; `ok` — задание исправно, трудность настоящая;
`methodist` — отдано на методический пересмотр. История накапливается, а не затирается:
по ней и видно, что задание попало повторно.

Реестр — `docs/qa/weekly-hard-tasks-registry.json`, версионируется в git.

## Чего процедура не делает

* **Не считает трудность дефектом.** Задание может быть просто сложным — для того и поток
  «повторно», чтобы отличить дефект от честной сложности по второму попаданию.
* **Не покрывает задания, которые нельзя пересчитать.** Где нужен рисунок со схемой или
  файл из архива (ОГЭ t9, t11, t12), решателя нет и не будет — там только сверка
  с источником и живой прогон.
* **Не заменяет обращение ученика.** Обращение остаётся более быстрым и точным сигналом;
  процедура нужна для заданий, о которых промолчали.
