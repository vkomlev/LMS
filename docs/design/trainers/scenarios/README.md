Принципы, которые держат оба сценария:
- тренажёр снимает застревание. Ошибка бесплатна, и разбор объясняет **именно эту** ошибку: у каждого неверного варианта свой текст;
- ни один шаг не просит написать программу и не показывает готовое решение заданий узла (сверка — §4);
- шаг на 5–15 секунд, а ответ — промежуточное состояние («что в `i` сейчас?»). Поэтому списывать невыгодно (§B.3 отчёта);
- своё состояние: ученик сам печатает имя, город, уровень. Числа и тема зависят от зерна, и по ссылке «Вызвать друга» вариант повторяется.

## 1. Формат сценария `trainer-scenario/1`

Это развитие §D.4 отчёта. Ключи §D.4 (`slug`, `title`, `params`, `code`, `steps`, `kind`,
`options[].misconception`/`why`, `effect`, `store`, `reject`, `expect`, `diagnose`, `misconceptions`)
сохранены. Чего не хватало и что добавлено — в §1.8.

| Поле | Обяз. | Что это |

### 1.2 Параметры и зерно

`params` — **упорядоченный** список. Движок вытягивает значения генератором `mulberry32(seed)`
строго в порядке списка (как в прототипе), поэтому одно зерно даёт один вариант и в SPW, и в проверке.

| Вид | Пример | Значение |
|---|---|---|
| `pick` | `{"name":"variant","pick":["int","noint"]}` | случайный элемент. Если элемент — объект, его поля становятся отдельными именами (`theme` → `{v1}`, `{q1}`, …) |
| `int` | `{"name":"age","int":[11,17]}` | целое из отрезка, края входят |
| `expr` | `{"name":"n","expr":"i0+d*2"}` | вычисляется из уже вытянутых. Случайность не тратит |

### 1.3 Шаблоны, условия, разметка

- **Шаблон** `{…}` в любой строке: имя (`{name}`) или целочисленное выражение из имён, чисел и `+ - *` (`{a2i+1}`, `{e-dd}`).
  Имена берутся из параметров, из ответов ученика (`store`) и из витка цикла (§1.5).
  Других фигурных скобок в текстах нет. Если понадобятся — экранировать `{{`.
- **Условие** (`when`, `correct`, `if`): `имя` (истинно ли), `!имя`, `ключ=значение`, `ключ!=значение`;
  несколько условий через `&`. Значение — всё после первого `=` (`cmp=<=` значит «cmp равно `<=`»).
- **Выбор по условию.** Почти любое текстовое поле (`q`, `why`, `why_ok`, `expect`, `line`, `success`) может быть
  строкой или списком `[{"when": …, "text"|"value": …}, …]`: берётся первый подходящий, последний — без `when`.
- **Разметка текстов:** только `` `код` `` и `**жирный**`. HTML запрещён: тренажёр встраивается на чужие сайты.

### 1.4 Уровни

Общие поля: `id`, `title`, `kind`; для `stepper` ещё `code`, `code_key`, `steps`.

| `kind` | Как работает |
|---|---|
| `quotes_puzzle` | «Расставь кавычки» (уровень 1 интерпретатора). `items[]` — мини-задачи: `intro`, `lines`, `target`, `diagnose`, `success` |
| `stepper` | Код + «Память программы» + консоль + вопрос перед строкой. `code` — список строк или словарь «вариант → строки» с ключом выбора `code_key` (например `"variant"`) |

**`quotes_puzzle`.** Строка кода — список токенов: `{"var":"name"}` (имя слева от `=`, не нажимается),
`{"code":" = "}` (неизменяемый кусок), `{"word":"{name}","id":"w_value"}` (слово, на нём ставят и снимают кавычки).
Сначала все слова без кавычек. Запуск — мини-вычислитель, **не** интерпретатор Python:
слово в кавычках — текст; без кавычек из цифр — число; без кавычек и уже созданная переменная — её значение;
иначе — `NameError: name '<слово>' is not defined` на этой строке (выполнение останавливается).
`print` печатает аргументы через пробел. `diagnose` — правила по порядку, срабатывает первое:
`{"error":"NameError"}`, `{"quoted":"<id>"}`, `{"unquoted":"<id>"}`, `{}` (всё остальное).
В текстах доступны `{got}` (что напечаталось), `{target}`, `{err_name}`.
`success` может зависеть от раскладки: условие `quoted:<id>` (слово с этим `id` в кавычках). `hint` уровня — постоянная подсказка под задачей.
Условия `if` у `quotes_puzzle` — объект, а не строка из §1.3: так проще описать «какая ошибка запуска» и «какое слово в кавычках».
Все слова в задачах — из одного слова: фраза без кавычек дала бы `SyntaxError`, а не `NameError`, и мини-вычислитель это не моделирует.

### 1.5 Шаги

Общие поля шага:

| Поле | Обяз. | Что это |
|---|---|---|
| `id` | да | уникален в уровне. Уходит в событие `trainer_step` |
| `kind` | да | `choice` / `console` / `value` / `trace` |
| `line` | да | подсвеченная строка (1…), `null` — без подсветки; можно выбором по условию |
| `q` | да | вопрос |
| `placeholder` | нет | серый текст в поле ввода: подсказывает формат ответа («числа через пробел») |
| `variants` | нет | шаг только для этих значений `code_key` (`["noint"]`) |
| `code` | нет | свой листинг для этого шага (сломанные программы, карточки `range`) |
| `before` | нет | эффект **до** показа вопроса. `{"reset":true}` очищает память и консоль |
| `effect` | нет | эффект **после верного** ответа |
| `why_ok` | для `console`/`value` | разбор при верном ответе (у `choice` — `why` верного варианта) |

Эффекты: `console_wait` (мигающий ввод с подсказкой), `set` (переменная в «Память»: `var`, `value`, `type` = `int|str`;
можно списком с `when`), `print` (строка в консоль; с `when`), `print_range` (числа `range(...)` по строке),
`error` (строки ошибки красным), `runaway` (бесконечный цикл: печатает `print` `times` раз с ускорением,
потом кнопка `stop_button`; это анимация, код не выполняется).

**`choice`.** `options[]`: `text`, `correct` (`true` / условие, например `"variant=int"` или `"!cond"`),
`misconception` (у неверного обязателен), `why` (обязателен у каждого; строка или выбор по условию).
Варианты перемешиваются один раз на шаг. Неверный вариант после нажатия гаснет. Повторное нажатие на погасший вариант не считается.

**`console`.** Ученик печатает в консоль. Порядок проверки: `normalize` (`trim` — обрезать пробелы по краям; Python в `int()` их тоже не замечает) → `accept` (подошло — верно) → `reject[]` по порядку (первое подошедшее). Поля: `max_len` (≤ 64, бриф Р3), `accept` (регулярка верного ввода),
`reject[]` (по порядку: `match`, `when`, `misconception` **или** `neutral: true`, `why`, `crash` — строки
настоящей ошибки Python в консоль), `crash_note`. `store`: `key` — ответ как текст, `int_key` — он же целым числом.
`{answer}` — что ввёл ученик. Нейтральный отказ — не ошибка (ученик ничего не перепутал: так ведёт себя Python).

**`value`.** Поле ввода. `normalize`: `trim` (обрезать края), `collapse_spaces` (несколько пробелов → один),
`numbers` (ответ — список целых через пробел или запятую), `casefold` (без учёта регистра). Нормализация применяется и к ответу, и к `expect`/`equals`/`starts_with`. `expect`: шаблон, или `{"range":[a,b,шаг]}`,
или выбор по условию. Сначала сравнивается `expect`, потом `diagnose[]` по порядку:
`equals` (+ `ignore_case`), `starts_with`, `matches` (регулярка), `range`, `not_number`, `numbers_count_gt`;
у правила может быть `when`; правило даёт `misconception` или `neutral`. Если не подошло ничего — `fallback`.

**`trace`** — витки цикла, развёрнутые заранее из параметров (§D.4: «генерируются заранее»; код не выполняется).
- `loop`: `{"type":"while","var","start","cmp","limit","step"}` или `{"type":"for_range","var","start","stop","step"}`.
- `acc` (необязательно): `{"var":"s","init":0,"op":"add_var"}` — копилка `s = s + i`.
- `per_iteration[]` — шаблоны шагов на каждый виток; `iters`: `all` или `first`. Если шаг на этом витке
  не спрашивается, его `before`/`effect` всё равно применяются молча: память и консоль остаются верными.
- `on_exit[]` — шаги после последнего витка (`{"use":"cond"}` — тот же шаг проверки условия, теперь оно неверно).
- Имена витка: `{i}`, `{i_next}`, `{s}` (до строки), `{s_new}` (после), флаги `cond` (условие верно), `eq` (`i` равно границе).
- В событии `trainer_step` к `id` шага из `per_iteration` добавляется номер витка `iter` (1…): иначе время по виткам не разобрать.
- Имена после цикла (доступны следующим шагам уровня): `{i_final}`, `{s_final}`, `{last_printed}`, `{acc_history}` (копилка после каждого витка, через пробел).

### 1.6 Коды ошибок

`misconceptions.<код>`: `label` (строка карты ошибок в финале — для ученика), `level` (куда отправить на повтор),
`tutor_hint` (одна фраза для ИИ-наставника: бриф Р1 «ошибки тренажёра передаются наставнику»), `map_ref` (строка карты ошибок узла 106; только у интерпретатора).
Каждый неверный вариант, `reject` и `diagnose` ссылается на код из этого словаря. Каждый код используется хотя бы одним шагом — это проверяет `check_scenarios.py`.

### 1.7 Счёт и финал

`scoring.stars_per_level`: 0 ошибок → ★3, до 2 → ★2, больше → ★1 (как в прототипе); максимум — ★9.
`neutral_is_mistake: false`. `same_option_twice: "not_counted"` — повторный выбор того же неверного варианта ошибкой не считается (вариант и так гаснет). `finish`: заголовок, текст карточки, карта ошибок (разные пояснения вошедшему и гостю),
`retry_hint` с `{top_label}`/`{top_level}` (самая частая ошибка → её уровень), подписи кнопок.
«К заданиям урока» показывается только в курсе, «Записаться» — гостю и во встройке, «Встроить» — на витрине.

### 1.8 Что добавлено к §D.4 и зачем

| Расширение | Зачем |
|---|---|
| `schema` | версия для проверки схемы при публикации (бриф Р2) |
| `params` — упорядоченный список + `int`/`expr`, объекты в `pick` | одинаковый вариант по зерну в SPW и в проверке; темы кода |
| `levels[]` | в прототипе три уровня, в §D.4 — плоский `steps` |
| `kind: quotes_puzzle` | уровень «Кавычки» в §D.4 не описан |
| `kind: trace` (`loop`, `acc`, `per_iteration`, `iters`, `on_exit`) | §D.4 говорит «генерируются заранее по описанию», но описания нет |
| условия `when`/`correct` и выбор по условию | варианты кода (`int`/`noint`, `inside`/`after`), граница цикла |
| `before`, `variants`, шаговый `code`, `reset` | ожидание ввода до вопроса; шаги только одного варианта; «сломанные» программы |
| `reject[].neutral`, `crash`, `accept`, `max_len`, `store.int_key` | «живой» `ValueError` без штрафа; лимит ввода из брифа |
| `expect` как `range`, `normalize: numbers`, `not_number`, `numbers_count_gt` | ответы-списки чисел у циклов |
| `misconceptions.<код>` — объект вместо строки (`label`, `level`, `tutor_hint`, `map_ref`) | карта ошибок, повтор уровня, передача наставнику |
| `effect.runaway`, `print_range`, `error` | бесконечный цикл, вывод `range`, падение программы |
| разметка `` ` `` и `**` без HTML | встройка на чужие сайты |

Ключ §D.4 `diagnose[].equals` сохранён. `store.var`/`type` из §D.4 переехали в `effect.set`:
значение и тип часто известны только на следующем шаге (`l2_typeof`).

## 2. Карта «ошибка → шаг → разбор»

### 2.1 «Ты — интерпретатор» — против карты ошибок узла 106

Карта ошибок узла 106 (`plan-vstraivaniya.md` §4): аргумент · кавычки · input(подсказка) · ожидание ввода · int/float · IDLE.
**Все шесть пунктов покрыты**; `check_scenarios.py` проверяет, что каждый `map_ref` встречается.

| Пункт карты 106 | Код | Уровень · шаг | Неверный ответ → что говорит разбор |
|---|---|---|---|
| кавычки | `quotes` | L1 `q1_duty`, `q2_trap`, `q3_number` | без кавычек у текста → `NameError` в консоли, «слово без кавычек — имя переменной»; имя переменной в кавычках → «напечаталось само слово»; ловушка «напечатай слово city» → «правило не „всегда кавычки“, а „текст — в кавычках“»; число в кавычках → вывод тот же, но «теперь это текст» |
| кавычки | `quotes` | L2 `l1_type` | ввёл ответ в кавычках → «пользователь кавычки не печатает» |
| кавычки | `quotes` | L2 `l3_output`, `l4_output`, `l4_fix` | «Герой: hero» → «без кавычек — имя переменной»; кавычки в ответе → «в консоли кавычек нет»; `'input(...)'` → «станет просто текстом» |
| аргумент | `argument` | L2 `l3_args`, `l3_output` | «1 — всё в скобках» / «3 — запятая тоже» → «аргументы — значения через запятую»; напечатал только имя → «print печатает все аргументы» |
| аргумент | `print_args` | L2 `l3_output`, `l3_plus`, `l4_output` | «Герой:Зорро» → «print ставит пробел»; ждал пробел от `+` → «`+` склеивает как есть» |
| input(подсказка) | `input_prompt` | L2 `l1_predict`, `l2_typeof` | «сохранит текст вопроса» / «'Сколько ему лет? 5'» → «в скобках подсказка для человека, в переменную не попадает» |
| ожидание ввода | `input_wait` | L2 `l1_predict` (+ живой курсор в `l1_type`, `l2_type`) | «спросит и пойдёт дальше» → «input останавливает программу, это не зависание» |
| int/float | `types` | L2 `l1_typeof`, `l2_typeof`, `l4_output`, `l4_predict`, `l4_fix`, `l5_float`, `l3_plus` | «цифры станут числом» → «input всегда даёт текст»; склейка «61» вместо 7 → «склейки не будет: без `int()` текст с числом вообще не складывается (TypeError), а с `int()` — складывается»; без `int()` — **живой** `TypeError` и починка строки 2 |
| int/float | `int_float` | L2 `l5_float` (+ `l2_type`: живой `ValueError` на 2.5, нейтрально, без кода ошибки — это не ошибка ученика) | «какая строка примет 2.5» → `int()` упадёт, `float()` примет, `input()` оставит текст |
| IDLE | `idle` | L2 `l0_where` | «в Shell после `>>>`» / «Shell тоже сохраняет» → «Shell выполняет по строке; программу пишут в File → New File и запускают по F5» |

Уровень 3 («Цикл») — мостик к «Цикл-машине», как в прототипе. В карту 106 не входит: `assign_eq`, `loop_cond`, `loop_order`, `loop_after`.
Механики из §5 плана 106, которых нет в LMS и которые закрывает тренажёр: расстановка кавычек (L1), консоль с ожиданием ввода (`l1_type`, `l2_type`),
пошаговый прогон с панелью переменных (L2, L3), живая ошибка `2.5` в `int(input())` (`l2_type`). Клик по зоне IDLE и сортировку карточек
пилот не делает: IDLE закрыт выбором (`l0_where`), Парсонс — следующий тренажёр (бриф §5).

### 2.2 «Цикл-машина» — типичные ошибки курса 110

Источник ошибок: реальные неверные ответы на задание 212 (`mini-range-i-vyvod/README.md`), курс 110 — №1 по провалам (37, бриф tsk-572), прототип (уровень 3).

| Ошибка | Код | Уровень · шаг | Как ловится → разбор |
|---|---|---|---|
| граница `<` / `<=` | `loop_cond` | L1 `cond` (каждый виток и выход), `last` | при `i == n` и `<=` ответил «нет» → «меньше **или равно**»; при `<` ответил «да» → «строго меньше; число n так и не напечаталось»; последним назвал n при `<` → разбор |
| ошибка на единицу в `range` | `range_end` | L2 `r1_out`, `r2_out`, `r3_out`, `r_fix` | в списке есть правая граница → «правая граница не входит, даже если шаг попадает ровно в неё»; починка «до b включительно» → `range(a, b+1)` |
| начало `range` | `range_start` | L2 `r1_out`, `r2_out`, `r3_out`, `r_fix`; L3 `i_first` | `range(m)` начал с 1 → «с одним числом счёт с 0»; `range(a, b)` начал с 0 → «с нуля — только с одним числом» |
| шаг `range` | `range_step` | L2 `r3_out` | перечислил подряд → «третье число — шаг» |
| забытое изменение счётчика → бесконечный цикл | `counter_update` | L1 `i_next` (ответ «не изменится»), `broken`, `broken_var` | в консоли бежит одно и то же число, кнопка «Стоп (Ctrl+C)»; «ошибки нет — Python честно повторяет»; «какая переменная должна меняться» → `i`, а не `n` |
| порядок строк в теле | `loop_order` | L1 `out`, `i_next`, `last` | напечатал уже увеличенное `i` → «строка 5 ещё не выполнялась»; прибавил 1 вместо шага d → «прибавляем d» |
| `print` внутри / после цикла | `loop_body` | L1 `done`; L3 `con`, `final` | «Готово после каждого числа» → «повторяются только строки с отступом»; несколько чисел при `print` без отступа и одно при `print` с отступом → разбор по отступу |
| `s = i` вместо `s = s + i`; `s = 0` внутри цикла | `accum` | L3 `s_new`, `broken_set`, `broken_reset` | положил `i` вместо суммы → «к **старому** s прибавляем»; «что напечатает `s = i`» → последнее `i`; «`s = 0` в теле» → «копилка обнуляется каждый виток» |
| `=` и `==` | `assign_eq` | L1 `assign` | «проверит, равно ли» → «один знак — положить» |

Раскадровка уровней:

| Уровень | Код (зависит от зерна) | Шаги |
|---|---|---|
| L1 while: счётчик | `n = i0+2d`, `i = i0`, `while i {<,<=} n: print(i); i = i + d`, `print("Готово")`. `i0 ∈ {1,2,3}`, `d ∈ {2,3}` | создание `i` → на каждом витке «условие верно?» и «новое `i`?» (вывод — на первом витке) → выход: условие неверно → «последнее напечатанное число» → «сколько раз „Готово“» → сломанная машина без `i = i + d` → «какая переменная должна меняться». На каждом зерне `i` в какой-то момент становится **ровно равным** `n`: при `<` цикл на этом обрывается (2 витка), при `<=` делает ещё один виток (3 витка). Граница проверяется на каждом зерне |
| L2 for и range | `range(a, a+3)`, `a ∈ 2..5`; `range(m)`, `m ∈ {3,4}`; `range(c, c+3·dd, dd)`, `c ∈ {1,2}`, `dd ∈ {3,4}` — шаг попадает ровно в правую границу | три карточки «какие числа напечатает» → починка «от a до b включительно» |
| L3 копилка и отступ | `s = 0`, `for i in range(p, p+3): s = s + i`, `print(s)` с отступом или без (`pos`), `p ∈ {2,3,4}` | первое `i` → новое `s` на каждом витке → «что появилось в консоли на этом витке» (первый виток) → «что в итоге в консоли» → сломанные `s = i` и `s = 0` внутри |

### 5.1 Глазами отстающего ученика (10–17 лет, взрослый новичок)

- Каждый вопрос — одно действие: «выбери», «напечатай», «набери, как будет в консоли». Формат ответа назван в вопросе или в подсказке поля («числа через пробел», «новое значение s»).
- Слова: «переменная», «аргумент», «присваивание», «отступ» объясняются там же, где появляются («один знак `=` — положить значение»; «аргументы — значения в скобках через запятую»). Убраны из текстов ученика после проверки: «разделитель», «выражение», знак «≠». Слов «итерация», «трассировка», «конкатенация», «инкремент», «литерал» в текстах нет (проверено поиском по файлам). «Виток» — вместо «итерации».

- Неоднозначных вопросов «на какой строке» нет: строка подсвечена, спрашивается про её действие.
- Риск: `l0_where` про IDLE непонятен тем, кто пишет в онлайн-песочнице (узел 824). Для встройки вне 106 этот шаг можно выключить. Открытый вопрос — §6.

### 5.2 Глазами сеньора (техническая точность)

`check_scenarios.py` — **0 ошибок на 7961 проверке**: 3360 комбинаций параметров интерпретатора и 2304 цикл-машины (Python 3.11.17).

Проверено запуском python3:
- L1 «Кавычки»: для каждой задачи и **всех** 2³ раскладок кавычек мини-вычислитель из §1.4 даёт тот же вывод или тот же `NameError: name '…' is not defined`, что настоящий Python. У ловушки `q2_trap` ровно одно решение.
- L2: строка 3 печатает `<метка> <ответ>` через пробел; `"Герой:" + hero` печатает без пробела; у `print` в строке 3 ровно 2 аргумента (через `ast`); вариант `noint` падает с `TypeError: can only concatenate str (not "int") to str`; `2.5` в `int(input())` даёт `ValueError: invalid literal for int() with base 10: '2.5'`; из трёх вариантов `l4_fix` программу чинит только `int(input(...))`, а `input(int("…"))` даёт `ValueError` на подсказке; `float(input())` на 2.5 даёт `float 2.5`, `input()` — `str 2.5`.
- Пустой Enter: настоящий `input()` возвращает `''` и **не ждёт дальше**. Текст прототипа «программа всё ещё ждёт» был неверен — исправлен в `l1_type`. `int(" 7 ")`, `int("007")` и `int("1_4")` Python принимает. Поэтому ввод с `_` получает нейтральный отказ, а не выдуманный `ValueError`.
- Все циклы: витки, значения `i` и `s` на входе в тело сняты `sys.settrace` с настоящего запуска и совпадают с трассой движка (§1.5); вывод программ совпадает с `expect`; последнее напечатанное число и граница `<`/`<=` — на каждом зерне.
- Сломанный `while` без изменения счётчика за 1 с не завершается и печатает одно и то же число. Ctrl+C (SIGINT) останавливает его с `KeyboardInterrupt`.
- `range`: каждая карточка совпадает с выводом Python, из четырёх вариантов `r_fix` нужный диапазон печатает только верный. Сломанные `s = i` и `s = 0` в теле печатают последнее `i`.
- Формат: у каждого `choice` ровно один верный вариант на каждом зерне, тексты вариантов не совпадают, у каждого варианта есть разбор, у каждого неверного — код ошибки; ни один `diagnose` не совпадает с правильным ответом (кроме первого витка копилки, где `s = 0` и `s + i = i`: там первым проверяется `expect`); все шаблоны раскрываются.

**Независимое ревью** (отдельный агент, 29.10) подтвердило: все 6 пунктов карты 106 и все 5 ошибок циклов покрыты, готовых решений заданий 106 и 110 нет. Найдено и исправлено до коммита:
- **неверный факт** в `l4_output`: «так склеилось бы, если бы был текст». На деле `'5' + 1` даёт `TypeError` (проверено). Разбор переписан;
- `l3_plus`: обещание «ошибка на следующем шаге» в варианте `int` было ложным — теперь разбор зависит от варианта; «пробел ставит запятая» → «пробел ставит `print`»;
- `l2_type`: порядок `accept`/`reject` записан явно; ввод с пробелами по краям обрезается, а длинное целое (7+ цифр) получает нейтральный отказ вместо выдуманного `ValueError`;
- L3 копилки: добавлено «`s += i` — короткая запись `s = s + i`» (в заданиях 213/226/227 ученик увидит `+=`);
- `broken_var`: вопрос «какая переменная должна меняться» спорил с Python (цикл кончится и при уменьшении `n`) — переформулирован в «строку для какой переменной забыли»;
- `l3_output`/`l4_output`: регистр букв не считается ошибкой; ответ с верным началом и опечаткой в имени — нейтральный отказ, а не «print ставит пробел»;
- кавычки-ёлочки без хвостового пробела (`q1t`), подпись «Через год питомцу будет» (не повторяет вариант №16 дотренировки), нейтральные по роду формы, недостающие поля в README.

**Не проверено запуском:** поведение IDLE (`l0_where`: Shell выполняет строку сразу, File → New File, F5 = Run → Run Module, без `>>>` в окне файла) — в облаке нет `tkinter`/`idlelib`. Утверждения сверены с документацией IDLE и сформулированы осторожно («программа так не сохранится и целиком заново не запустится»).
Трассировка ошибки в консоли тренажёра упрощена: Python 3.11+ показывает ещё строку кода с `^^^`, тренажёр — только `Traceback`, файл, строку и последнюю строку. Последняя строка совпадает с Python дословно.

## 6. Открытые вопросы и что не вошло
