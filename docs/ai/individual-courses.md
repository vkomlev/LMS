# Индивидуальные курсы ученику (повторение, доработка)

Правило оператора (05.10.2026, tsk-1245): **индивидуальный курс закрывает прохождение
основных курсов ученика, пока не пройден целиком.**

## Как устроено
- Индивидуальный курс — отдельный корень (`courses`, `course_uid` вида `ind:...`), к нему
  подкурсами (`course_parents`) подключаются готовые темы банка. Задания и материалы не
  копируются: у темы просто появляется второй родитель.
- Ученик записывается на корень (`user_courses`; на подкурс триггер не даст).
- Замок — точечная зависимость `course_dependencies(основной_корень -> индивидуальный,
  auto_assign=false)` (tsk-231, фаза 6). Действует только на тех, кому индивидуальный курс
  доступен (дерево активных `user_courses`), остальных учеников основного курса не трогает.
- Где виден: «следующий шаг» движка (`resolve_next_item` → `blocked_dependency`) и
  оглавление основного курса в SPW («Сначала пройдите курс …» + ссылка).
  Прямые ссылки на задания (домашка со страницы занятий) остаются рабочими.
- Снимается сам, когда индивидуальный курс `COMPLETED`: последняя сдача каждого задания
  зачтена + все материалы пройдены (`compute_course_state`).
- Снять досрочно: деактивировать запись ученика на индивидуальный курс
  (`user_courses.is_active=false`) или удалить строку зависимости.

## Как выдать
`scripts/issue_individual_course.py` — одна транзакция, без `--apply` прогон с откатом:

```
python scripts/issue_individual_course.py --user 4569 --title "Повторение: ..." \
  --uid ind:tskNNNN-user4569-... --subcourses 863,867,864 [--block 88,112] --apply
```

Для уже выданного курса: `--user 4569 --course-id 2106 --block 88,112 --apply`.
По умолчанию `--block` = все активные корни ученика. Запись на прод — по протоколу
`/db-check` (префикс `DBCHECK_OK=1`). После — живая проверка в кабинете ученика
(ссылка входа из админки, встроенный браузер): курс в «Мои курсы», на основном курсе замок.
