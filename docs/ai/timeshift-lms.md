# Проверка тестов на протухание по календарю в LMS

Тест, чья фикстура задаёт дату константой, а проверяемый код берёт «сегодня» внутри
себя, зеленеет в день написания и краснеет через недели. Инструмент против этого
живёт в Root — `python -m tools.timeshift_pytest` (tsk-609): он прогоняет набор со
сдвинутым вперёд «сегодня», и корректный тест переживает любой сдвиг.

**Штатный плагин к LMS напрямую не применим.** Он подменяет `date`/`datetime` только
в пакетах `tools`, `bot`, `tests`. В LMS код лежит в `app`, а тестовые модули
импортируются верхним уровнем (`test_tsk741_homework`, а не `tests.test_...`: файла
`tests/__init__.py` нет). Прогон «как есть» не подменил бы ничего и был бы
ложно-зелёным.

## Как запускать

```bash
PYTHONPATH=scripts python -m pytest -p timeshift_lms --timeshift-days=180 tests/test_tsk741_homework.py -q
```

`scripts/timeshift_lms.py` — обёртка: она собирает список модулей по факту (`app.*`
плюс загруженные `test_*` и `conftest`) и передаёт его в `install_shift` из Root.
Серию горизонтов гоняют циклом по `--timeshift-days`; рабочий набор —
1, 3, 8, 15, 31, 60, 180, 400, 1000, 3650 дней плюс контрольный 0.

**Контрольный прогон на нуле обязателен.** Красный набор без сдвига означает, что
судить о календаре нельзя — сначала чинить.

## Две ловушки, каждая уже стоила ложной тревоги

**Путь к Root не должен оставаться в `sys.path`.** У Root есть свой пакет `tests`.
Пока каталог Root стоит первым в `sys.path`, `from tests.test_x import ...` внутри
тестов LMS резолвится в ЧУЖОЙ пакет. Это дало 19 «падений» на НУЛЕВОМ сдвиге —
диагноз «правка сломала дашборд» продержался бы ровно до попытки её откатить.
Обёртка добавляет путь только на время импорта и сразу убирает.

**Смешанные часы под сдвигом красные всегда — и это не дефект теста.** Подмена
двигает питоновское «сейчас», но `now()` на стороне PostgreSQL остаётся настоящим.
Тест, который вставляет строку через SQL `now() - interval '30 minutes'`, а соседнюю
через `datetime.now(UTC)`, под сдвигом разъезжается по времени сам с собой. Образец —
`tests/test_manual_grant_not_student_activity_tsk656.py`: занятие заводится SQL-часами,
сдача — питоновскими. На настоящей будущей дате обе стрелки идут вместе, поэтому такие
падения в счёт не берутся. Отличать по признаку: если в тесте есть и `now()` в SQL, и
`datetime.now` в Python — сперва смотреть сюда, а не в календарную привязку.
