# ADR-0004 — `GET /courses/by-code/{code}` без ACL: намеренный публичный резолвер

- **Статус:** Accepted (переподтверждено оператором 2026-08-01)
- **Дата решения:** 2026-07-15 (tsk-127), переподтверждено 2026-08-01 (tsk-461)
- **Задача:** tsk-127 (self-heal резолвер), tsk-461 (аудит гейтов, попутная находка tsk-433)
- **Связано:** [tsk-461](../../../../Root/tasks/tsk-461-lms-endpointy-bez-auth-gejta-check-task-task-results-by-pending-review-courses-by-code-bez-acl.md), tsk-460 (соседняя находка той же разведки — утечка `solution_rules`, закрыта ACL)

## Контекст

`GET /api/v1/courses/by-code/{code}` (`app/api/v1/courses_extra.py:151`) резолвит
курс по внешнему `course_uid` (например `COURSE-PY-01`) в `CourseRead`. Эндпоинт
требует аутентификацию (`Depends(get_current_user)` — cookie ученика ИЛИ
сервисный ключ), но **не проверяет**, зачислен ли вызывающий на курс или на его
родителя (нет `assert_course_access`).

Причина существования — tsk-127: SPW self-heal `CourseNotFoundResolver` вызывает
этот эндпоинт со студенческой cookie, чтобы превратить листовой `course_uid` в
числовой `id` (например, при переходе по ссылке на материал курса, на который
ученик ещё не зачислен явно, но виден в навигации). До введения этого эндпоинта
резолв шёл через легаси `get_db` (требует `?api_key=` в query) — из браузера
недоступно, ученик получал ложный «Курс не найден».

При аудите под tsk-433 (2026-07-29) находка была переоткрыта как потенциальный
пробел ACL (tsk-461): любой аутентифицированный пользователь, включая ученика,
не зачисленного на курс, может резолвить произвольный `course_uid` в его карточку.

## Решение

**Оставить без ACL.** Подтверждено оператором 2026-08-01 через явный вопрос
(AskUserQuestion, tsk-461) — это по-прежнему осознанный компромисс, а не
забытый обход.

Обоснование:
1. **Схема ответа безопасна.** `CourseRead` (`app/schemas/courses.py:142`) отдаёт
   только метаданные курса: `id`, `title`, `access_level`, `description`,
   `parent_course_ids`, `created_at`, `is_required`, `course_uid`,
   `is_public_demo`. Персональных данных, состава участников, `solution_rules`
   или содержимого заданий здесь нет — в отличие от tsk-460 (утечка
   `solution_rules` через `tasks_extra.py`), где ACL был обязателен.
2. **Функциональная необходимость.** SPW self-heal резолвер должен работать для
   произвольного `course_uid`, встреченного в навигации/ссылке, включая курсы,
   на которые ученик ещё не зачислен явно (например, курс виден как часть
   структуры, но зачисление триггерится позже). Требование `assert_course_access`
   сломало бы ровно тот сценарий, для которого эндпоинт создан.
3. **Прецедент.** `GET /courses/search` (`courses_extra.py:57`) и `GET /courses/{id}`
   отдают ту же схему `CourseRead` под более широким гейтом
   (`require_role("teacher","methodist","admin")`) — метаданные курса уже не
   считаются в проекте секретом первого порядка, вопрос был только в том, кто
   может их *искать/перечислять* массово, а не в том, можно ли резолвить один
   конкретный уже известный код.

## Альтернативы (отклонены)

- **`assert_course_access` перед резолвом** — ломает self-heal резолвер tsk-127
  для незачисленных курсов; потребовал бы отдельного публичного эндпоинта с той
  же семантикой, то есть просто переименовал бы проблему.
- **Отдельная урезанная схема (`CourseUidResolveRead`: только `id`+`course_uid`)**
  без `title`/`description` — рассматривалась, отклонена как избыточная
  инженерия ради поля, которое и так не секретно (см. п.3 выше).

## Последствия

- **+** Self-heal резолвер SPW (tsk-127) продолжает работать без регрессии.
- **+** Явно задокументированное решение — следующий аудит (как этот) не должен
  снова тратить цикл на вопрос «баг или фича».
- **−** Любой аутентифицированный пользователь может перебором `course_uid`
  построить список существующих кодов курсов и их title/description. Приемлемо:
  те же данные уже доступны через `require_role`-гейт `/courses/search` тем, у
  кого есть роль, а рядовой ученик не имеет практического способа перебора
  (нет доступа к списку кодов, кроме уже видимых ему в интерфейсе).
- **Follow-up:** если в `CourseRead` когда-либо добавится чувствительное поле —
  пересмотреть это решение (сейчас оно верно ровно для текущего состава схемы).
