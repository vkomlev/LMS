# Спек tsk-1147 — дашборд преподавателей у методиста

## Цель
Методист видит по каждому преподавателю за выбранный период три показателя работы с
заявками помощи: долю заявок, закрытых не с первого раза; время реакции; число
обработанных заявок — всё раздельно «на занятии / вне занятия», а число ещё и по способу
ответа (текст / голосом на занятии / видеоразбор / консультация в Телемосте).

## Факты прод-БД (28.09, read-only)
| | на занятии | вне занятия |
|---|---|---|
| заявок `manual_help`+`individual_review` | 183 | 88 |
| с текстовым ответом | 158 | 85 |
| закрыто без ответа | 25 | 3 |
| медиана реакции | 3,8 мин | 10,8 мин |
| 80-й процентиль | 11,2 мин | 675 мин |
| ≤ 10 мин | 142 (78 %) | 44 (50 %) |

- Колонки «когда взяли заявку» нет: `claimed_by` + `claim_expires_at`, момент взятия не
  хранится. Ответы — `help_request_replies.created_at`.
- `blocked_limit` (312, автозаявки при исчерпании попыток): закрывает преподаватель
  (303), медиана 1,4 мин, возвратов быть не может (лестница tsk-303 только у ручных).
- Телемост в ответах — 37 заявок `manual_help` (+1 `blocked_limit`), видео-ссылок 0.
- `webinar_link` у заявок пуст везде — ссылку кладут в текст ответа.

## Определения (решено)
**Когорта.** Заявки `request_type IN ('manual_help','individual_review')`, `created_at` в
периоде `[from, to)` по Москве. Хозяин заявки — то же выражение, что в `get_reopen_kpi`
(tsk-599): `COALESCE(последний возврат, closed_by, assigned_teacher_id)` — вынести в общий
SQL-фрагмент и вызвать из обоих мест, не копировать.
`blocked_limit` в показатели а–в НЕ входит (это снятие лимита, а не просьба ученика; на
долю возвратов и способ ответа не влияет); выводится справочным столбцом «снято лимитов».

**а) Не с первого раза** = заявок когорты с ≥1 строкой `help_request_reopens` / заявок
когорты. Совпадает с tsk-599 по построению (тот же запрос-источник). Доля `None` при
знаменателе < `MIN_REQUESTS_FOR_RATE` (10) → «мало данных».

**б) Время реакции** = `COALESCE(первый ответ, closed_at) − created_at`.
Обоснование: момент взятия не хранится, а начинать его хранить — значит получить
показатель только с даты выката и без истории; первый ответ — то, что ученик реально
видит; закрытие без ответа (25 из 183 на занятии — «голосом») — тоже реакция, без него
устная работа выглядела бы как «не ответил». Незакрытая без ответа заявка в медиану не
идёт, считается отдельно «ждут ответа».
Выводим медиану (минуты) и долю в пределах порога. Пороги раздельные, по факту:
**на занятии — 10 мин** (сейчас 78 %), **вне занятия — 2 ч** (сейчас ~75 %). Медиана
и доля — `None` при < 10 заявок в ячейке.

**«На занятии»** = `created_at` заявки попал в окно занятия, где был ученик:
`lesson_window_sql.in_lesson_sql('h.created_at', 'h.student_id')` — это и есть общий
предикат tsk-1111 (`homework_service._in_lesson_sql` — тонкая обёртка над ним, приватная;
вызываем публичный оригинал, не обёртку и не копию).

**в) Обработано** = заявок когорты, закрытых преподавателем (`closed_by` NOT NULL,
заявка сейчас закрыта), по хозяину, на занятии / вне. Разбивка по способу — по
**итоговому** способу заявки: тип последнего ответа; закрыта без ответа → `voice`.

## Тип ответа
- Колонка `help_request_replies.reply_kind varchar(16) NOT NULL DEFAULT 'text'`,
  CHECK `IN ('text','voice','video','telemost')`.
- «Голосом» (решено при реализации): строка ответа НЕ пишется. Закрытие
  преподавателем без ответа — или заметно (> 1 мин) позже последнего ответа, то есть
  после возврата, — считается «голосом» при подсчёте. Так история и новые данные идут
  одним правилом, а кнопки закрытия в SPW и боте не меняются; в форме «Голосом» без
  текста вызывает обычное закрытие. Можно выбрать `voice` и к текстовому ответу.
- Индивидуальный разбор (`individual_review`) закрывается системно после оценки ученика
  и строки ответа не оставляет: закрытый разбор без ответа = консультация в Телемосте.
- Автодогадка (одна функция на сервер, SPW и бот): `telemost.yandex` → `telemost`;
  youtube/youtu.be/rutube/vk video/vkvideo/disk.yandex/.mp4 → `video`; иначе `text`.
  Сервер применяет её, если клиент тип не прислал; клиент показывает предвыбор, правка —
  одно нажатие.
- История: размечается в самой миграции тем же правилом (регулярки PostgreSQL = Python = TS,
  тест на совпадение); выкат на прод — по протоколу `/db-check`, выборка до/после.
- Известная мелочь: `` в JS не считает кириллицу буквой — «файл.mp4это» клиент
  предвыберет как видео, сервер — как текст. Выбор клиента главнее, вреда нет.

## Границы
Входит: миграция, автодогадка, закрытие «голосом», API агрегатов
`GET /api/v1/teacher/help-requests/kpi/dashboard?date_from=&date_to=` (рядом со сводкой возвратов, та же проверка ролей), выбор типа в SPW и в боте
преподавателя, экран методиста (таблица преподавателей, период, «мало данных»).
Не входит: голосовые сообщения, хранение момента взятия, уведомления о просрочке,
графики динамики, показатели по методистам.

## Риски
| Риск | Мера |
|---|---|
| Хозяин считается иначе, чем в tsk-599 → цифры на двух экранах расходятся | общий SQL-фрагмент, тест на совпадение `reopen_rate` |
| Автодогадка разъезжается между клиентами | правило в LMS, клиенты шлют `null` = «пусть решит сервер»; предвыбор — зеркало с тестом на те же примеры |
| Старый клиент бота без поля | поле необязательное, дефолт — автодогадка |
| `in_lesson_sql` на 600 строк без индекса | замер EXPLAIN на проде до выката |
| Выкат чужой работы reset'ом | коммит pathspec, SPW в отдельном worktree |

## Критерии готовности
1. Миграция применена на проде, 271+ ответов размечены, распределение показано до/после.
2. Числа экрана за период 04.06–28.09 совпадают с прямым SQL по каждой ячейке.
3. `reopen_rate` нового эндпоинта = `get_reopen_kpi` для тех же параметров (тест).
4. В SPW и боте ответ со ссылкой Телемоста предвыбирает «консультация»; смена — одно нажатие; сохранённый тип виден в БД.
5. Закрытие «голосом» пишет строку `voice` и попадает в разбивку.
6. Ячейки с < 10 заявок показывают «мало данных».
7. `/review-gate` PASS, выкат, живая проверка экрана методиста и ответа преподавателя.
