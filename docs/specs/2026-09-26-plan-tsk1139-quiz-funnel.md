# План tsk-1139 (техника): квиз с развилкой → регистрация → демо + заявка → бот → пробное

Дата: 2026-09-26 · Скилл: `/change-plan-architect` · Статус: **ждёт утверждения оператора**
Источник решений: `Marketing/clients/it-school/strategy/2026-09-26-funnel-site-quiz-demo.md` §2, §4, §7.

## 0. Что уже есть (снято из кода 26.09)
- Квиз = курс `is_public_demo` + задания `SC_Qw/MC_Qw`; шкалы в `solution_rules`; итог = первое сработавшее
  `assignment_rule(trigger_event='quiz_scale')` → `target_course_uid` (`guest_quiz_service.py:286`). Порядок линейный.
- Гость = cookie `guest_session`; ответы в `guest_attempt`; при входе `attribute_guest_session` ставит `attributed_user_id`.
- Заявка квиза: `lead_magnet_service.upsert_lead`, канал `quiz`, дедуп по (сессия, квиз). Колонок UTM/страницы нет.
  При регистрации заявка **не создаётся и не привязывается** (`linked_student_id` только руками).
- SPW: `/quiz/[uid]`, итог → кнопка «Записаться в Telegram»; UTM и `?branch` не читаются; адрес возврата после входа —
  `rememberReturnPath` (localStorage, 1 ч). Самозапись — только ручная кнопка (`enroll-free`).
- Бот ученика: `/start` без разбора параметра; незнакомцу — только «заявка на доступ»; напоминания — циклы-опросчики
  (`poller.py`), отписки нет; `send_document` в общем коде есть.

## 1. Решение по развилке (п.1 задачи)
**Вариант Б — входной квиз + 4 квиза-ветки (отдельные курсы), без ветвления в движке.** Рекомендую.
- Входной квиз — курс с одним вопросом «для кого подбираем»; у каждого варианта в `task_content.options[].next_quiz_uid`.
  После ответа SPW переходит на `/quiz/{ветка}`; сессия гостя та же, метки сохраняются.
- `/quiz/{вход}?for=parent|ege|teen|adult` — ответ на развилку проставляется автоматически, сразу переход в ветку.
  Ссылка прямо на `/quiz/{ветка}` тоже работает.
- Почему не ветвление в движке: итог, рекомендация, замер `quiz-funnel` и импорт заданий уже работают «на курс»;
  ветка = курс даёт всё это бесплатно, контент-сессия импортирует ветки обычным `bulk-upsert`. Движок меняется в одном месте
  (опция с `next_quiz_uid`). Общая аналитика — группировка по входному квизу через метку `entry_uid` в сессии.
- Старый `wp:kviz-podbor-kursa` не трогаем: новый вход — новый `course_uid`.

## 2. Этапы

### Ф1. LMS: метки и развилка (миграция)
- `guest_session.attribution jsonb` — ставится один раз при создании сессии: `entry_uid, branch, page, referrer, utm_*`
  (белый список ключей, длины обрезаются). `POST /learning/guest/session` принимает `attribution?`.
- `leads.attribution jsonb` — копия меток сессии + `branch`, `consent`.
- Опция развилки: `next_quiz_uid` в ответе `GET /guest/quiz/{uid}` (только для опций, где задано).
- Итог квиза: новые поля `teaser` (часть видна гостю) и `full_available_after_login: bool`; сырые шкалы гостю
  у веток воронки не отдаём (только тизер) — признак `task_content.funnel=true` у курса-ветки / в опции.

### Ф2. LMS: регистрация из квиза → заявка + демо
- `POST /me/quiz-funnel/claim {quiz_uid}` (вызывает SPW после входа, идемпотентно):
  1) привязка гостевой сессии (есть — `attribute-guest`);
  2) `upsert_lead` канал `quiz`, `contact=email`, `linked_student_id=user`, `attribution` сессии, `source_detail=ветка`;
  3) рекомендация → если курс бесплатный — `enroll_self_free`; иначе ответ `demo_course_uid` (демо-темы tsk-1108);
  4) ответ: полный разбор (шкалы, рекомендация, куда вести).
- Родитель (ветка `parent`, либо «ребёнку до 14»): `consent: {kind:'parent_minor', text_version, at}` обязателен,
  иначе 422. **Текст согласия — `[уточнить у оператора]`**, до него ветка `parent` работает с выключенным
  рубильником `QUIZ_FUNNEL_PARENT_CONSENT_TEXT` пустым → claim для `parent` отдаёт 409 «регистрация недоступна»,
  кнопка на итоге ведёт на запись на пробное вместо регистрации.
- Токен для бота: в ответе claim и в итоге гостя — `bot_start = "q_" + <короткий токен>` (таблица `bot_lead_token`,
  32 симв., одноразовая привязка, без персональных данных в ссылке).

### Ф3. SPW
- `/quiz/[uid]`: читать `?for=` и UTM/`page`/`referrer` → передать в создание сессии; развилка → переход в ветку.
- Итог ветки: тизер + главная кнопка по ветке (§2.1 стратегии) «Получить полный разбор и демо» →
  `/auth/magic-link/request` с `rememberReturnPath('/quiz/{uid}/done')`; для `parent` — чекбокс согласия.
  Вторая кнопка «Получить PDF в Telegram» → `https://t.me/<бот>?start=q_<токен>`.
- `/quiz/[uid]/done` (авторизованная): зовёт `claim`, показывает полный разбор + «Открыть демо/курс».
- Живая проверка в браузере (dev, затем прод после выката).

### Ф4. Бот ученика: режим гостя/лида (TG_LMS, `/telegram-ux-flow-designer`)
- `/start q_<токен>` — разбирается **до** проверки роли; незнакомцу не показываем «заявку на доступ».
  LMS: `POST /integrations/bot-leads/start {tg_id, username, token}` → `{branch, pdf_url, trial_available}`;
  создаёт `bot_lead` (tg_id, guest_session, lead, branch, step, next_at, unsubscribed_at).
- Экран 1: PDF ветки (`send_document`) + две кнопки: «Записаться на пробное», «Канал и группа ВК» (просто ссылки,
  без проверки). Внизу «Не присылать напоминания».
- Напоминания: опросчик как `poller.py`, `GET /integrations/bot-leads/due` → отправка → `POST …/{id}/sent`.
  График: **+1 день (демо), +3 дня (пробное), +7 дней (последнее)**, затем стоп. Не шлём, если уже записан на пробное
  или отписался. Каждое сообщение — с кнопкой «Отписаться».
- «Записаться на пробное» → `POST /integrations/bot-leads/{id}/trial` → `upsert_lead` (та же заявка, `note` + отметка
  `trial_requested_at`, контакт — `@username`/tg_id). Выбор времени — вне объёма (менеджер связывается сам);
  можно позже подключить `GET /integrations/free-slots`.
- Если tg уже ученик — PDF выдаётся так же, меню ученика не ломается.

### Ф5. Замеры
- `GET /marketer/quiz-funnel?entry_uid=` — шаги: старт → итог → регистрация (сессия привязана) → первое решённое
  задание (после регистрации) → бот (`bot_lead`) → пробное (`trial_requested_at`) → оплата (платёж ученика
  после регистрации). Разрезы: ветка, `utm_source/campaign`, страница. Схема меток — одна, согласовать с tsk-1072
  (ключи: `utm_source, utm_medium, utm_campaign, utm_content, page, for`).

## 3. Контракт для контентной сессии (`campaigns/site-funnel-quiz/`)
- Каждая ветка — курс-квиз: `course_uid` `quiz-<ветка>`, задания `SC_Qw/MC_Qw` (≤8–10), шкалы в `solution_rules`,
  итоги = `assignment_rule quiz_scale` → курс рекомендации + `task_content.teaser` (коротко) и описание (полный разбор).
- Вход: `quiz-vhod`, один вопрос, 4 варианта с `next_quiz_uid` и кодом `for`.
- PDF: `pdf/<parent|ege|teen|adult>.pdf` → кладём в `/media/funnel/` LMS; путь в настройке ветки.
- Импорт — существующий `bulk-upsert` (через `/db-check` на проде).

## 4. Рубильники и выкат
- `QUIZ_FUNNEL_ENABLED=false` по умолчанию (claim, bot-leads, `?for=`); `QUIZ_FUNNEL_REMINDERS_ENABLED=false`.
  Включение — `.env` + рестарт, когда готов контент. Миграция Ф1 — через `/db-check`.
- Коммиты с неготовым согласием — `Hold-For-Operator: текст согласия родителя` только если рубильник не закрывает.
- Cross-project: `lms-api.md`, `lms-db-schema.md`, CHANGELOG в ContentBackbone.

## 5. Риски
- Персональные данные ребёнка: в гостевой сессии только ответы и метки, без контактов; контакт — от родителя с согласием.
- Спам в боте → жёсткий график 3 сообщения и отписка.
- Два лида на человека (форма на итоге + claim) → дедуп по (сессия, квиз) уже есть, claim дополняет ту же запись.
