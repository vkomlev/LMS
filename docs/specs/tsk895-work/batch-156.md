## Открытые вопросы (требуют решения оператора/методиста, не вычислительные)

1. **id=2151 и id=3289** — оба условия говорят "Повторяется пункт 2" / "Предыдущий пункт
   повторяется" без указания числа повторений. Иллюстративных примеров с рассчитанным R
   нет ни в одном из двух условий, поэтому обычный анкор "воспроизвести пример" не сработал.
   Вместо этого я перебрал варианты 1/2/3/4 повторений для каждого задания по отдельности —
   совпадение с эталоном БД наступает **только при 2 суммарных выполнениях шага** и сразу в
   обоих заданиях. Это сильный, но не стопроцентный сигнал (совпадение с эталоном подтверждает
   интерпретацию, а не доказывает её единственную корректность лингвистически). Если этот
   тип заданий встретится где-то ещё в банке — стоит явно дописать в условие "повторяется
   один раз" вместо текущей обтекаемой фразы, чтобы не полагаться на реверс-инжиниринг.
2. **id=2156** — в тексте условия отсутствует "Например..." блок, который есть у всех
   остальных заданий такого типа в этом наборе. Трактовка (см. таблицу) дала численное
   совпадение с эталоном, но это единственное задание из 34, где нет прямой текстовой
   проверки моего понимания алгоритма — при следующей методической правке этого задания
   стоит добавить иллюстративный пример в стем, как у остальных.
3. **id=4820, id=4821** — это вспомогательные (THEORY) задания-шаблоны без конкретных данных
   ("Дана строка S...") — по конструкции не имеют единственного числового ответа, эталона в
   БД нет (`manual_review_required=true`). Это не расхождение, а особенность типа задания;
   упоминаю, чтобы не выглядело как "забытые" строки.
