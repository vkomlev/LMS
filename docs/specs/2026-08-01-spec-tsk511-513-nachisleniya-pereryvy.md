# Спека tsk-511 / tsk-512 / tsk-513 — помесячные начисления, автопересчёт, перерывы

Дата: 2026-08-01 · Проекты: LMS + SPW · Основание: три пункта оператора от 2026-08-01

## Зачем

Сейчас цена считается «на лету»: каждый запрос заново читает расписание. Поэтому
пункт «автопересчёт при смене расписания» в буквальном смысле уже работает — и ровно
поэтому ему негде проявиться. Ни перерыву, ни ручной цене, ни истории «сколько
насчитали за июль» жить негде. Всё три пункта упираются в одну недостающую сущность —
**начисление за месяц**.

Граница с tsk-010: здесь считаем **сколько ученик должен**. Как он это заплатил (чек,
шлюз, подтверждение) — остаётся в tsk-010 и здесь не делается.

## Решения оператора (2026-08-01)

| Развилка | Решение |
|---|---|
| Где живёт сумма за месяц | Помесячное начисление; пока месяц открыт — пересчитывается само, закрытый больше не меняется |
| Закрытый месяц оказался неверен | **Не переписываем.** Расхождение переносится поправкой в следующий открытый месяц. В обычном случае пропуск отмечают до оплаты, и начисление сразу верное |
| Ручная цена против автопересчёта | Ручная держится, экран показывает расхождение с расчётом и даёт вернуться к расчёту одним нажатием |
| Как перерыв влияет на сумму | По числу пропущенных занятий |
| Перерыв и расписание | Гасит занятия ученика и влияет на цену |

## Ключевое ограничение, найденное в живых данных

Занятия (`lesson_occurrence`) сгенерированы только на 2026-07-26 … 2026-08-14 — около
трёх недель вперёд, 38 строк. **Считать долю перерыва по сгенерированным занятиям
нельзя:** за август их существует лишь половина, и сумма зависела бы от того, когда в
последний раз крутили генератор.

Поэтому база месяца берётся из **постоянного расписания**: активные слоты ученика
(`lesson_slot_student` + `lesson_slot.weekday`) проецируются на календарный месяц.
Число занятий месяца — сколько дат месяца попадает на дни недели слотов ученика.
Результат не зависит от горизонта генерации.

## Модель данных

**`student_break`** — перерыв ученика (кабинет методиста).
`id, student_id, starts_on, ends_on, note, created_by, created_at, updated_at`
`CHECK (ends_on >= starts_on)`. Границы включительные.

**`student_price_override`** — ручная цена (кабинет маркетолога).
`id, student_id, group_id, price_minor, note, created_by, created_at, updated_at`
`UNIQUE (student_id, group_id)`. Снимается удалением строки — «вернуться к расчёту».

**`student_monthly_charge`** — начисление за месяц.
`id, student_id, group_id, period (первое число месяца), calculated_minor,
manual_minor NULL, expected_lessons, break_lessons, status ('open'|'closed'),
closed_at, closed_by, created_at, updated_at`
`UNIQUE (student_id, group_id, period)`

**`charge_adjustment`** — поправка к месяцу (перенос с прошлого либо ручная).
`id, student_id, group_id, period, amount_minor (со знаком), reason,
source ('carry_forward'|'manual'), origin_period NULL, created_by, created_at`
`UNIQUE (student_id, group_id, period, origin_period) WHERE source='carry_forward'` —
перенос из одного и того же месяца не задваивается при повторном пересчёте.

**Итог месяца** = `COALESCE(manual_minor, calculated_minor) + сумма поправок`.

Плюс расширение `CHECK` на `lesson_occurrence_participant.status` значением `on_break`.
Существующие значения не трогаются, расширение CHECK безопасно.

## Расчёт

1. Базовая цена группы — как сейчас (`_resolve_group_price`): точное попадание по
   частоте, ближайший меньший, сегмент, ручной выбор.
2. `expected_lessons` — дат месяца, попадающих на дни недели активных слотов ученика.
3. `break_lessons` — из них попадающих внутрь любого перерыва.
4. `calculated_minor = base * (expected - break) / expected`, округление до копеек.
   При `expected = 0` доля не применяется: делить не на что, берётся базовая цена
   (а её у такого ученика обычно и нет — там ручная).
5. Ручная цена группы (`student_price_override`) подменяет базу и **не пропорционируется**:
   договорённость с человеком не должна тихо уезжать от перерыва.

## Пересчёт

Открытые месяцы пересчитываются при: смене расписания, заведении/правке/снятии
перерыва, смене тарифа или цены, изменении ручной цены. Закрытый месяц не трогается:
если его пересчёт даёт другое число, разница пишется поправкой `carry_forward` в
следующий открытый месяц с указанием, из какого месяца она пришла.

## Что входит

- LMS: миграция, сервисы перерывов и начислений, пересчёт, API методиста (перерывы) и
  маркетолога (начисления, ручная цена, закрытие месяца).
- SPW: экран «Начисления» в кабинете маркетолога (сумма, из чего сложилась, ручная
  цена, расхождение, закрытие месяца); перерывы в кабинете методиста.

## Что НЕ входит

Приём платежей, чеки, шлюз, очередь подтверждения (tsk-010). Разовая оплата за курс
целиком. Автоматическое закрытие месяца по расписанию — закрывает человек.

## Критерии готовности

1. Перерыв на 2 недели у ученика с 2 занятиями в неделю при цене 5500 даёт ≈2750 и
   показывает, из чего это сложилось.
2. Занятия ученика в дни перерыва гаснут (`on_break`), снятие перерыва их возвращает;
   прошедшие отметки (`confirmed`, `no_show`) не трогаются.
3. Смена расписания 1→2 занятия меняет сумму открытого месяца без ручных действий.
4. Закрытый месяц не меняется; расхождение приходит поправкой в следующий и не
   задваивается при повторном пересчёте.
5. Ручная цена держится при смене расписания, расхождение с расчётом видно на экране.
6. Гейты: перерывы — методист/админ, начисления — маркетолог/админ; сервисный ключ не
   проходит. Ученик своей суммы в этой задаче не видит.
7. `pytest`, `tsc`, `lint`, `vitest` зелёные; живая проверка на проде со снятием
   тестовых данных.

## Риски

- **Округление.** Доля от 5500 при 9 занятиях в месяце не делится нацело. Округляем до
  копеек в меньшую сторону в пользу ученика и показываем, из чего сложилась сумма.
- **Двойной перенос.** Повторный пересчёт закрытого месяца не должен плодить поправки —
  защита частичным уникальным индексом по `origin_period`.
- **Гашение занятий необратимо по невнимательности.** Возвращаем только те, что сами и
  погасили (`on_break`), прошедшие отметки не трогаем.
- **Горизонт генерации.** База берётся из постоянного расписания, а не из занятий —
  см. раздел про ограничение.
