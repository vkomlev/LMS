# tsk-010 — выбор платёжного шлюза для самозанятого

Дата проверки источников: **2026-08-01**. Всё ниже — по официальным страницам
сервисов; там, где цифра не подтверждена, это сказано прямо.

Условия: физлицо со статусом самозанятого (НПД), онлайн-обучение, 35–45
учеников, помесячная подписка 2 750–20 000 ₽, оборот ≈150–200 тыс ₽/мес,
бэкенд FastAPI (нужен серверный приём уведомлений). Налоговые чеки оператор
выбивает сам в «Мой налог» — интеграция с ФНС не требуется.

## Кто отсеивается сразу

| Кандидат | Почему не подходит |
|---|---|
| Т-Банк (интернет-эквайринг) | Только ИП и юрлица; самозанятому-физлицу расчётный счёт не открыть |
| CloudPayments | Только ИП и юрлица |
| СБП напрямую | Приём C2B требует расчётного счёта. Перевод на личную карту возможен, но без API, уведомлений и привязки платежа к ученику — для бэкенда не вариант |
| lava.top | Нет чеков по 54-ФЗ, комиссия около 8% — вдвое дороже при большем риске |

## Сравнение прошедших отбор

| Критерий | ЮKassa | Robokassa | Продамус |
|---|---|---|---|
| Самозанятый без ИП | Да (паспорт + ИНН, договор онлайн) | Да (справка о постановке на учёт НПД) | Да (пока доход до 2,4 млн ₽/год) |
| Комиссия | 3,5% (акция 2,8% — только ИП и юрлицам) | Карты 3,4–3,9%, СБП 3,0–3,5% | 3,8%, подключение 0 ₽ |
| Регулярные списания | Есть, но в боевом магазине включает менеджер по запросу | Есть, включается отдельно | Есть, с управлением через API |
| Тестовый режим | **Сразу после регистрации, без документов и договора** | Есть (`IsTest=1`) | Есть (`demo_mode=1`) |
| Защита от повторов | Ключ идемпотентности, действует 24 ч; повторная доставка уведомлений 24 ч | Ключа нет (уникальность своим номером счёта); подпись + список адресов | Подпись HMAC-SHA256; про повторы и идемпотентность не нашёл |
| Python | Официальный SDK, документация на русском | Раздел в документации есть | Примеры только PHP и JavaScript |
| Вывод денег | До 2 рабочих дней; лимит приёма с карт 500 000 ₽/мес | Срок не нашёл | Не нашёл |

## Рекомендация — ЮKassa

Единственный вариант, где сошлись три критичные вещи: работа с самозанятым по
паспорту и ИНН, **тестовый режим до подписания договора** (разработку можно
начать сегодня) и официальный Python-SDK с русской документацией. Ключ
идемпотентности и повторная доставка уведомлений в течение суток закрывают
главную боль серверного приёма — двойное зачисление и потерянный платёж.
Разница в комиссии с ближайшим конкурентом при нашем обороте — около 200 ₽ в
месяц, выбирать по цене смысла нет.

**Главный риск — регулярные списания.** По умолчанию они работают только в
тестовом магазине; для боевого их включает менеджер по отдельному запросу.
Пока это не подтверждено письменно для аккаунта самозанятого, планировать
автосписание нельзя. Проверять это нужно до написания кода интеграции.
Запасной вариант при отказе — Robokassa либо счёт на оплату раз в месяц
вручную (ручной способ уже работает, см. tsk-010).

Второстепенное: акция со ставкой 2,8% на самозанятых не распространяется —
наша ставка 3,5%; лимит 500 000 ₽/мес по картам текущий оборот покрывает, но
при росте школы к нему стоит вернуться.

## Что нужно от оператора

1. Зарегистрировать аккаунт ЮKassa (личный вход, паспорт и ИНН, статус
   самозанятого активен в «Мой налог»). Договор подписывается онлайн.
2. Создать **тестовый** магазин и передать разработчику его `shopId` и
   секретный ключ. Боевые ключи на этом этапе не нужны и браться не должны.
3. Написать менеджеру ЮKassa про регулярные списания и получить письменное
   подтверждение, что их включат боевому магазину самозанятого. Это
   блокирующий шаг — делать параллельно с разработкой.
4. Подготовить сайт к проверке: оферта на обучение, описание услуги и цен,
   контакты, реквизиты. Образование — зона повышенного внимания модерации.
5. Указать карту или счёт для выплат.
6. **Не подключать «Чеки от ЮKassa»** — это +1% за каждый чек, а чеки
   выбиваются вручную в «Мой налог».

## Для старта разработки (тестовый режим)

Нужен только `shopId` и секретный ключ тестового магазина — документы и
договор для него не требуются. В тестовом режиме доступны платежи, возвраты,
уведомления и регулярные списания; альтернативные способы оплаты — нет.
У тестовых платежей стоит признак `test: true` — по нему в коде нужна явная
проверка, чтобы боевой контур не принял тестовую оплату за настоящую.
Отдельный адрес уведомлений для тестового магазина — прямая рекомендация
документации, смешивать с боевым нельзя.

## Что осталось непроверенным

- Комиссия ЮKassa по СБП для самозанятого — на странице «рассчитаем
  индивидуально».
- Ступени тарифа Robokassa для самозанятых: страницы тарифов и раздела для
  самозанятых дают разные цифры, даты обновления нет ни на одной.
- Повторная доставка уведомлений у Robokassa и Продамуса — в документации не
  описана.
- Сроки выплат у Robokassa и Продамуса.
