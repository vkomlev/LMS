# Контракт общего LLM-клиента LMS (`app/services/llm/`)

**Дата:** 2026-08-06 · **Статус: ПРИНЯТ — `spec-gate` пройден** (подтверждение чипа tsk-302 от 2026-08-06, см. §12.1)
**Этап 1 разблокирован:** можно начинать Фазу 2 (транспорт). Учесть два аддитивных
дополнения из §12.1 — опциональный `seed` в батч-режиме и признак `retryable` у ошибок.
**Этап:** 1 по [схеме оркестрации](2026-08-06-orkestraciya-tsk302-tsk572.md) · владелец — tsk-572
**Потребители:** tsk-572 (интерактив, стриминг) и tsk-302 (батч, JSON-судья)

> Контракт фиксируется **до написания кода** и обязан покрыть оба режима без переделки.
> Проектируется под требования tsk-572 (строго шире); батч-вызов на «стриминг-годном»
> клиенте делается тривиально, обратное неверно.

## 1. Зачем отдельный клиент, а не `cb_llm_client`

| Причина | Факт |
|---|---|
| Асинхронность | `cb_llm_client` синхронный (`requests`); LMS — async FastAPI. Прямой импорт заблокирует event loop |
| Стриминг | `cb_llm_client` не умеет вовсе (писался под батч). Для чата обязателен: без него p99 первого байта = p99 полного ответа |
| Расположение | Пакет лежит внутри репо ContentBackbone; его `pyproject.toml` прямо говорит «standalone — Фаза 2, при появлении consumer #2» |
| CB как сервис | Невозможно: пайплайны CB работают локально на машине оператора, прод-LMS до них не дотягивается |

**Переиспользуется:** сам провайдер (CloseRouter) и **канон имён env** (ADR-0046,
«connections shared, policy local»). Сведение двух транспортов в общий пакет — в TODOS,
не сейчас.

## 2. Структура модуля

```
app/services/llm/
  __init__.py      публичный фасад: complete(), stream()
  contracts.py     типы запроса/ответа/чанка, таксономия ошибок
  providers.py     резолв подключения по канону ADR-0046 + нормализация base_url
  client.py        транспорт на httpx (async), повторы, бюджеты
  cooldown.py      остывание провайдера после 429
  usage.py         учёт расхода
```

**Владение:** модуль принадлежит tsk-572. tsk-302 **потребляет, не правит**.

## 3. Резолв подключения

Канон ADR-0046, приоритет `<PROVIDER>_*` над legacy-алиасами:

| Что | Переменные (по приоритету) | Дефолт |
|---|---|---|
| base_url | `CLOSEROUTER_BASE_URL`, `CB_CLAUDE_BASE_URL` | `https://api.closerouter.dev` |
| ключ | `CLOSEROUTER_API_KEY`, `CB_CLAUDE_API_KEY` | — (без ключа провайдер `unusable`) |
| модель по умолчанию | `CLOSEROUTER_MODEL` | задаётся вызывающим явно |

**Нормализация `base_url` (гоча, найдена чипом tsk-302).** Клиент собирает путь как
`{base}/v1/chat/completions`. Если оператор задаст `...closerouter.dev/v1`, получится
`/v1/v1/...`. Правило: **срезать хвостовые `/` и хвостовой сегмент `/v1`** перед склейкой.
Тест обязателен на оба написания.

**Прод:** в `.env` LMS сейчас **ноль LLM-переменных** — ключ добавляется отдельным
операторским шагом. Сам CloseRouter с прод-сервера доступен (проверено SSH). Напоминание:
в прод-`.env` **только латиница** (кириллица уже ломала чтение настроек).

## 4. Публичный API

Два входа, один конвейер (резолв → остывание → вызов → учёт расхода → таксономия ошибок).

### 4.1. Батч — для tsk-302

```python
async def complete(
    messages: list[LLMMessage],
    *,
    model: str,
    temperature: float = 0.0,
    max_tokens: int = 1024,
    purpose: str,              # 'code_review' | 'tutor' | ... — идёт в учёт расхода
    student_id: int | None = None,
    budget: Budget = Budget.BATCH,
) -> LLMResult
```

`LLMResult`: `text`, `model`, `tokens_in`, `tokens_out`, `duration_ms`, `attempts`.
Разбор JSON — **на стороне потребителя** (клиент отдаёт текст, не парсит рубрику).

### 4.2. Интерактив — для tsk-572

```python
async def stream(
    messages: list[LLMMessage],
    *,
    model: str,
    temperature: float = 0.6,
    max_tokens: int = 1024,
    purpose: str,
    student_id: int | None = None,
    budget: Budget = Budget.INTERACTIVE,
) -> AsyncIterator[LLMChunk]
```

`LLMChunk`: `delta: str`, `done: bool`, и на финальном чанке — те же поля учёта, что
у `LLMResult`. Ошибка **до первого чанка** поднимается исключением; ошибка **после** —
финальный чанк с `done=True` и признаком неполноты (потребитель показывает обрыв
и кнопку «продолжить», а не ошибку).

## 5. Таксономия ошибок и политика повторов

Единая для обоих режимов. Все — наследники `LLMError`.

| Класс | Триггер | Повтор | Побочное действие |
|---|---|---|---|
| `LLMRateLimited` | HTTP 429 | **ЗАПРЕЩЁН** | Провайдер уходит в остывание (§7) |
| `LLMTimeout` | превышен бюджет | батч — 1; **интерактив — 0** | — |
| `LLMUnavailable` | сеть, DNS, TLS, HTTP 5xx | 1 с backoff | — |
| `LLMConfigError` | HTTP 401/403, 404-модель | **нет** | **Алерт персоналу** — это ошибка конфигурации, не ученика |
| `LLMMalformed` | нет `choices`, битый SSE | нет | Лог тела ответа |
| `LLMCooldown` | провайдер остывает | нет | Отказ сразу, без сетевого вызова |
| `LLMUpstreamError` | **`{"error":…}` внутри SSE при HTTP 200** | нет | Перейти к следующей модели цепочки (§6a) |
| `LLMQuotaExceeded` | `pre-consume quota failed` | нет | **Алерт персоналу** — деньги/квота ключа |

**КРИТИЧНО — ошибка приходит с HTTP 200 (проверено живьём 2026-08-06).** CloseRouter отдаёт
`Content-Type: text/event-stream`, статус 200, а внутри потока — `data: {"error":{...},
"status":502}`. Наивный клиент увидит «успех, ноль контента» и покажет ученику **пустой
ответ как нормальный**. Обязательно: проверять каждый SSE-кадр на ключ `error` и поднимать
`LLMUpstreamError`/`LLMQuotaExceeded` вместо тихого завершения потока.

Реальные тела, пойманные на стенде:
- `{"error":{"code":"upstream_error","message":"Model not found…","status":502,"metadata":{"provider_name":"Z.ai"}}}`
- `{"error":{"code":"upstream_error","message":"pre-consume quota failed, user remaing quota: $0.00045, required pre-consume quota: $0.002122","status":502,"metadata":{"provider_name":"Anthropic"}}}`

**Почему 429 нельзя ретраить:** повтор кормит брейкер провайдера. Брейкер CloseRouter уже
срабатывал (2026-07-05) от агрессивного цикла. Существующий `cb_llm_client` 4xx не
обрабатывает вовсе — то есть на 429 не реагирует ни ретраем, ни остыванием.

## 6. Бюджеты

| Бюджет | Соединение | Первый токен | Всего | Повтор таймаута |
|---|---|---|---|---|
| `Budget.INTERACTIVE` | 2 с | **5 с** | 20 с | 0 — ученик не ждёт второй круг |
| `Budget.BATCH` | 5 с | — | 60 с | 1 |

Бюджет — параметр вызова, не глобальная настройка: один и тот же клиент обслуживает оба
профиля одновременно.

## 6a. Политика моделей и цепочка отката

**Поправка к §9:** фолбэк между *провайдерами* по-прежнему не делаем (провайдер один), но
**фолбэк между моделями внутри CloseRouter — делаем**. Основание — не теория, а два живых
факта со стенда: модель может быть **в каталоге и при этом недоступна у upstream**
(`z-ai/glm-5.2` → «Model not found»), и модель может отбиваться по квоте ключа независимо от
своей работоспособности. Без цепочки любая из этих причин кладёт наставника целиком.

Цепочка — список слева направо, первая рабочая выигрывает. Переход к следующей **только** на
`LLMUpstreamError` / `LLMConfigError` (404-модель) / `LLMQuotaExceeded`. На `LLMRateLimited`
переход **не** делаем — это остывание провайдера, а не проблема модели.

**Переменные (политика локальная, канон ADR-0046):**

```
LLM_TUTOR_MODELS=<цепочка через запятую>   # интерактив, обязателен стриминг
LLM_JUDGE_MODELS=<цепочка через запятую>   # батч, обязателен response_format
LLM_COOLDOWN_SECONDS=120
```

## 7. Остывание провайдера

Получен 429 → провайдер помечается остывающим на `LLM_COOLDOWN_SECONDS` (дефолт 120).
Пока остывает — `complete`/`stream` поднимают `LLMCooldown` **сразу, без сетевого вызова**.

Состояние — в процессе приложения (не в БД): переживать перезапуск не требуется, а лишняя
запись в горячем пути не нужна. При нескольких воркерах остывание независимо у каждого —
приемлемо: цель не идеальная синхронизация, а не долбить провайдера всей толпой.

## 8. Учёт расхода

Таблица `llm_usage_event` — **с первого дня, лимиты не включаем**. Основа будущих подписных
тарифов и общий инструмент обеих задач.

| Поле | Смысл |
|---|---|
| `id`, `created_at` | |
| `purpose` | `'tutor'` \| `'code_review'` \| … — кто потратил |
| `student_id` (nullable) | для подписных лимитов; `null` для системных задач |
| `model`, `provider` | что реально вызвали |
| `tokens_in`, `tokens_out` | из `usage` ответа |
| `duration_ms`, `outcome` | `ok` \| класс ошибки |

Запись — **не в транзакции потребителя** (сбой учёта не должен ронять ни приём ответа
ученика, ни диалог). Ориентир масштаба: ~1500 вызовов/мес у tsk-302 + ~160 диалогов/мес
у tsk-572; при цене CloseRouter $0.20–0.30 за 1M токенов это единицы долларов.

## 9. Границы — чего клиент НЕ делает

- Не парсит предметные ответы (JSON-рубрику tsk-302 разбирает сам потребитель).
- Не знает про задания, учеников и педагогику — только транспорт и учёт.
- Не хранит историю диалога (это `ai_tutor_session`, зона tsk-572).
- Не включает лимиты и не режет по квоте (счётчик — да, политика — позже).
- Не резолвит второго провайдера/фолбэк — сознательно: пока наставник необязателен,
  деградация дешевле резервного провайдера.

## 11. Открытые вопросы и известные ограничения замера

**Квота ключа — снята частично (обновлено вечером 2026-08-06).** Оператор пополнил баланс,
стенд прогнан повторно (`scripts/llm_model_bakeoff.py`, 3×8 моделей). Что изменилось:

- дорогие модели **измерены**, и гипотеза подтвердилась: «364 c до первого токена» у
  `gpt-5.5` были отбоем по квоте, а не латентностью — честный замер дал **4.4 c**;
- `claude-sonnet-5` при этом **слил ответ** в 1 прогоне из 3 и дисквалифицирован, а
  `claude-opus-4.8` прошёл, но стримит грубее вдесятеро дешёвого `grok-4.1-fast`;
- **остаётся:** `claude-sonnet-4.5` и `deepseek-v3.2` по-прежнему не измерены — у **ключа**
  своя квота ($0.000004), отдельная от кредитов аккаунта ($7.04), и пополнение баланса её
  не подняло. Действие оператора: поднять лимит самого ключа в панели CloseRouter.
  До тех пор неизмеренные модели в цепочки не ставим.

Прочее:
- `LLM_COOLDOWN_SECONDS` = 120 — первое приближение, калибруется по реальным 429.
- Ограничение частоты на нашей стороне — не в первой версии (остывание закрывает главный
  риск); вернуться при росте нагрузки ×10.
- Полный прогон 9 регресс-сценариев (не одного злейшего) — Фаза 3 плана, приёмка оператором
  как Гейт 2 методики.

## 12. Что требуется от чипа tsk-302 для `spec-gate`

Подтвердить, что §4.1 (батч), §5 (таксономия), §8 (учёт расхода) покрывают нужды судьи
ИИ-авторства без доработок, либо назвать недостающее **до** начала Фазы 2.

### 12.1. Ответ чипа tsk-302 (2026-08-06) — ПОДТВЕРЖДАЮ, с двумя дополнениями

**§4.1 (батч) — покрывает.** Сверено с рабочим пилотом `scripts/tsk302_ai_detector_pilot.py`,
который уже отработал 50 реальных сдач: нужны ровно `messages` + `model` + `temperature=0.0`
+ `max_tokens` (хватает 300) + текстовый ответ на разбор своими силами. Разбор JSON-рубрики
на стороне потребителя — правильное решение: у судьи ответ приходит то чистым JSON, то
обёрнутым в ```json-забор, и снимать это должен тот, кто знает формат рубрики.

**§5 (таксономия) — покрывает.** Запрет ретрая на 429 и остывание — согласен, это ровно тот
риск, о котором предупреждает инцидент 2026-07-05.

**§8 (учёт расхода) — покрывает.** `purpose='code_review'` и порядок ~1500 вызовов/мес
совпадают с моей оценкой (при цене CloseRouter это единицы долларов в месяц).

**Дополнение 1 (нужно мне, просьба заложить в §4.1): опциональный `seed: int | None = None`.**
Пилот гоняет `seed=42` — при повторной калибровке рубрики на том же корпусе важно, чтобы
расхождение вердиктов означало изменение рубрики, а не дрожание модели. `temperature=0`
сам по себе полного детерминизма не даёт. Параметр опциональный, наставнику не мешает
(он его просто не передаёт).

**Дополнение 2 (нужно мне, просьба уточнить в §5): явный признак «повторяемо ли».**
Судья работает в фоновой очереди, и обработчику надо отличать «повторить в следующий заход»
(`LLMCooldown`, `LLMRateLimited`, `LLMTimeout`, `LLMUnavailable`) от «повторять бесполезно»
(`LLMConfigError`, `LLMMalformed`) — иначе фон будет либо долбить провайдера на неверном
ключе, либо навсегда терять оценку из-за разовой сетевой ошибки. Сейчас это выводимо из
класса ошибки, но выводить вручную в каждом потребителе — источник расхождений. Прошу
атрибут `retryable: bool` на `LLMError` (значение по классу, таблица §5 уже фактически его
