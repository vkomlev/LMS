## Целевая возможность

Момент провала перестаёт быть тупиком. Ученик, ошибшийся в задании, в ту же секунду получает
разговор о **своей конкретной ошибке**, ведущий к самостоятельному решению (уровень 0
лестницы помощи). Когда одно непонимание повторяется у нескольких учеников — система сама
поднимает методисту вопрос о мини-курсе (уровень 4), а не ждёт, пока преподаватель заметит.

**Не-цели (явно вне охвата):** детектор ИИ-авторства в живом потоке (tsk-302, этап 3);
гейт на подсказки; устная §64-защита; включение подписных лимитов (счётчик — да, лимиты —
нет); второй LLM-провайдер; сведение транспорта с `cb_llm_client`.

## Пробелы и недостающие ресурсы

**БЛОКИРУЮЩИЕ (без них фаза не стартует):**

1. **[БЛОКЕР процесса] Код занят чипом tsk-302 (этап 0).** Последовательный режим утверждён
   оператором. Пока этап 0 не закрыт — только документы. Снимается сигналом от чипа tsk-302.
2. **[БЛОКЕР Фазы 2] Контракт LLM-клиента не согласован.** `spec-gate` оркестрации требует
   согласия обеих задач до написания кода. Закрывается Фазой 1 (документ, делается сейчас).
3. **[БЛОКЕР прода] Ключ CloseRouter отсутствует в прод-`.env`.** Операторский шаг
   (категория Б — доступ к секретам). Только латиница (прецедент: кириллица уже ломала
   чтение настроек).
4. **[БЛОКЕР Фазы 3] Модель наставника не выбрана.** Кандидаты из флота: `openai/gpt-5.5`,
   `anthropic/claude-sonnet-5`. Решается **живым прогоном 9 регресс-сценариев**, не спором.

**Молчащие дефекты — закрыть структурно, не дисциплиной:**

5. **[КРИТ] Утечка эталона в промпт.** Не упадёт ни тестом, ни ошибкой. Фикс: тип
   `TutorTaskView` **физически без поля** `solution_rules` + тест-страж, валящий сборку при
   появлении текста эталона в готовом промпте.
6. **[КРИТ] Датчик пробела отравлен `manual_teacher`** (11 643 из 13 795 строк — ручная
   простановка с 0% ошибок). Наивный триггер разбавлен в 6 раз и **не сработает никогда,
   выглядя рабочим**. Фикс: одна именованная функция «реальные ученические сдачи»
   (`source_system='spw_web'`), через неё **все** аналитические пути + тест на смешанной
   фикстуре.

**Прочие:** 429 не ретраить (остывание провайдера); TTL висящих `open`-сессий; ответ ученика
в промпте — строго как данные в отдельной секции (он подставляется программно) + 9-й
регресс-сценарий сверх 8 из методики.

## Решение по дублированию

**Переиспользуем общий слой, второй транспорт не заводим.** `app/services/llm/*` пишется
один раз под требования tsk-572 (строго шире) и потребляется tsk-302 без переделки —
обратное неверно: батч-клиент пришлось бы переписывать под стриминг.

Осознанный остаточный долг: во флоте окажется два LLM-транспорта (`cb_llm_client` для
батчевых пайплайнов CB и `app/services/llm` для интерактива LMS). Сведение в общий пакет —
Фаза 2 ADR-0046, вынесено в TODOS, **не сейчас**: пока не ясно, что именно у интерактивного
и батчевого клиентов общего сверх резолва подключения.

## Этапы внедрения

### Фаза 0 — ожидание очереди (не моя работа)
Чип tsk-302 закрывает этап 0 (починка `metrics`, `ReviewClaimItem`, `ReviewGradePanel`,
деплой, живая проверка) и освобождает код. **Предусловие для всех моих кодовых фаз.**

### Фаза 1 — контракт LLM-клиента (документ, БЕЗ кода) ← делается сейчас
Согласуемый обеими задачами контракт `app/services/llm/`:

**Два входа, один конвейер:**
- `async def complete(...) -> LLMResult` — батч (tsk-302: `temperature=0`, JSON-разбор)
- `async def stream(...) -> AsyncIterator[LLMChunk]` — интерактив (tsk-572)

Общее для обоих: резолв подключения по канону ADR-0046 (`CLOSEROUTER_*`) с **нормализацией
суффикса `/v1`** (гоча, найдена чипом tsk-302), проверка остывания провайдера, учёт расхода,
единая таксономия ошибок.

**Таксономия ошибок и политика повторов:**

| Класс | Повтор | Действие |
|---|---|---|
| `LLMRateLimited` (429) | **ЗАПРЕЩЁН** | остывание провайдера на N мин, дальше сразу отказ |
| `LLMTimeout` | батч — 1; интерактив — 0 | ученик не ждёт второй круг |
| `LLMUnavailable` (сеть, 5xx) | 1 с backoff | затем деградация |
| `LLMConfigError` (401/403/404-модель) | нет | **алерт персоналу** (ошибка конфигурации, не ученика) |
| `LLMMalformed` | нет | лог тела ответа |

**Бюджеты:** интерактив — соединение 2 с, первый токен 5 с, всего 20 с; батч — всего 60 с.
**Учёт расхода:** таблица `llm_usage_event` (`student_id?`, `purpose`, токены вход/выход,
модель, оценка стоимости) — с первого дня, **лимиты не включаем**; это основа будущей
подписки и общая для обеих задач.

**Артефакт:** `docs/specs/2026-08-06-contract-llm-client.md` + ADR о передаче авторского
контента провайдеру. **Гейт: `spec-gate` — подтверждение от чипа tsk-302.**

### Фаза 2 — LLM-транспорт (этап 1 оркестрации, код)
Реализация контракта Фазы 1 + миграция `llm_usage_event`. Ключ в dev-`.env`, затем
операторский шаг для прод-`.env`. Разблокирует обе задачи.

### Фаза 3 — ядро наставника (код, без UI)
Таблицы `ai_tutor_session` / `ai_tutor_message` (снимок текста задания в сессии — переиздание
не ломает диалог). Сборка промпта из методики через `TutorTaskView` (**без эталона
физически**) + ответ ученика отдельной секцией как данные. Режимы A/B/C. Мягкий предел ~10
ходов → предложение уровня 1. TTL висящих сессий. Эндпоинты со стримингом. **Живой прогон 9
регресс-сценариев на кандидатах моделей → выбор модели.**

### Фаза 4 — SPW: чат ученика
Точка входа — автоматически после неверного ответа, там где сейчас «Ответ неверен».
Стриминг, плашка «этот разговор виден преподавателю», деградация = кнопка преподавателя.
**Плюс невзятая победа: рендер `options[].explanation`** — бьёт по тем же 527 провалам без
единого вызова LLM.

### Фаза 5 — TG_LMS: наставник в боте
Тот же контур в student-боте. Стриминга в Telegram нет — редактирование сообщения по мере
готовности либо ожидание полного ответа (решается в фазе).

### Фаза 6 — поверхности преподавателя + память наставника
Сводка диалога в `ReviewClaimItem` и `ReviewGradePanel.tsx` (**общие с tsk-302 — по очереди,
аддитивно разными полями**). Память наставника по паре (ученик, тема). Метрики: доля
решивших после диалога, темы повторяющегося непонимания, расход. Алерты 401/403, всплеск 429.

### Фаза 7 — датчик пробела + эскалация методисту (сценарий 2)
Сигналы: диалоги наставника + брак (**только `spw_web`**) + `blocked_limit` + ручной ввод
преподавателя. Фоновый тик (паттерн `course_dependency_state_cron`). Эскалация методисту
«нужен мини-курс по теме X» с **двумя действиями**: «создан вручную» (отметка) /
«передать в бэклог на автоотработку».

### Фаза 8 — бэклог мини-курсов + авто-порог
Очередь запросов, обработка по расписанию с ревью-гейтом и публикацией. **Включается
автоматически при достижении порога**, когда ручная отработка перестаёт справляться. Порог
калибруется по данным Фаз 6-7, не угадывается сейчас.

### Вне кода, параллельно с любой фазой
5 мини-курсов руками через `/methodist` на топ-кластеры провалов (Циклы 37, Жадные алгоритмы
33, Строки 26, Числа 23, Классификация ПО 17). Конфликтов не создаёт.

| Риск | Мера |

| Наставник «сливает» решение под давлением ученика | 9 регресс-сценариев + приёмка оператором как Гейт 2; методика уже закалена 8 итерациями |

| Конфликт с tsk-302 в 4 точках | Последовательная очередь (решение оператора) + pathspec-коммиты + `index_scope_gate` |

Без деплоя. Уровень 4 (мини-курсы) откатывается независимо — он в проде и от ИИ не зависит.

## Критерии Go/No-Go

- **Go Фазы 2** — только после: (а) сигнала от чипа tsk-302 об освобождении кода;
  (б) `spec-gate` PASS по контракту.
- **Go Фазы 4** (выкат ученику) — только после: живого прогона 9 сценариев с приёмкой
  оператором **и** доказанной деградации (429/таймаут/401 → ученик видит преподавателя, а не
  ошибку).
- **Go Фазы 7** — только после накопления телеметрии диалогов (иначе пороги угадываются).
- **No-Go**, если тест-страж на утечку эталона не написан: без него КРИТ-пробел открыт.
- **No-Go**, если датчик считает по сырому `task_results` без фильтра источника.

## Решение по UX-сложности

Промежуточных экранов **не добавляем**. Наставник открывается прямо на экране результата,
там где ученик уже находится — ни одного лишнего перехода. Возврат — одной кнопкой.

Единственная намеренная сложность (`justified`): **плашка «этот разговор виден
преподавателю»** перед первой репликой. Причина — этическая: подросток пишет откровенно,
думая, что это между ним и роботом. Приёмочный тест: плашка видна **до** первой реплики, а
не после.
