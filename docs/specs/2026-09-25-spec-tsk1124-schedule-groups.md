# Спек tsk-1124 — группы расписания (аудитория + предмет)

Задача: `D:\Work\Root\tasks\tsk-1124-*.md`. Проекты: LMS, SPW, TG_LMS.

## Цель
Каждый слот принадлежит одной группе расписания (аудитория + предмет), ученик — одной или
нескольким; ученик видит и выбирает только слоты своих групп, кабинеты, опрос и тариф
опираются на ту же группу.

## Якоря (решения оператора, 25.09)
1. Группа = аудитория + предмет, справочник («Взрослые · Тестирование», «Дети · Информатика»).
2. У слота ровно одна группа, у ученика одна или несколько.
3. Группа управляет: запись и перенос; фильтры кабинетов методиста/преподавателя; опрос
   «Пожелания к расписанию» и рассылки; подсказка тарифной группы (деньги не двигать без
   подтверждения).
4. Разметка: все 24 активных слота и 91 ученик (154 привязки) → одна группа
   «Дети · Информатика» (ЕГЭ и ОГЭ занимаются вместе, делить нечем).
5. Ученик без группы ведёт себя как «Дети» (группа по умолчанию) — никто не теряет запись.
6. Взрослые тестировщики: слот пятница 12:00 мск, первая ученица — Коханюк (users.id=4652,
   курс «Тестировщик ПО», category пустая).

## Границы
Входит: справочник групп, группа у слота, группы ученика, единый предикат видимости слота,
его подключение во все пути выбора слота учеником, фильтры и подписи в кабинетах SPW,
аудитория опроса и напоминаний по группе, подсказка тарифа, заведение взрослой группы и
слота, живые проверки.
Не входит: разделение ЕГЭ/ОГЭ на разные слоты; автоматическая смена тарифа/начислений;
новые рассылки (сегодня рассылки по слотам нет — LMS и SPW её не содержат, только
напоминания опроса и занятий); диалоги ботов (в TG_LMS нет выбора слотов — только три
опросчика, они наследуют серверный фильтр).

## Инвентарь мест выбора слотов (снят механически, 25.09)
Учебник-путь (обязан идти через предикат):
- `schedule_booking_service._load_slots` → GET `/me/schedule-slots` (SPW SlotPicker,
  SchedulePreferenceForm), `join_slot` → POST `/me/schedule-slots/{id}/join`;
  `get_free_slots` → `/integrations` (лиды).
- `lesson_occurrence_service._active_slots_of / _find_slot_at / _list_slot_candidates /
  _seat_student_at` → GET `/lesson-occurrences/available-slots`, GET
  `/me/lesson-occurrences/bookable`, POST `/lesson-occurrences/{id}/join`,
  POST `/lesson-occurrences/{id}/reschedule` (tsk-967).
- `lesson_calendar_service.list_teachers_for_time` (`/me`).
Методист/преподаватель (фильтр + проверка совпадения группы):
- `/lesson-slots` (list/create/patch), participants add/transfer, `schedule_plan_service`
  (find_gaps/load_students/load_current_slots/apply), `schedule-slot-requests`,
  `/teacher/lesson-occurrences`, `/users/{id}/students`.
Опрос и напоминания: `schedule_preference_service.is_audience/get_summary`,
`schedule_preference_reminder_service` (cron + POST remind) — сейчас аудитория не зависит от
слотов; добавить группу.
Не трогаем (считают деньги/явку по факту привязки, группа не влияет): pricing, charge,
subscription, attendance, curator, graduation, breaks, merge.

## Модель данных
- `schedule_group(id, audience CHECK in ('kids','adults'), subject text, name unique,
  pricing_group_id NULL → pricing_group (только подсказка), is_default bool — ровно одна
  строка true (частичный уникальный индекс), is_active, created_at, updated_at)`.
- `lesson_slot.group_id` FK → schedule_group, после разметки NOT NULL.
- `user_schedule_group(user_id, group_id, created_at, added_by)`, PK (user_id, group_id).
- Эффективные группы ученика = его явные группы, иначе `{группа is_default}`.

## Единый предикат
Модуль `app/services/schedule_group_policy.py`:
- `student_group_ids(session, student_id) -> set[int]` (явные либо по умолчанию);
- `slot_group_filter(student_id_param)` — SQL-фрагмент
  `ls.group_id IN (<эффективные группы>)` для сырых запросов и выражение для ORM.
Все пути ученика из инвентаря вызывают его, копии условия запрещены
(память: «общее условие звать функцией»). Методисту — явный `?group_id=` в списках;
при добавлении/переносе ученика в слот чужой группы — 409 с понятным текстом, обход
флагом `force_group=true` (с автодобавлением группы ученику).

## Решения по ходу (Ф3, 26.09)
- **Сетка записи только детская.** `in_grid` (Пн–Чт 12–19, Сб 9–14) — осеннее
  расписание детей; пятница в неё не входит, и взрослый слот пт 12:00 был бы
  спрятан из записи. Проверка сетки теперь только для групп `audience='kids'`
  (`schedule_booking_service._grid_ok`); у взрослых решает сам активный слот.
- **Занятие без слота** (разовое) принадлежит группе по умолчанию — по тому же
  правилу, что ученик без группы (`occurrence_visible`).
- **Площадки** (`GET /integrations/free-slots`) без `group_id` видят группу по
  умолчанию, взрослые площадки передают свою группу.
- Предикат: `schedule_group_service.effective_group_ids` + `slot_visible` /
  `occurrence_visible`; сторож-тест запрещает копии условия в `app/services`.
- Проверка группы при добавлении/переносе ученика методистом — в Ф4 вместе с UI.
