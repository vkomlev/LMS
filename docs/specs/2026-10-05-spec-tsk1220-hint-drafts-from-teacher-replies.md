# tsk-1220 — черновики текстовых подсказок из ответов преподавателей

## Цель
Из текстовых ответов преподавателей на заявки помощи модель делает черновики подсказок к заданиям; черновик без утечки ответа попадает в очередь вычитки; в `hints_text` он попадает только после подтверждения человеком; раз в неделю рутина добирает новые ответы.

## Границы
Входит:
- таблица черновиков и API в LMS;
- генератор на стороне LMS (вызов модели);
- пакетный скрипт в ContentBackbone (линтер + запись в очередь + состояние «с прошлого прогона»);
- экран вычитки в SPW;
- первый прогон по накопленной базе;
- рутина раз в неделю.

Не входит:
- автопубликация;
- правка существующих подсказок;
- видеоподсказки (tsk-1138);
- линтер для заданий без эталона: правило молчит, там защищает только вычитка.

## Решения
1. **Хранение — отдельная таблица `task_hint_drafts`**, а не jsonb в задании. Черновик не должен попасть к ученику. Нужен учёт «из каких ответов собран», чтобы рутина не генерировала повторно. Отказ тоже должен храниться.
   Колонки: `id`, `task_id`, `text`, `source_reply_ids int[]`, `status` (`draft` / `approved` / `rejected`), `model`, `lint_flags jsonb`, `created_at`, `reviewed_by`, `reviewed_at`, `published_index`.
2. **Отбор ответов** (код, не модель):
   - `reply_kind='text'`, длина ≥ 40 символов;
   - нет ссылки на Телемост и видео;
   - исключены ответы, где ученик по сути получает ответ или разбор своего кода. Это решает модель: она возвращает `skip`, если приём из ответа не обобщается.
3. **Генерация** — `POST /tasks/{id}/hint-drafts/generate`, только methodist или admin, сервисный ключ допустим. Возвращает текст или `skip`, ничего не сохраняет. Промпт:
   - один обобщённый приём или ход рассуждения;
   - без ответа, без числа-результата, без кода решения (tsk-855, tsk-1180);
   - тон как у соседних `hints_text`, которые подаются в промпт;
   - если подсказки уже есть — следующая ступень «если не помогло», без повтора.
4. **Фильтр** в скрипте CB: `contains_answer_token` / `contains_answer_wordform` против эталона, плюс проверка «нет блока кода» и «нет совпадения с эталонным ответом». Утёкший черновик в очередь не идёт, он только считается в отчёте.
5. **Очередь** — `GET /tasks/hint-drafts/queue`, `POST /tasks/hint-drafts` (запись черновика), `POST /tasks/hint-drafts/{id}` (правка / approve / reject).
   Подтвердить может только человек: сервисный ключ получает 403, как в tsk-590. При approve текст **дописывается в конец** `hints_text` в той же транзакции, `updated_at` ставится триггером. `content_provenance` не ставим — так задумано в `PATCH /hints`, иначе заморозится условие.
6. **Модель** — проверяется по `model-routing.md`:
   - формат на двух непохожих заданиях (код и не-код);
   - удержание роли на ответе преподавателя, который содержит готовый ответ.

## Критерии готовности
- Миграция применена на проде, тесты LMS зелёные, в том числе на 403 для сервисного ключа при approve.
- Approve дописывает строку в конец `hints_text` и не трогает существующие подсказки (тест).
- Скрипт в сухом прогоне показывает число кандидатов, а в очередь кладёт только черновики, прошедшие линтер.
- Очередь на проде открывается под методистом, черновик виден, approve и reject работают (живая проверка).
- Первый прогон даёт сводку в задаче: сколько заданий, черновиков, пропусков и утечек.
- Рутина создана через scheduled-tasks и проходит `routine_report_gate`.

## Риски
| Риск | Мера |
|---|---|
| Модель выдаёт ответ | Промпт плюс линтер. Задания без эталона защищены только вычиткой — это помечается в карточке. |
| Ответы преподавателя про конкретный код | Модель возвращает `skip`, число пропусков видно в отчёте. |
| Повторная генерация каждую неделю | Учёт `source_reply_ids`: задание берётся снова, только если появились новые ответы. |
| Порча `hints_text` | Только дозапись по одобрению, тест на сохранность существующих подсказок. |
