## 1. Исходные данные

- Исследование: `docs/research/2026-10-28-tsk1247-trainers/` (report.md, prototype.html, mechanics-board.md).
- Цели оператора (28.10): (1) отстающие прокачивают базовые темы без опоры на внешнюю генерацию;
  (2) бесплатные вирусные инструменты для внешней аудитории. Пилот — Python.
- Решения оператора 29.10:
  - функционал прототипа принят; дизайн аскетичный — докрутить;
  - референс: тренажёры xumuk.ru (таблица Менделеева и др.); исходная ссылка `xumuk.ru/esa/fs.html` не работает;
  - встраивание на любые сайты — да, с обязательным авторством и ссылкой на victor-komlev.ru;
  - бесплатная лицензия с брендом — да;
  - контакты — как при регистрации в LMS (тот же порядок согласий);
  - в курсе — ветвление после теории: «Всё понятно?» Да → задания, Нет → тренажёр.
    Механизма ветвления в LMS пока нет.

## 2. Системный аудит (PRE-REVIEW)

- Есть: гостевой контур (`guest_session`, `is_public_demo`), лид-магниты (`lead_magnet_service`),
  `/embed/*` (только показ, `frame-ancestors` = victor-komlev.ru), `learning_events` (только вошедшие),
  наставник после неверного ответа, якоря node_sequence (П7, tsk-996) — порядок теории и заданий в узле.
- Нет: интерактивного типа задания, ветвления пути в узле, записи событий гостя вне квиза/диагностики.
- Узел 106 «Первая программа» — 4 курса, ~85 учеников, база «до» снята (tsk-1246).

## 3. Шаг 0

- NorthStar (`docs/NORTH_STAR.md`): цель «ученик доходит до результата». Тренажёр как снятие застревания —
  в цели. Внешняя вирусность — маркетинговая цель, NorthStar её не покрывает: не конфликт, но успех пилота
  меряется по двум разным осям, смешивать нельзя.
- **ПРЕДУПРЕЖДЕНИЕ (маркер дрейфа «строим механизм, не спросив, доходит ли человек»):**
  развилка «Всё понятно? Да/Нет» опирается на самооценку. Отстающие чаще всего отвечают «понятно»
  (тот же эффект, что 24 обращения за помощью на 527 неверных ответов). Нужен второй вход в тренажёр
  по факту: неверный ответ на задание узла → предложение тренажёра.

Режим: **РАСШИРЕНИЕ** (оператор, 29.10). Два входа в тренажёр: развилка «Всё понятно?» после теории
и предложение после неверного ответа на задание узла (оператор, 29.10).

Опора для ветвления: у материалов уже есть уровень обязательности (skippable / recommended / required,
`app/models/materials.py:85`) и единый порядок узла `node_sequence` (П7). Тренажёр = материал узла
нового типа `trainer`, уровень `skippable`; развилка = свойство материала-теории, а не новый механизм пути.

## 4. Разделы обзора

- **Расширения (приняты 29.10):** два тренажёра на общем движке («Ты — интерпретатор», «Цикл-машина»);
  витрина `/trainers` в духе xumuk.ru (страница на тренажёр, SEO, «Встроить», «Записаться»);
  ошибки тренажёра передаются наставнику.
- **Р1 Архитектура:** движок `TrainerEngine` в SPW по JSON-сценарию; маршруты `/t/[slug]`, `/trainers`,
  `/embed/trainer/[slug]` (frame-ancestors *, без cookie, несъёмная плашка авторства);
  LMS: `materials.type += 'trainer'`, развилка — `materials.content.checkpoint` у теории,
  `GET /trainers/{slug}`, `POST /trainers/{slug}/events` → `learning_events`.
  Решения: 1A — сценарий хранится в LMS в содержимом материала, публикуется публикатором CB;
  п.2 — от копирования страницы не защищаемся, авторство держит плашка в iframe + лицензия.
  Бот TG_LMS: тип `trainer` показывать ссылкой. Откат — рубильник `TRAINERS_ENABLED`.
- **Р2 Ошибки:** сценарий проверяется схемой при публикации (битый до ученика не доходит);
  2A — события вошедшего в очереди браузера с досылкой; граница ошибки React → «начать уровень заново»;
  миграция `ADD VALUE` к enum `content_type` — отдельной ревизией без данных.
- **Р3 Безопасность:** открыт только `/embed/trainer/*`; ручка событий — лимит по IP, ≤200 шагов в пакете,
  коды ошибок только из сценария, ввод консоли ≤64 символа; ответы сценария не скрываем (защита — выгодность
  честного пути); контакты — путём регистрации LMS.
- **Р4 Данные:** развилка — нажатие «Да/Нет» пишется событием `checkpoint_answer` (иначе нечем мерить
  самооценку против факта); повторное прохождение — новая попытка, не перезапись; гость → вход — перенос
  через `attribute-guest`.
- **Р5 Качество:** движок — чистая функция `step(state, answer) → state` без React, рендер отдельно;
  генерация шагов цикла — в сценарий заранее; один файл схемы сценария на LMS (pydantic) и SPW (zod из
  JSON Schema, не руками).
- **Р6 Тесты:** юнит движка на оба сценария (все ошибки из карты, все зёрна); прогон «до финала» по каждому
  зерну; API — гость/вошедший/встройка/лимит; e2e Playwright: урок → «Нет» → тренажёр → задание; неверный
  ответ → кнопка; iframe на чужом домене; ширина 375 px.
- **Р7 Производительность:** сценарий ≤30 КБ, кешируется (ETag); события пакетом раз в уровень.
- **Р8 Наблюдаемость:** метрики пилота — (а) доля «Нет» и доля входов после ошибки; (б) доходят ли до финала;
  (в) первая попытка заданий узла 106 до/после у прошедших и непрошедших; (г) встраивания по доменам и
  заявки с витрины. Отчёт — скрипт `scripts/trainer_pilot_report.py`, раз в неделю.
- **Р9 Выкатка:** миграция → LMS за рубильником (выкл.) → SPW → публикация сценариев → включение на узле 106
  → живая проверка. Откат: рубильник; встраивание — строка CSP.
- **Р10 Будущее:** обратимость 4/5 (enum `trainer` останется в БД). Долг: нет редактора сценариев —
  сознательно, до 3-го тренажёра.
