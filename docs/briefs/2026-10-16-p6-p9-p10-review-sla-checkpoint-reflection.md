# Постановка: LMS П6, П9, П10 — срок ответа на заявку и счётчик просроченного, контрольная точка в материале, рефлексия после разбора

> Задачи: tsk-995 (П6), tsk-998 (П9), tsk-999 (П10). Источник — педагогический аудит
> `docs/qa/lms-pedagogy-audit-2026-09-17.md`. Решения оператора — 2026-10-16.
> Факты о коде сверены с main 2026-10-16 (голова Alembic `tsk1361_requirement_sync`).
> Образец исполнения — `docs/briefs/2026-10-14-p3-p5-retrieval-help-gate-final-check.md` (П3–П5 выкачены).

## Цель

Преподаватель видит реальное «просрочено» и свою скорость проверки (П6), ученик после ответа на
заявку коротко формулирует, что понял и что нет (П10), а материал может задать 1–2 вопроса сразу
после теории и записать сигнал усвоения, не блокируя прохождение (П9).

Сверка с `docs/NORTH_STAR.md` («ученик доходит до результата, время преподавателя — на то, ради чего
нужен человек»): П6 делает регламент предсказуемым, П10 и П9 дают сигнал, где ученик не понял, без
лишней ручной работы. Расхождений нет.

| Р2 | Где спрашивать рефлексию (П10) | **После любого ответа на заявку** — и после индивидуального разбора, и после обычного ответа преподавателя; ответ ученика необязателен (можно пропустить) |

## Факты, на которые опирается постановка (не делать дублей)

- **Срок ручной проверки РАБОТ уже есть** (tsk-1176): `app/services/review_sla.py` — `review_due_at = submitted_at + REVIEW_SLA_HOURS` (48 ч), `is_review_overdue`; используется в `list_pending_reviews` (`teacher_queue_service.py:~1605`), `attempts.py` (`manual_check_due_at`), `me_service.py`, `teacher_attention_service.py` (`reviews_stale`). Новый срок для работ НЕ вводить.
- **`help_requests.due_at`** (`models/help_requests.py:116`) кодом **не пишется** ни в одном из 4 INSERT (`help_requests_service.py:~238, ~349, ~464`, `attempt_auto_extend_service.py:~131`), но читается: сортировка, фильтр `overdue`, признак `is_overdue`.
- **`overdue_total`** в `get_teacher_workload` (`teacher_queue_service.py:~1692–1753`) считается по `help_requests.due_at` → **всегда 0**; показывается в SPW `components/teacher/WorkloadSummary.tsx:~58` и `components/methodist/MethodistOverview.tsx:~108`.
- **Скорости проверки работ нет нигде.** `teacher_dashboard_service.py` (tsk-1147) считает время реакции только по заявкам помощи.
- **`review_understood`** (`models/help_requests.py:126`, Boolean) — только у `individual_review`; эндпоинт `POST /learning/help-requests/{id}/rate-review` (`learning.py:~1186`), сервис `rate_individual_review` (`help_requests_service.py:~1790`): true — закрыть заявку, false — эскалация методисту. SPW: `components/task/HelpLadderPanel.tsx:~118–150` (показ только после клика по ссылке разбора), хук `lib/learning/use-help-ladder.ts`.
- **Материал:** `materials.content` JSONB, для text — `{text: <html>, format: "html"}`; рендер `components/material/MaterialViewer.tsx`; прохождение — `POST /learning/materials/{id}/complete` → `student_material_progress`.
- **Публикатор CB:** `monolith/lms_publish/blocks_to_lms.py` — `INTERACTIVE_BLOCK_TYPES = (control_question, task, quiz)` вырезаются из материала и становятся отдельными заданиями.
- **События:** `learning_events` (`student_id`, `event_type`, `payload` JSONB, `created_at`) — уже пишет `task_opened`, `hint_open`.

## Границы

**Входит:** П6, П10, П9 по плану ниже.

**Не входит:**
- новый срок проверки для работ (он есть — `review_sla`);
- напоминания и уведомления о просроченных заявках (ТГ, почта) — отдельно, после пилота;
- переписывание лестницы помощи tsk-303, кроме точки показа рефлексии;
- контент П9 в облаке: вопросы для пилотного урока пишет `/methodist` локально (шаг 16);
- влияние ответа на чекпоинт на статус материала, курса, заданий, попыток — его НЕТ (диагностика, не гейт).

## Ограничения

- Миграции — `app/db/migrations/versions/`; перед созданием и перед пушем — `git fetch` + `alembic heads` по свежему `origin/main`, одна голова.
- Всё, что меняет поведение для учеников, — **за выключенным по умолчанию рубильником**: `HELP_REFLECTION_ENABLED` (env, false) для П10; показ чекпоинтов П9 — рубильник `MATERIAL_CHECKPOINTS_ENABLED` (env, false). П6 видят только преподаватели и методисты — без рубильника, но `HELP_SLA_HOURS` настраивается.
- Не ломать `rate_individual_review`: «Нет, всё ещё не понимаю» → эскалация методисту остаётся.
- Ответы рефлексии и чекпоинтов — текст ученика: экранировать при показе, ограничить длину (рефлексия ≤ 500 символов на поле, ответ чекпоинта ≤ 200).
- Аналитика пробелов (`learning_gaps_service`, `REAL_STUDENT_SOURCES`) и все расчёты по `task_results` не должны меняться от чекпоинтов: чекпоинт — **не** `task_results`.
- Облачная реализация: нет боевой БД и живого сайта. Тесты — на тестовой БД проекта; живая проверка — после выката на машине оператора.

## План

### Фаза A — П6: срок ответа на заявку, счётчик просроченного, скорость проверки (tsk-995)

1. Настройка `HELP_SLA_HOURS` (`app/core/config.py`, по умолчанию 24) и функция `help_due_at(created_at)` рядом с `review_sla.py` (тот же стиль).
2. Заполнять `help_requests.due_at = created_at + HELP_SLA_HOURS` во ВСЕХ путях создания **открытых** заявок (`manual_help` по заданию и по материалу, `blocked_limit`, `individual_review`); для сразу закрытых (автопродление `attempt_auto_extend_service`) — не ставить. Тест на каждый путь.
3. Разовое заполнение для уже открытых заявок: миграция данных `UPDATE help_requests SET due_at = created_at + interval '24 hours' WHERE due_at IS NULL AND status = 'open'` (часы — из той же константы; в отчёте — сколько строк затронуто на тестовой БД). На проде миграция пойдёт выкатом — **число строк до выката сверить read-only** (шаг 18).
4. `overdue_total` в `get_teacher_workload`: = просроченные открытые заявки (`due_at < now()`) **+** просроченные обязательные работы на проверке (`is_review_overdue` из `review_sla`, тем же условием и ACL, что `list_pending_reviews`). В ответе — раздельно `overdue_help` и `overdue_reviews` плюс прежний `overdue_total` (сумма) для совместимости.
5. Метрика скорости проверки работ: за последние 30 дней по преподавателю (и по школе для методиста) — медиана и 90-й перцентиль `checked_at - submitted_at` по `task_results` с ручной проверкой (`checked_by` не NULL, источник не `manual_teacher`-зачёт без сдачи — уточнить по коду и обосновать), плюс доля проверенных в срок `REVIEW_SLA_HOURS`. Добавить в ответ `GET /teacher/workload` и в методистский обзор (там же, где `teacher_dashboard_service` считает реакцию по заявкам).
6. SPW: `WorkloadSummary.tsx` — «Просрочено» с разбивкой «заявки / работы»; блок «Скорость проверки за 30 дней: медиана N ч, в срок X %». `MethodistOverview.tsx` — то же по школе. Без новых экранов.

### Фаза B — П10: рефлексия после ответа на заявку (tsk-999)

8. Эндпоинт `POST /learning/help-requests/{id}/reflection` `{main: str|null, unclear: str|null, understood: bool|null}`: только владелец заявки; можно, когда у заявки есть ответ преподавателя (`help_request_replies`) ИЛИ ссылка на разбор; один раз (повтор → 409 `already_reflected`); пустые поля допустимы (пропуск).

Для `individual_review` форма заменяет прежние две кнопки (с той же эскалацией). Показ — не только после клика по ссылке: после появления ответа преподавателя.

### Фаза C — П9: контрольная точка внутри материала (tsk-998)

12. **CB (`D:\Work\ContentBackbone`, репозиторий vkomlev/ContentBackbone):** в блочном формате — признак у `control_question` (например, `"embed": true` или новый тип `checkpoint` — выбрать по коду, обосновать) → публикатор `blocks_to_lms.py` **не вырезает** такой блок в задание, а встраивает в `content` материала: `{text: <html>, format: "html", checkpoints: [{id, after_block: N, question, kind: "single"|"short", options?: [...], answer: ...}]}`. Ответ хранится в материале, ученику не отдаётся (п.13). Тесты публикатора; обычные `control_question` без признака работают как прежде.

Повторный ответ разрешён (пишется новое событие). Прохождение материала (`/complete`) от ответа **не зависит**. Гейты: доступ к материалу (те же, что у выдачи материала), оплата.
14. Сигнал усвоения: в отчёте `topic_mastery_service` (если он уже читает `learning_events`) — учесть `material_checkpoint`; в `learning_gaps_service` и `task_results` — **ничего не менять**. Если `topic_mastery` событие не подхватывает естественно — оставить только запись события и написать в отчёте, что подключать.
15. **SPW:** `MaterialViewer.tsx` — при `MATERIAL_CHECKPOINTS_ENABLED` и наличии `checkpoints` вставить после указанного блока карточку вопроса (выбор / короткий ответ) с кнопкой «Проверить себя», результатом и пояснением; кнопка «Прошёл материал →» доступна всегда. При выключенном рубильнике — материал выглядит как сейчас.

## Критерии готовности

1. `pytest` LMS без новых падений (известные на main: `test_tsk301_ai_spend_guard::test_no_unregistered_ai_spend_point`, 3 из `test_tsk521_link_audit`, `test_tx_isolation_optout::test_optout_list_matches_modules_with_own_engine`; `test_code_quality_tsk302` изредка под нагрузкой). Тесты CB публикатора — зелёные.
2. Миграции применяются и откатываются (`upgrade head` → `downgrade -1` для каждой), одна голова.
3. При рубильниках по умолчанию поведение для ученика **не отличается** от main: тесты лестницы помощи tsk-303 и движка — без правок ожиданий.
4. П6: каждая новая открытая заявка получает `due_at = created_at + 24 ч`; `overdue_total` = заявки + работы и не равен 0 на тестовых данных с просрочкой; метрика скорости считается и отдаётся в `/teacher/workload`.
5. П10: при включённом рубильнике после ответа преподавателя ученик может оставить рефлексию один раз; преподаватель видит её в карточке; `individual_review` с «не понял» по-прежнему эскалируется методисту.
6. П9: материал с `checkpoints` отдаётся ученику без ответов; ответ пишет событие `material_checkpoint` и возвращает вердикт; `/complete` и статусы курса не зависят от ответа; при выключенном рубильнике SPW показывает материал как раньше; обычные `control_question` публикуются как прежде.
7. SPW: `tsc --noEmit` и eslint без новых ошибок; vitest на форму рефлексии, разбивку «Просрочено», карточку чекпоинта.
8. Отчёт: решения по пп. 5 и 12 с обоснованием, список файлов, что проверить живьём, что включать оператору.

## Риски

| Риск | Мера |
|---|---|
| Разовое заполнение `due_at` сразу сделает много старых заявок «просроченными» и испугает преподавателей | Перед выкатом посчитать число (шаг 18); если старых открытых много — ставить срок от момента миграции, а не от `created_at` (решить по числу, записать в отчёт) |
| Метрика скорости учтёт зачёты преподавателя без сдачи ученика | Явный фильтр источника и наличия `submitted_at` ученика; тест |
| Правильный ответ чекпоинта утечёт ученику через выдачу материала | Отдельная проекция `content` для ученика без `answer`; тест на отсутствие поля |
| Изменение публикатора CB сломает существующие курсы при переиздании | Новый признак только опционален; тест «без признака — как раньше»; переиздание курсов не запускать |
| Форма рефлексии раздражает учеников | Необязательна, «Пропустить» на виду; рубильник выключен по умолчанию |
| Конфликт миграций с параллельными сессиями | `alembic heads` перед созданием и перед пушем |
