# Бриф — кабинет методиста в SPW (tsk-433)

## 1. Проблема и результат

Методист сегодня работает только через ТГ-бота. Веб-кабинета нет. Прецедент —
портал преподавателя (tsk-298, Эпик B роадмапа): закрыт с полным паритетом с ботом,
бот сохранён как канал пушей.

**Результат:** методист выполняет свою дневную работу в вебе — разбирает эскалации,
проверяет работы, отвечает на заявки помощи, видит учеников/преподавателей/курсы,
точечно правит контент — не открывая Telegram.

## 2. Решения оператора (2026-07-29)

| Развилка | Решение |
|---|---|
| Объём Фазы 1 | Операционный слой **+** авторский CRUD (паритет с ботом) — как цель tsk-433 |
| Судьба ТГ-бота | **Параллельный канал** (пуши/мобильный), не выводится из эксплуатации |
| Режим обзора / форма поставки | **СОКРАЩЕНИЕ волнами**: проектируем всю систему сразу, реализуем и выкатываем Волну 1 |
| Роль веб-редактора контента | **Точечная правка + ревизия**, не дубль конвейера `/methodist` → Sheets → bulk-upsert |

## 3. Ключевой урок, который задача обязана закрыть

Кабинет преподавателя собирался экран за экраном разными сессиями без сквозного
дизайн/UX-прохода → 5 форматов дат и 5 визуальных языков статус-бейджей (аудит
tsk-422/451). Причина структурная: в `components/ui` нет общих `StatusBadge`/`DataTable`,
каждый экран решает форматирование сам.

**Следствие для tsk-433:** дизайн-система и общие компоненты закладываются ДО первого
экрана и на весь кабинет, а не на Волну 1. Экран, который форматирует дату или статус
мимо общего компонента, — брак.

## 4. Что уже существует (не пересоздавать)

- **Операционный backend готов сегодня:** роль `methodist` — глобальный ACL-bypass почти
  во всём teacher-контракте (reviews claim/grade/regrade, help-requests, activity-feed,
  progress, статистика, сообщения, снятие лимита попыток). Своя логика проверки не пишется —
  веб вызывает те же эндпоинты (правило tsk-298 «must-reuse»).
- **`GET /api/v1/methodist/escalations/pending`** — персональный инбокс эскалаций.
- **SPW role-guard generic:** `hasRole(me, "methodist")` работает без правок; паттерн
  `app/(teacher)/layout.tsx` — серверный guard + тонкие page.tsx + client-компонент на экран
  + хуки в `lib/<домен>/use-*.ts`.
- **Конвейер авторинга:** скилл `/methodist` → JSON/Google Sheets → bulk-upsert по
  `external_uid`. Веб его НЕ дублирует.

## 5. Что отсутствует (пробелы)

- Нет ни одного SPW-маршрута под методиста.
- Нет сводного/дашбордного эндпоинта для методиста (только персональный инбокс + teacher-очередь).
- Нет workflow модерации/публикации курса (в модели `courses` нет статуса) — **вне охвата**.
- Нет процесса калибровки сложности — **вне охвата** (есть только справочник `difficulty_levels`).
- Нет scoped-реестра «методист → курсы» — роль даёт глобальный доступ; это осознанно
  принимается как есть (N методистов = 2).

## 6. Вне охвата (явно отложено)

| Отложено | Обоснование |
|---|---|
| Модерация/публикация курса (draft→review→published) | Нет модели данных; отдельная продуктовая задача, не кабинет |
| Калибровка сложности как процесс | Нет процесса даже офлайн; сначала нужен продуктовый ответ |
| Создание курса «с нуля» в вебе, импорт из Sheets из веба | Дубль конвейера `/methodist` — решение оператора п.2 |
| Scoped-ACL методиста (курсы/преподаватели) | Глобальный bypass достаточен при N=2; усложнение без спроса |
| `/plan-design-review`, `/qa-design-review`, `/feature-completeness-review` | Только ПОСЛЕ первого живого использования (зафиксировано в tsk-433) |
| Вывод ТГ-бота из эксплуатации | Решение оператора: параллельный канал |

## 8. Риски

| Риск | Митигация |
|---|---|
| Сессия закончится на половине реализации | Режим СОКРАЩЕНИЕ волнами: Волна 1 самодостаточна и деплоится отдельно |
