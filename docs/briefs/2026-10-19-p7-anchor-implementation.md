# Постановка: П7 (tsk-996) — чередование теории и практики через якорь задания к материалу

> Реализация **принятого** ADR-0008 (`docs/ai/adr/0008-interleave-theory-practice-anchor.md`, решение оператора 2026-10-19).
> Факты о коде — ADR-0008 «Контекст» и `docs/briefs/2026-10-19-p7-interleave-options.md` (сверено 19.10).
> Образец исполнения — П3–П10 (`docs/briefs/2026-10-14-…`, `2026-10-16-…`): облачный запуск по фазе, перенос, тесты, выкат, живая проверка.

## Цель

Внутри раздела курса ученик получает теорию и практику вперемешку («материал → его задания → следующий
материал»), если задания привязаны к материалам якорем; без якорей поведение для учеников не меняется.

## Решения (обязательны, не пересматривать)

| # | Решение | Источник |
|---|---|---|
| Р1 | Форма — **якорь**: `tasks.anchor_material_id` (+ `anchor_source`), а не общая нумерация и не слияние сущностей | ADR-0008, оператор 19.10 |
| Р2 | Порядок узла выводится одной функцией `node_sequence` для всех 6 мест движка | ADR-0008 |
| Р3 | Все якоря NULL = ровно текущий порядок; миграции данных нет | ADR-0008 |
| Р4 | Ручной якорь методиста (`manual`) переиздание из CB не затирает; отсутствие поля в публикации ≠ обнуление | ADR-0008, Codex |
| Р5 | Старый обход — за переключателем `NODE_SEQUENCE_ENABLED` до конца пилота | ADR-0008, Codex |

## Границы

**Входит:** фазы A–C ниже.
**Не входит:** задание перед первым материалом узла; общая сортировка «узла целиком» новым эндпоинтом;
пилот на курсе и проставление якорей в существующих курсах (решение оператора после фазы C);
изменения бота TG_LMS (next-item без `after_*` — не затронут).

## Ограничения

- Миграции — `app/db/migrations/versions/`; `git fetch` + `alembic heads` перед созданием и пушем — одна голова.
- Не менять: триггеры и UNIQUE `tasks.order_position` (tsk-813), reorder по типам, `host_order_position`
  прозрачных подкурсов (tsk-1198), `_reorder_tasks_by_difficulty`, выборку tsk-314, ДЗ, П3, П5, П9, гостевой/демо доступ.
- Кеш обхода `("walk", root_id)` (tsk-662/1250) сохраняется — без лишних запросов на каждый шаг.
- Облако: нет боевой БД и сайта; тесты — на тестовой БД; живая проверка — после выката на машине оператора.

## План

### Фаза A — общая функция порядка, без якорей (LMS)

1. `node_sequence(course_id)` (новый модуль `app/services/node_sequence.py` или в `learning_engine_service`):
   материалы узла по `_order_key` → после каждого материала его задания (по `task_key`) → подразделы →
   задания без якоря/с невалидным якорем по `task_key`, с прозрачными подкурсами как сейчас. В фазе A якорей
   ещё нет — функция обязана давать **текущий** порядок.
2. Перевести на неё все места, где сейчас собирается порядок «материалы → задания» (механически сверить список
   grep’ом, не по памяти): `learning_engine_service` (`_walk_tree`, `_locate_item_course`, ветка `resolve_next_item`
   ~1356–1406 с `material_ids = []`), `me_service` syllabus-states, `content_grace_service._walk_sequence`,
   `preview_navigation._ordered_items`, `manual_progress_service`, `teacher_progress`.
3. Переключатель `NODE_SEQUENCE_ENABLED` (env, по умолчанию `true`; при `false` — прежний код без изменений).
4. **Тест эквивалентности:** на фикстурах разной формы (только материалы; только задания; подразделы;
   прозрачные подкурсы; выборка tsk-314; grace; неактивные элементы) выдача syllabus-states и полная цепочка
   next-item от начала узла **одинаковы** при `true` и `false`. Плюс скрипт `scripts/tsk996_sequence_snapshot.py`
   (read-only): снимок порядка по списку `course_id` в JSON — для сверки на копии/проде перед выкатом.

### Фаза B — якорь в БД, API и кабинете методиста (LMS + SPW)

5. Миграция: `tasks.anchor_material_id INTEGER NULL REFERENCES materials(id) ON DELETE SET NULL`,
   `tasks.anchor_source VARCHAR(16) NULL` (CHECK `IN ('publish','manual')`), частичный индекс; триггер-страж:
   якорь только на материал того же `course_id`, иначе ошибка.
6. Переезд задания между курсами (функция tsk-802) — обнулить якорь; переезд материала — обнулить якоря на него
   у заданий старого узла.
7. `node_sequence` учитывает якоря (неактивный материал — его задания стоят на его месте; якорь на чужой/удалённый
   материал = без якоря).
8. API: `PATCH /tasks/{id}` (и схема выдачи задания методисту) — `anchor_material_id` (валидация узла),
   при ручной правке `anchor_source='manual'`; снятие — явным `null`.
9. SPW, редактор задания у методиста: поле «Показывать после материала: [список материалов раздела] / в конце
   раздела». Ученические экраны не меняются (порядок с сервера).
10. Тесты: цепочка next-item по узлу с якорями — каждый элемент ровно один раз, в ожидаемом порядке; удаление и
    переезд; неактивный материал; прозрачный подкурс рядом с якорями; выборка tsk-314 опустошает группу.

### Фаза C — публикатор ContentBackbone ставит якоря (CB + LMS bulk-upsert)

11. CB `extract_lms_tasks`: для каждого задания — номер H2-раздела, под которым оно стоит в блоках
    (контрольные точки П9 номер не занимают); `to_task_payloads`: `anchor_external_uid = "{base}#m{N}"`;
    задание до первого H2 или в уроке без H2 — поле не передаётся.
12. LMS `bulk_upsert` заданий: резолвит `anchor_external_uid` → `anchor_material_id` в том же узле;
    перезаписывает якорь **только** если текущий `anchor_source` пуст или `'publish'`; ставит `'publish'`;
    поле не пришло — якорь не трогает.
13. Флаг публикатора `--no-anchors` (откат: переиздание без якорей не меняет существующие, а явное снятие —
    отдельной командой/скриптом с dry-run).
14. Тесты CB: урок «теория — задания — теория — задания» → якоря на свои разделы; урок без H2 → без якорей;
    тесты LMS: ручной якорь переживает переиздание; пересортировка по сложности не ломает группы.

## Критерии готовности

1. Полный pytest LMS — без новых падений (известные на main: `test_tsk301_ai_spend_guard::test_no_unregistered_ai_spend_point`,
   3 из `test_tsk521_link_audit`, `test_tx_isolation_optout::test_optout_list_matches_modules_with_own_engine`;
   `test_code_quality_tsk302` изредка под нагрузкой). Тесты CB публикаторов LMS/WP и линтер — зелёные.
2. Фаза A: тест эквивалентности зелёный на всех фикстурах; при `NODE_SEQUENCE_ENABLED=false` код идёт прежним путём.
3. Фаза B: миграция `upgrade → downgrade -1 → upgrade`; без якорей выдача = фаза A; с якорями — ожидаемый порядок, без пропусков и повторов.
4. Фаза C: переиздание не затирает `manual`; без H2 — без якорей; `--no-anchors` работает.
5. SPW: tsc, eslint без новых ошибок и предупреждений; vitest на поле якоря в редакторе.
6. Отчёт каждой фазы: список мест, переведённых на `node_sequence` (grep), что проверить живьём.

## Риски

| Риск | Мера |
|---|---|
| Курсор next-item пропускает/повторяет элементы на смешанной последовательности | Тест полной цепочки по узлу во всех формах фикстур (п.4, п.10) |
| Пропущено одно из мест, собирающих порядок | Механический grep по `"materials"`/`"tasks"` шагам и `order_position` в сервисах обхода; список — в отчёт |
| Рост запросов из-за якорей | Якоря грузятся тем же запросом заданий узла; кеш `walk` сохраняется; замер числа запросов в тесте |
| Переиздание затирает ручную работу методиста | `anchor_source` + правило п.12, тест |
| Расхождение порядка у прозрачных подкурсов | Отдельная фикстура; `host_order_position` не меняется |
