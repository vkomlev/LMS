# Проверки и диагностика

Каждая проверка содержит дату, цель, контур, команду и очищенный вывод. Активный systemd
юнит не доказывает доступность снаружи. Непройденный обязательный пункт — `NOT_READY`.

## Инвентарь и инцидент

ОС/ядро, uptime, память/диск; `ss -tlnp`, юниты, версии, cron/timers, права, эффективный
sshd и sudoers. Читать нужные журналы; секреты перечислять именами без значений.
Бан/лимит — гипотеза до журнала; пустой текущий журнал не исключает прошлый бан.
До совета повысить тариф измерить ресурсы и подключения, проверить блокировки через `db-check`.

HTTP к перегруженному/чужому источнику — поштучно с паузой не менее 25 секунд. Несколько
таймаутов — остановить повторы; контрольный запрос уточняет сеть, но не доказывает бан.
Не заменять копирование файлов тысячами HTTP-запросов.

## Сборка и защита

- Синтаксис конфигов, сервисы, слушающие и доступные извне порты. Список из задачи включает
  фактический SSH-порт, а не всегда 22/80/443.
- Новая SSH-сессия после изменения, доступ оператора и деплоя, отрицательная проверка
  запрещённого входа без серии попыток.
- Защита секретных путей/uploads, fail2ban без легитимных совпадений, исключения публикатора
  и подтверждённых ботов. Rate limit проверять в разрешённом объёме по реальным настройкам.
- Dry-run обновлений, задания, копия и пробное восстановление.
- HTTPS: имя, срок, цепочка; dry-run обновления сертификата, когда настроено.

До DNS: `curl --resolve <домен>:443:<IP> https://<домен>/...` с нужным SNI. `-k` допустим
только как явно обозначенная диагностика HTTP при непроверенном сертификате; это никогда
не TLS PASS. Обход кеша подтверждать настройками и журналом источника: query string или
заголовок сами по себе свежесть не гарантируют.

## Перенос и наблюдение

Сверить страницы (главная, статьи, уроки, 404): HTTP, title, canonical, robots,
структурированные данные; состав всех sitemap. API — с защищённым файлом учётных данных,
не ключом в командной строке. Разобрать ошибки приложения. После переключения — DNS
из нескольких источников, TLS, те же адреса публично. Во время наблюдения считать долю
5xx (ошибки / запросы), 429/баны легитимных клиентов и ресурсы; пороги фиксировать в плане.
