# Проверка и сохранение результата методиста

### Шаг 5: Верификация
- [ ] Каждый учебный результат = наблюдаемый глагол + уровень Блума
- [ ] Прогрессия монотонна, нет скачка через непокрытую предпосылку
- [ ] Каждое задание имеет наблюдаемые критерии готовности
- [ ] Сложность каждого задания оценена по 3 параметрам
- [ ] Сложность не превышает потолок заявленной стадии аудитории (иначе — добавить scaffolding-шаг или пометить)
- [ ] **Профиль курса зафиксирован** (Шаг 0.А): источник, модель аудитории, каталог вывода, `uid-prefix` — записаны в YAML плана; чужие курсовые требования не притянуты
- [ ] **Проверка пересечения с портфелем пройдена** (course-profile.md, Шаг 0.А.6): пересечений не найдено ИЛИ найденное пересечение вынесено оператору и решение зафиксировано — не пропущено молча
- [ ] *(если методика AI-наставник включена оператором)* цепочка встроена; ни одно задание не решается одним промптом без понимания; у каждого задания есть механизм защиты от списывания. По умолчанию методика выкл. — пункт пропускается
- [ ] Сумма времени заданий ≤ бюджет самостоятельной работы формата
- [ ] **Полнота против инвентаря:** каждый файл источника (профиль) классифицирован include/exclude с причиной; обязательный-по-стадии минимум (coverage-and-review, Часть 1) не выпал; есть раздел «Карта покрытия источника»
- [ ] **Исполнимость кода на машине ученика** (coverage-and-review, Часть 2, анти-поверхностность): тема с заданиями «напиши и запусти свою программу» имеет урок-заготовку (файл/путь/целая программа/признак успеха/разбор ошибки), имя файла в примере совпадает с реальным именем вложения
- [ ] **Ретрофит корпуса** (coverage-and-review, Часть 3): при новой главе / изменении числа глав / правке формулировки — механический grep по всему корпусу уроков (прогнозные фразы, `total` navigator, форвард-ссылки «уже видели», исправленная строка), не точечный фикс одного места
- [ ] **Двойная проверка (Шаг 4) пройдена**, остаточные риски зафиксированы
- [ ] **Задания по `assignment-rules.md`:** типы только из enum (`TA` лишь у проектных, частота по §3.5a — не в конце каждой темы); счёт по узлам (лист=3, подкурс 1-го ур.=10–15 + 2–3 проектных); микс 70/25/5 посчитан фактически; difficulty по маппингу; у каждого задания `external_uid`/`course_uid`/наблюдаемые `solution_rules`; узел-измеритель (пробник/эмуляция, §3.7) помечен отдельно от обучающего; словарь условия сверен с материалами курса (§9 п.7); перед сдачей готового банка — механический проход по ВСЕМ заданиям темы на подсказку/эталон (§6), не только по новым
- [ ] **Глубина практики (гейт §3.4 + mastery-линза):** содержательная тема классифицирована как подкурс (10–15 разнообразных), не лист на 3; каждый приём/метод материала применён ≥1 заданием; распространённые приёмы не пропущены; микс типов практики (§8 п.8); mastery-линза Шага 4 пройдена
- [ ] **Профиль прогрессии аудитории (assignment-rules §3.5):** объём/сложность заданий растут от старта к финалу в коридоре профиля; для не-детской аудитории к концу — многострочные программы и ≥ требуемого числа проектных; «детский» одношаговый формат весь курс для не-детской ЦА = брак; многошаговые/проектные авто — `SA_COM`, не `TA`
- [ ] **Две проекции присутствуют:** LMS-импорт (JSON bulk-API + Google Sheets раскладка) и WP-структура «Навигатор»; `course_uid`/`external_uid` общие и стабильные
- [ ] **Конверт урока у КАЖДОГО урока:** цель-действие на входе + итог на выходе (обе проекции, не `lms_skip`); спиральный курс — мостик «Вспомни: …»; первый программирующий урок — подсказка запуска. Абстрактные темы помечены под ASCII-схему внутри материала (coverage-and-review анти-поверхностность)
- [ ] **Плоский курс только для мини (≤20 сущностей); больше — подкурсами** (класс → глава → тема-лист); у каждого листа материалы+задания рядом, лист ≤20 (LMS подаёт материалы→задания, подкурсы по `order_number` → длинная сплошная теория забывается к практике; порог enforce-ит публикатор, tsk-148). См. `lms-wp-export.md` § 1.1.1
- [ ] **WP-навигация и перелинковка (многостраничный курс):** в конце каждого L3-урока — блок навигации (Назад/В начало урока/В начало курса/Вперёд, сквозной переход); SEO-перелинковка на смежные материалы сайта в новой вкладке; внутренние ссылки — фактические вложенные пермалинки (см. lms-wp-export.md Часть 2). Оператор просит карту кокона/перевод на SEO-стандарт → структурированная процедура вместо ручной перелинковки (lms-wp-export.md Часть 2 п.5)
- [ ] Структура согласована с оператором (гейт Шага 2 пройден)

Нарушение → доработать, не выдавать.

### Шаг 6: Сохранение — две проекции (по `lms-wp-export.md`)
Источник курса **не переписывать** (план — слой нормализации). Каталог вывода — `output-root`
профиля (курс CreateCourses — слои `courses/<slug>/plan|assignments|exports`; флагман —
`docs\v2\curriculum\`); создать, если нет, и сообщить оператору пути.

**Файлы** (`{output-root}`, имена — по модулю):
1. `{модуль}-план.md` — учебный план
   (учебные результаты, прогрессия, карта занятий, «Карта покрытия источника»,
   «Двойная проверка», «Карта соответствия LMS-узел ↔ WP-страница»).
2. `{модуль}-задания.md` — задания по `assignment-rules.md`.
3. `{модуль}-lms-import.json` — LMS-проекция: курсы (`CourseCreate`+`course_uid`+
   иерархия/зависимости) + задания (`TaskUpsertItem` под `tasks/bulk-upsert`) +
   материалы. Схема — lms-wp-export § 1.2-A.
4. `{модуль}-lms-sheets.md` — те же данные раскладкой Google Sheets
   (листы Courses/Tasks/Materials, lms-wp-export § 1.2-B).
5. `{модуль}-wp-навигатор.md` — WP-проекция «Навигатор»: L1 навигатор / L2 темы
   (фикс. блоки + «Раздел N из M») / L3 посты, slug-паттерны, breadcrumbs.
   **Обязательно:** блок навигации в конце каждого L3-урока + SEO-перелинковка на
   смежные материалы сайта; внутренние ссылки — фактические вложенные пермалинки.
   Состав блока и спецификация — `lms-wp-export.md`, Часть 2, «L3 — навигация
   и перелинковка».

`course_uid`/`external_uid` — общий стабильный ключ обеих проекций
(идемпотентный upsert при повторном импорте).

YAML-метаданные `{модуль}-план.md`:
```
---
skill: methodist
module: {модуль или "весь курс (карта-план)"}
course-profile: {course: слаг | source-root: … | audience-model: … | progression-profile: … | spiral: да/нет | output-root: … | uid-prefix: …}
audience: {аудитория в модели курса} / {новичок|с-базой|уверенный}
format: {SELF|GUIDED|MENTOR} — {N недель + M ч самостоятельной}
methodology-source: {tsk-059-final | baseline (tsk-059 в разработке)}
lms-export: {путь к -lms-import.json и -lms-sheets.md}
wp-export: {путь к -wp-навигатор.md}
course-uids: [список course_uid узлов]
docs-refs: [файлы источника курса, использованные как основа]
date: {YYYY-MM-DD}
---
```
