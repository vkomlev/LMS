# Профиль курса — параметризация методиста под любой курс

Источник истины для skill `methodist`, Шаг 0.А. Скилл универсален: он проектирует
**любой** курс (школьный, детский, предвузовский, взрослый, мини-курс, флагман).
Всё, что специфично для конкретного курса — источники материалов, модель
аудитории, каталог вывода, обязательный минимум покрытия — задаётся **профилем
курса**, а не зашито в скилл.

**Инвариант:** требования одного курса не переносятся на другой «по инерции».
Файлы флагмана (`F-Claude*`, `X1*`, «Три ЦА»), его нумерация аудиторий и каталог
`curriculum/` — свойства профиля флагмана, а не правила методиста.

## Поля профиля

| Поле | Что задаёт | Откуда берётся |
|---|---|---|
| `course` | слаг/имя курса | запрос оператора, имя папки курса |
| `source-root` | каталог материалов-источника | корень курса (см. алгоритм) |
| `inventory-glob` | что считать инвентарём для гейта полноты | `source-root` + расширение файлов материалов |
| `audience-model` | как называются и нумеруются аудитории курса | документ ЦА курса, иначе интервью |
| `stage` | новичок / с-базой / уверенный | интервью (Шаг 1) |
| `progression-profile` | дети / подростки / предвузовский / взрослый-новичок | тип и назначение курса (`difficulty-and-design`, «Профиль прогрессии») |
| `spiral` | спиральный курс (класс→класс, многоглавный) или линейный | структура курса |
| `format` | SELF / GUIDED / MENTOR, бюджет часов | интервью, документ форматов курса |
| `output-root` | куда сохраняются план, задания, экспорты | конвенция проекта курса (см. примеры) |
| `uid-prefix` | префикс `course_uid` / `external_uid` | слаг курса, стабилен между прогонами |
| `required-minimum` | обязательный-по-стадии минимум покрытия | `coverage-and-review`, Часть 1 (общий инвариант + профильная надстройка) |

## Алгоритм определения (Шаг 0.А, до интервью)

1. **Корень курса.** Явно назван оператором → берём его. Иначе — рабочий каталог
   сессии и упоминание курса в запросе.
2. **Курс в `CreateCourses`** (`d:\Work\CreateCourses\courses\<slug>\`) — типовой
   случай, 19 курсов: читать `README.md` курса, `plan/`, `materials/`; инвентарь —
   `materials/**/*.md` (+ то, что README называет источником); вывод — слои
   `plan/ assignments/ exports/` того же курса; `uid-prefix` = слаг.
3. **Флагман** (`d:\Work\IT_Businessman\docs\v2`) — частный профиль: инвентарь
   `docs/v2/*.md`, аудитории по `02. Три ЦА.md` (ЦА-1/ЦА-2/ЦА-3 — курсовая
   нумерация, источник истины при конфликте), структура по `Карта Трека 1.md` и
   `plan track 1 v2.md`, форматы по `Форматы.md`, вывод в `docs\v2\curriculum\`.
4. **Другой проект / курс с нуля** — источник и каталог вывода назвать оператору
   и подтвердить; нет материалов-источника → сказать об этом прямо, не сочинять
   содержание «по памяти» (Правила качества).
5. **Незаполненные поля добираются интервью** (Шаг 1) и фиксируются в YAML плана
   блоком `course-profile`. Профиль записан в плане — следующий прогон его
   восстанавливает, а не переспрашивает.
6. **Проверка пересечения с существующим покрытием портфеля (ОБЯЗАТЕЛЬНО, до
   Шага 2 — проектирование программы).** Тема нового курса/модуля может уже быть
   написана где-то в портфеле независимо (прецедент `tsk-1011`: тема Excel
   независимо написана трижды — ручной лендинг, модуль другого курса, новый
   курс — потому что бриф не сверялся с остальным сайтом; тот же класс разрыва,
   что `tsk-769`). Механически, не по памяти:
   - **Сайт** (профили, публикующие в WP — см. `lms-wp-export.md`, Часть 2):
     `/site-researcher` или `веб-запрос` сайтмапа victor-komlev.ru + Grep заголовков
     и slug на ключевые слова темы нового курса.
   - **CreateCourses**: `Grep` по ключевым словам темы в
     `D:\Work\CreateCourses\courses\*\materials\**\*.md` и `README.md` каждого
     курса.
   - Другой профиль (например, флагман) — тот же принцип на каталог портфеля
     этого профиля, не на сайт CreateCourses по умолчанию.
   - **Найдено пересечение → стоп, не продолжать молча**: вынести оператору
     через `короткий вопрос оператору` (Контекст: что и где найдено; Суть: объединить /
     расширить существующее / делать новое осознанно; Рекомендация с
     обоснованием). Пересечений нет → зафиксировать в YAML профиля
     `coverage-check: не найдено пересечений (YYYY-MM-DD)`.

7. **Источник — рукописный конспект/скан/фото/методичка преподавателя → словарь
   обозначений с доказательством (повтор-дефект, курс kolledzh-oaip-pascal, tsk-955).**
   Для `source-root` из фото/сканов конспекта каждый значок/сокращение источника
   (например, «П1», «Пер», любая нестандартная нотация) обязан попасть в явный
   «словарь обозначений»: значок → его смысл С ЦИТАТОЙ конкретного места в источнике,
   где смысл виден (не достроен по созвучию — курс однажды прочитал «П1/П2/П3» как
   «промежуточные столбцы», хотя шапка таблицы конспекта читалась «Пер 1/Пер 2/Пер 3»,
   то есть переменные; курс получил обозначение, противоположное источнику). Обозначение
   без цитаты-доказательства в курс не вводить — описывать как «в тетради записано так,
   уточни у преподавателя». Чек-лист Шага 5: обозначения курса = обозначения источника,
   расхождения названы явно.

## Примеры профилей

**Курс CreateCourses (типовой):**
```
course: python-podrostki-11-14
source-root: d:\Work\CreateCourses\courses\python-podrostki-11-14\materials
audience-model: подростки 11–14 (одна аудитория, курсовой нумерации нет)
progression-profile: подростки | spiral: нет
output-root: d:\Work\CreateCourses\courses\python-podrostki-11-14\{plan,assignments,exports}
uid-prefix: PYPOD
```

**Школьный спиральный курс:**
```
course: informatika-5-11
source-root: ...\courses\informatika-5-11\materials
audience-model: классы 5–11 (у разделов разная аудитория — сегменты проектируются отдельно)
progression-profile: дети (5–7) / подростки (8–9) / предвузовский (10–11) | spiral: да
output-root: ...\courses\informatika-5-11\{plan,assignments,exports}
```

**Флагман:**
```
course: ai-predprinimatel (Трек 1)
source-root: d:\Work\IT_Businessman\docs\v2
audience-model: ЦА-1 джуны / ЦА-2 руководители / ЦА-3 маркетологи (docs/v2/02. Три ЦА.md)
progression-profile: взрослый-новичок | spiral: нет
output-root: d:\Work\IT_Businessman\docs\v2\curriculum
required-minimum: надстройка профиля — фундамент Claude, бесплатные альтернативы,
  расходы, глоссарий, безопасность (coverage-and-review, Часть 1, таблица флагмана)
```

## Что НЕ меняется от профиля

Методическое ядро скилла профилем не параметризуется и обязательно всегда:
таксономия Блума и оценка сложности, прогрессия без скачков, двойная проверка
(ученик / сеньор) и линза освоения, гейт полноты против инвентаря (меняется
только сам инвентарь), правила заданий (`assignment-rules.md`), конверт урока,
структура подкурсами и порог 20, две проекции LMS + WP.
