# Сохранение текста и визуалов

### Шаг 5: Сохранение в output/

После выдачи — сохранить файл:

**Путь:** `d:\Work\ContentFactory\output\{YYYY-MM-DD}-digital-copywriter-{format}-{goal}.md`

**Примеры имён:**
- `2026-04-20-digital-copywriter-tg-lifehack.md`
- `2026-04-20-digital-copywriter-vk-sales.md`
- `2026-04-20-digital-copywriter-article-edu.md`

**Особый случай — `outreach-script`:**
- Один тег → `{YYYY-MM-DD}-digital-copywriter-outreach-{tag}.md` (например `2026-05-11-digital-copywriter-outreach-hot-recent.md`)
- Пакет всех 6 тегов → `{YYYY-MM-DD}-digital-copywriter-outreach-tsk-057-all.md`
- В YAML файла обязательно поля `goal: outreach-script`, `tag: {имя тега}` или `tags: [список тегов]`, `linked-task: D:\Work\Root\tasks\tsk-057-lichnaya-kampaniya-viktora.md`
- **Image prompt НЕ требуется** для outreach (это DM, не пост с обложкой). Раздел `## Image prompt` пропускается.

Если за день несколько в одном формате+цели — суффикс `-2`, `-3`.

**Особый случай — `reels-script`:**
- Путь: `{YYYY-MM-DD}-digital-copywriter-reels-script-{goal}-{вариант}.md`, где `{вариант}` = `face` (с лицом/аватаром) или `noface` (без лица) — иначе разные варианты одной темы затрут друг друга при одинаковой дате+цели.
- В YAML файла обязательны поля `variant: face|noface` и `cta-word: {код-слово}`.
- **Image prompt НЕ требуется** (это видео-сценарий, не пост с обложкой). Раздел `## Image prompt` пропускается.

**Особый случай — `wp-publish` / `lms-publish`:**
- Сохранять как **`.json`** (сам блочный документ, не markdown-обёртку): `{YYYY-MM-DD}-digital-copywriter-{wp|lms}-{kind}-{slug темы}.json`.
- Содержимое файла = ровно тот JSON, что выдан пользователю (валидный по контракту; парсится `wp-publish` / `lms-publish-lesson`). Один и тот же документ (с заполненными `answer`) годен для обоих каналов.
- Раздел `## Image prompt` НЕ требуется (картинки — блоки `image` с `placeholder: true`, вставляются вручную после публикации).
- **Исключение — `kind: seo_article`** (не учебный материал): вместо `## Image prompt` сгенерировать обложку-инфографику (та же схема и механика, что у tg/vk ниже, холст 1200×630) и записать её путь в top-level поле документа `cover_image` ДО выдачи JSON пользователю (чтобы поле указывало на реально существующий файл).

**Особый случай — `tg` / `vk` (инфографика вместо иллюстрации, tsk-1002):**
- Раздел `## Image prompt (DALL-E)` НЕ используется — вместо иллюстрации по промпту генерируется детерминированная инфографика (SVG→PNG), холст 1080×1080.
- Содержимое — JSON по схеме:
  ```json
  {
    "kind": "stat | steps | flow | text",
    "title": "заголовок картинки",
    "subtitle": "подзаголовок (опционально)",
    "blocks": [ /* не нужен для kind=text */ ],
    "body": "1-3 предложения — только для kind=text"
  }
  ```
  - `stat` (в посте 2-4 конкретные цифры/факта) → `blocks: [{"value": str, "color": "blue|green|yellow|red", "line1": str, "line2": str?}]`
  - `steps` (пронумерованная последовательность шагов) → `blocks: [{"n": str, "title": str, "subtitle": str?, "color": "blue|green|yellow|red"}]`
  - `flow` (причинно-следственная цепочка без номеров) → `blocks: [{"title": str, "subtitle": str?, "color": "blue|green|yellow|red"}]`
  - `text` (ни цифр, ни шагов, ни цепочки) → без `blocks`, только `body`
- Сохранить этот JSON как сайдкар `{тот же путь и имя, что у .md-черновика}.infographic.json`, затем сгенерировать PNG рядом (`{тот же stem}.png`):
  ```bash
  python -c "
  import sys; sys.path.insert(0, r'D:\Work\ContentBackbone')
  from monolith.post_infographics.build import build_infographic
  import json
  content = json.load(open(r'<путь-к-infographic.json>', encoding='utf-8'))
  build_infographic(content, r'<путь-к-png>', width=1080, height=1080)
  "
  ```
  (для обложки статьи, случай выше — та же команда с `width=1200, height=630`).
- **Рендер упал (нет браузера, сбой) — не блокировать сохранение черновика.** Сохранить .md/.json как есть без картинки и явно предупредить текстом в конце ответа, что картинку нужно доделать вручную.

```
## Image prompt (DALL-E)

**Идея образа:** {1 строка — какой визуальный образ-метафора отражает суть поста, привязанная к ключевой аналогии}

**Промпт (RU):**
{развёрнутый промпт на русском, 2–4 предложения: что в кадре, стиль, цвета, освещение, композиция, без текста на изображении}

**Prompt (EN):**
{тот же промпт на английском — для DALL-E / Midjourney работает стабильнее}

**Negative / чего избегать:** text, logos, watermarks, low-poly 3D, plastic stock-photo people, neon AI clichés (glowing brain, blue circuit lines, robot hand)

**Соотношение сторон:** {tg/vk → 1:1 или 16:9; article → 16:9; email → 1.91:1}
```

**Правила image prompt:**
- Образ метафоричный, привязан к ключевой аналогии поста (не буквальная иллюстрация термина).
- Стиль по умолчанию: акварельный набросок, книжная иллюстрация, минималистичная редакторская графика, soft natural light. Никаких сток-фото с улыбающимися людьми в галстуках, никаких "AI-клише" (светящийся мозг, синие схемы, рука робота с цифрами).
- Без текста на изображении.
- Если в посте есть конкретная сцена (человек на лошади, шпаргалка в кармане, закрытая школа) — она и идёт в образ.
- Если пост абстрактный — выбрать одну предметную деталь-метафору (ключ в замке, тропинка между двух дорог, мосты).
- Английская версия промпта обязательна (DALL-E/Midjourney устойчивее на EN).

**Правила сохранения:**

Для `outreach-script` Image prompt НЕ требуется (DM не нуждается в обложке). Для формата `reels-script` Image prompt НЕ требуется (видео-сценарий, не статичный пост)
