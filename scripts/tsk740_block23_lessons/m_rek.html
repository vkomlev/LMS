После этого урока ты сможешь: написать короткую функцию, которая находит длину кратчайшего пути в ациклическом графе, объяснить, зачем ей запоминание, и назвать условие, при котором этот способ перестаёт работать.

Вспомни: в задании 16 ты ставил над рекурсивной функцией декоратор @lru_cache, чтобы она не пересчитывала одно и то же. Здесь нужен ровно он же, только в короткой записи @cache — это одно и то же, просто без скобок и параметра.

Идея: думать от финиша

Зададим вопрос не «куда идти из старта», а «сколько стоит дойти до финиша из вершины X». Ответ на него складывается из ответов соседей:

Лучший путь из вершины X в финиш = наименьшая из сумм «вес ребра X → сосед + лучший путь из соседа в финиш» по всем рёбрам, выходящим из X. У самого финиша лучший путь равен нулю: идти никуда не надо.

Это и есть рекурсия: функция для вершины X вызывает саму себя для соседей X, те — для своих соседей, и так до финиша.

Как это идёт на файле-примере

Ищем путь из вершины 1 в вершину 100. Разметим вершины, начиная с финиша, — так же, как это сделает функция, когда вызовы начнут возвращаться:

вершина 100 : финиш                                   -> 0.0
вершина 7   : одно ребро 7 -> 100 весом 2.0           -> 2.0 + 0.0 = 2.0
вершина 4   : одно ребро 4 -> 100 весом 8.0           -> 8.0 + 0.0 = 8.0
вершина 1   : три ребра
              в 7   : 5.5  + 2.0 = 7.5
              в 100 : 12.0 + 0.0 = 12.0
              в 4   : 2.5  + 8.0 = 10.5
              наименьшее                              -> 7.5

Целая часть 7.5 — это 7, ровно ответ ФИПИ для примера. Прямое ребро 12.0 проиграло: функция сравнивает все варианты, а не берёт первый попавшийся.

Программа

Граф прочитан в словарь граф так, как в теме про словарь смежности. Функция поиска:

from functools import cache

@cache
def лучший(вершина, финиш):
    if вершина == финиш:
        return 0.0
    ответ = float('inf')
    for сосед, вес in граф[вершина]:
        ответ = min(ответ, вес + лучший(сосед, финиш))
    return ответ

print(int(лучший(1, 100)))

Что здесь стоит понимать:

  • if вершина == финиш: return 0.0 — место, где рекурсия останавливается. Без этой строки функция шла бы дальше финиша и никогда не нашла бы ответ.
  • float('inf') — «бесконечность»: так функция говорит «из этой вершины до финиша не дойти». Если из вершины не выходит ни одного ребра, цикл не выполнится ни разу, и она вернёт бесконечность — такой тупик просто проиграет любому настоящему пути.
  • Словарь граф создан через defaultdict(list), поэтому обращение к вершине без исходящих рёбер не ломает программу, а даёт пустой список.
  • @cache запоминает результат для каждой пары «вершина, финиш». Без него функция пересчитывала бы одну и ту же вершину на каждом пути через неё, а путей в реальном файле бывают миллионы — ответ пришлось бы ждать часами. С ним каждая вершина считается один раз.
  • int(...) — только у готового ответа. Округлять по дороге нельзя: дробные части рёбер сложатся иначе.

Привычная по заданию 16 запись тоже работает: from functools import lru_cache и @lru_cache(None). Короткая @cache появилась в Python 3.9 — если на старом компьютере она не находится, пиши длинную.

Когда этот способ НЕ годится

Функция спускается по рёбрам и верит, что рано или поздно упрётся в финиш или в тупик. Это так, только если в графе нет циклов. Если бы из вершины A можно было по рёбрам вернуться в A, функция ходила бы по кругу, пока Python не остановит её ошибкой RecursionError.

Правило для экзамена: в условии написано «ациклический» — пиши рекурсию с запоминанием, это самый короткий путь к ответу. Слова «ациклический» нет — бери алгоритм Дейкстры из следующего урока, он работает на любом графе с положительными весами.

В демоверсии ФИПИ граф ациклический, и во всех заданиях этого блока тоже.

А глубина рекурсии?

Python по умолчанию разрешает около 1000 вложенных вызовов. Здесь глубина равна длине пути, а в файле не больше 200 строк — значит, в пути не больше 200 рёбер, и вложенных вызовов не больше 201. До предела далеко, поднимать его не нужно.

Итог:

  • лучший путь из вершины = минимум из «вес ребра + лучший путь из соседа», у финиша ноль, у тупика бесконечность;
  • @cache обязателен — без него это перебор всех путей;
  • способ верен только на ациклическом графе; нет слова «ациклический» в условии — Дейкстра;
  • в файле до 200 строк, поэтому предел вложенности Python здесь не мешает;
  • целая часть берётся один раз, от готового ответа.
