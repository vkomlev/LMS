После этого урока ты сможешь: написать самый простой по устройству способ проверки — алгоритм Беллмана-Форда — и объяснить, при каком условии короткий алгоритм Флойда становится неудобным именно для этого задания.

Зачем ещё один способ

Главный приём самопроверки ты уже знаешь: решить ту же задачу другим алгоритмом и сравнить числа. Дейкстра для этого годится, но в ней есть куча и отбрасывание устаревших записей — есть где ошибиться. Беллман-Форд устроен проще всех: в нём нет ни рекурсии, ни очереди, только циклы по списку рёбер. Его удобно держать как запасную проверку, которую трудно написать неправильно.

Алгоритм Беллмана-Форда

Он устроен грубее Дейкстры и потому проще: никакой очереди с приоритетом, только многократный проход по всем рёбрам. Идея — повторять релаксацию всех рёбер подряд до тех пор, пока расстояния перестанут улучшаться.

def беллман_форд(рёбра, вершины, старт, финиш):
    расстояние = {v: float('inf') for v in вершины}
    расстояние[старт] = 0.0
    for _ in range(len(вершины) - 1):
        изменилось = False
        for откуда, куда, вес in рёбра:
            if расстояние[откуда] + вес < расстояние[куда]:
                расстояние[куда] = расстояние[откуда] + вес
                изменилось = True
        if not изменилось:
            break
    return расстояние[финиш]

Здесь рёбра — просто список троек, прочитанных из файла, без всякого словаря. Внешний цикл повторяется не больше, чем число вершин минус один: за столько проходов расстояние гарантированно «дотечёт» до самой дальней вершины. Флаг изменилось позволяет выйти раньше, как только улучшать стало нечего.

На файле-примере видно, как ответ добирается до цели за два прохода. Колонки те же, что в уроке про Дейкстру, — только достижимые из вершины 1:

проход   1     4     7     100
старт   0.0    ∞     ∞      ∞
  1     0.0   2.5   5.5    7.5      <- рёбра встретились в удачном порядке
  2     0.0   2.5   5.5    7.5      <- ничего не изменилось, выходим
Порядок строк в файле произвольный, поэтому за один проход расстояние может и не дойти до цели — тогда понадобится второй, третий проход. Именно поэтому внешний цикл здесь обязателен, а одного прохода по рёбрам недостаточно.

Приём самопроверки

Два алгоритма читают один и тот же файл и обязаны вернуть одно число. Рекурсия и Дейкстра работают по словарю смежности, Беллман-Форд — по плоскому списку рёбер, то есть ошибка в чтении файла или в структуре данных проявится по-разному. Совпали — ответ можно записывать.

Про алгоритм Флойда

Есть и третий известный способ — алгоритм Флойда. Он считает расстояния сразу между всеми парами вершин и записывается совсем коротко: три вложенных цикла. Именно за краткость его часто предлагают для этого задания.

for k in вершины:
    for i in вершины:
        for j in вершины:
            if d[i][k] + d[k][j] < d[i][j]:
                d[i][j] = d[i][k] + d[k][j]

У него есть особенность, о которой стоит знать заранее. Флойд перебирает все тройки вершин, то есть делает примерно N³ действий. Пока вершин в файле несколько десятков, это мгновенно. Но нумерация вершин в задании доходит до 1000, и если завести таблицу «каждая с каждой» по номерам вершин, получится миллиард операций — программа не успеет. Поэтому для Флойда номера вершин сначала сжимают: составляют список реально встречающихся вершин и заменяют номер на его позицию в этом списке. Шаг несложный, но его легко забыть, и тогда решение либо зависнет, либо съест всю память.

Поэтому в этом блоке основной инструмент — рекурсия с запоминанием, для графа с циклами и для проверки — Дейкстра или Беллман-Форд, а Флойд полезно знать как запасной вариант — особенно если в задании спросят расстояния сразу между несколькими парами вершин.

Итог:

  • Беллман-Форд — многократный проход по списку рёбер, без очереди с приоритетом;
  • проверка ответа = решить вторым способом и сравнить числа;
  • Флойд короче всех, но считает все пары и требует сжатия номеров вершин;
  • для задания 23 рабочая связка — рекурсия с запоминанием плюс Дейкстра или Беллман-Форд для самопроверки.
