После этого урока ты сможешь: изменить свою программу под задание с дополнительным условием — путь через вершину, в обход вершин, только по рёбрам нужного веса, не больше K рёбер, вывести сам путь — и объяснить, в какое место программы вписывается каждое условие.

Вспомни: кратчайший путь ищет функция лучший(вершина, финиш), количество путей — функция путей(вершина, финиш). Обе с @cache, обе думают от финиша. Весь урок — это небольшие правки этих двух функций.

Три места, куда вписывается условие

Любое дополнительное условие задания 23 встаёт в одно из трёх мест программы:

где                   что вписывают              пример
1. чтение файла       выбросить рёбра, вершины   в обход вершины
2. цикл по соседям    пропустить ребро           рёбра весом от L
3. вызовы функции     два вызова или параметр    через N, до K рёбер

Все примеры ниже — на файле-примере ФИПИ из первого урока: путь из 1 в 100, обычный ответ 7.5 (путь 1 → 7 → 100).

Через вершину N — два вызова

Путь через вершину 4 — это путь от старта до 4, а за ним путь от 4 до финиша. Функцию менять не нужно:

N = 4
print(int(лучший(1, N) + лучший(N, 100)))

На примере: 2.5 (от 1 до 4) + 8.0 (от 4 до 100) = 10.5, целая часть 10. Ответ больше обычного 7.5 — так и должно быть: условие только сужает выбор, путь через вершину короче обычного кратчайшего не бывает.

В обход вершин — выбросить при чтении

Проще всего не пускать запретную вершину в граф вообще: пропускаем строку файла, если она у ребра в начале или в конце.

запрет = {7}
граф = defaultdict(list)
for строка in open('23.txt'):
    части = строка.split()
    if len(части) < 3:
        continue
    откуда, куда, вес = int(части[0]), int(части[1]), float(части[2])
    if откуда in запрет or куда in запрет:
        continue
    граф[откуда].append((куда, вес))

На примере без вершины 7 остаются пути 1 → 100 (12.0) и 1 → 4 → 100 (10.5), ответ 10.5. Несколько запретных вершин — просто несколько чисел в множестве запрет.

Только рёбра нужного веса — пропустить в цикле

Условие «путь только из рёбер весом не меньше L» проверяем там, где перебираются соседи:

L = 3

@cache
def лучший(вершина, финиш):
    if вершина == финиш:
        return 0.0
    ответ = float('inf')
    for сосед, вес in граф[вершина]:
        if вес >= L:
            ответ = min(ответ, вес + лучший(сосед, финиш))
    return ответ

На примере при L = 3 выпадают рёбра 1 → 4 (2.5) и 7 → 100 (2.0), остаётся только прямое 1 → 100: ответ 12.0. Сравнивай с порогом вещественный вес из файла, а не округлённый.

Не больше K рёбер — третий параметр

Функции надо знать, сколько рёбер ещё можно пройти. Добавляем параметр осталось: каждый шаг уменьшает его на единицу, а при нуле, если финиш не достигнут, путь невозможен.

@cache
def лучший_k(вершина, финиш, осталось):
    if вершина == финиш:
        return 0.0
    if осталось == 0:
        return float('inf')
    ответ = float('inf')
    for сосед, вес in граф[вершина]:
        ответ = min(ответ, вес + лучший_k(сосед, финиш, осталось - 1))
    return ответ

print(int(лучший_k(1, 100, 1)))

На примере не больше чем одним ребром из 1 в 100 можно дойти только напрямую: 12.0. @cache здесь запоминает тройку «вершина, финиш, осталось», поэтому остаётся быстрым.

Сам путь — возвращать пару

Иногда спрашивают не длину, а вершины пути: например, сумму номеров промежуточных вершин. Пусть функция возвращает пару — длину и сам путь кортежем:

@cache
def лучший_путь(вершина, финиш):
    if вершина == финиш:
        return 0.0, (вершина,)
    ответ = (float('inf'), ())
    for сосед, вес in граф[вершина]:
        длина, путь = лучший_путь(сосед, финиш)
        if вес + длина < ответ[0]:
            ответ = (вес + длина, (вершина,) + путь)
    return ответ

длина, путь = лучший_путь(1, 100)
print(путь)
print(sum(путь[1:-1]))

На примере путь — (1, 7, 100), промежуточная вершина одна, сумма 7. Путь хранится кортежем, а не списком: запомненный @cache результат никто не сможет случайно изменить. Такие задания всегда оговаривают, что кратчайший путь единственный, — иначе ответ зависел бы от того, какой из равных путей нашёлся первым.

Те же приёмы для количества путей

вариация           кратчайший путь                    количество путей
через вершину N    лучший(1, N) + лучший(N, 100)       путей(1, N) * путей(N, 100)
в обход вершин     выбросить при чтении                выбросить при чтении

Почему для путей умножение: каждый путь от старта до N можно продолжить каждым путём от N до финиша. На примере путь из 1 в 4 один, из 4 в 100 тоже один: 1 × 1 = 1. Без вершины 7 путей из 1 в 100 остаётся два из трёх.

Ловушка с @cache. Если в одной программе ты сначала посчитал обычный ответ, а потом перестроил граф (например, выбросил запретную вершину), функция вернёт запомненные ответы для старого графа. Либо запускай программу заново для каждого варианта, либо перед новым подсчётом вызови лучший.cache_clear().

Итог:

  • условие встаёт в одно из трёх мест: при чтении файла, в цикле по соседям или в вызовах функции;
  • через вершину — два вызова: сумма для длины, произведение для количества;
  • в обход вершин — выбросить их рёбра при чтении;
  • ограничение на ребро — проверка в цикле; ограничение на число рёбер — третий параметр;
  • сам путь — функция возвращает пару «длина, кортеж вершин»;
  • перестроил граф в той же программе — сбрось @cache или запусти заново.
